1. Executive Summary

This Phase 0 normalized the already-obtained KOA StudioSA / installed
koa_devguide.xml evidence and compared it with the current local Production
working tree. No Production code, tests, runtime data, stock data, queue data,
routine instance data, or operation policy files were modified by this phase.

Primary result:
- Keep one central KiwoomApi / one central QAxWidget ownership model.
- Keep the existing Queue -> Approval -> Operation Policy -> Dispatch Claim ->
  Final Send Gate -> SendOrder -> Chejan safety core.
- Add broker/session/readiness and connection epoch before expanding TR,
  realtime, or candle architecture.
- Treat realtime market data as a future MarketDataHost capability, not as an
  immediate replacement for current opt10080 candle acquisition.
- Do not treat fixed "TR always 5/sec" as a verified contract. The official
  evidence confirms common request limits and server-side flexible throttling,
  but not a stable universal production scheduling number.

11. Findings

P0 findings:
1. No global TR governor exists although official evidence says CommRqData,
   CommKwRqData, and SendCondition share request-limit handling and server
   throttling can vary.
2. Pending TR callbacks do not carry a common connection_epoch guard. Recovery
   checks login_session_id before request, but callback-time stale response
   defense is not globally frozen.
3. Execution Universe is implicit. routine_signal_probe blocks obvious review,
   emergency, stopped, and trade_disabled states, but the project has not yet
   named and enforced a central Execution Universe across market data, signal,
   queue, and send.

P1 findings:
1. screen_registry.json is declarative but empty while Production uses 9001,
   9101, 9102, 9103, 0101, and 9000.
2. Realtime is not wired; SetRealReg ownership, SetRealRemove ownership, FID
   registry, and OnReceiveRealData dispatch are missing.
3. GetServerGubun exact return semantics remain partially verified.
4. opt10080 continuation is not fetched; current code records a warning when
   more pages exist.
5. Mini chart/main monitoring/AutoTradeSetting refresh remains downstream but
   lacks a formal per-stock event notification boundary.

P2 findings:
1. Naming around BrokerReadiness, MarketDataHost, ExecutionUniverse, and
   StrategyObservationUniverse should be frozen before implementation.
2. Screen-number documentation exists but is not generated from code and can
   drift.
3. FID constants exist in multiple contexts and need source locators.

12. Architecture Candidate Decision

- BrokerSessionSnapshot / BrokerReadiness: NEEDED. Process-local source of
  truth projection from KiwoomApi state; no new durable runtime file initially.
- connection_epoch: NEEDED. Process-local generation incremented on login
  success, disconnect observation, and reconnect.
- global TR Governor: NEEDED. Central queue/pacer for all CommRqData,
  CommKwRqData, SendCondition candidates.
- screen number allocator/registry: NEEDED. Existing screen_registry.json must
  be reconciled with actual code before realtime.
- pending TR request identity: NEEDED. Extend existing rqname identity with
  account/session/epoch/screen/trcode/request kind.
- stale callback guard: NEEDED. Drop or quarantine callbacks whose epoch or
  request identity no longer matches.
- canonical candle single writer: NEEDED. Reuse candle_manager/save_candles;
  do not create competing writers.
- atomic candle commit: NEEDED. Verify candle_manager atomicity/read-back in a
  later implementation phase.
- BAR_COMMITTED(stock, bar_identity): NEEDED. Logical notification; not Event
  Journal as source of truth.
- logical MarketDataHost: NEEDED. Introduce after session/TR/screen foundations.
- Strategy Observation Universe: NEEDED. Includes operation + waiting market
  data observation.
- Execution Universe: NEEDED. Strict subset allowed to signal/queue/send.
- Risk Observation Universe: NEEDED. Holdings, open orders, uncertain orders,
  broker/fill evidence regardless of strategy state.
- per-stock Fast Path: NEEDED after candle commit identity.
- realtime shadow mode: NEEDED before realtime primary.
- UI downstream notification: NEEDED. UI consumes core notifications and should
  not block execution.
