## 1. Runtime Layer Phase 1 개요

Runtime Layer Phase 1은 lifecycle 처리 이후 runtime 상태를 직접 쓰기 전에,
projection, persistence preview, recovery preview, reconciliation preview를 분리하여
runtime 반영 가능성과 복구 가능성을 검토하는 보호 계층이다.

이번 Phase 1의 핵심 방향:

- runtime state를 즉시 write하지 않고 preview 결과로 분리한다.
- position, balance, runtime 파일 변경은 실제 commit 계층과 분리한다.
- runtime projection은 lifecycle/fill/evidence 기반 상태 후보를 계산한다.
- persistence preview는 저장 후보와 저장 계획을 검토한다.
- recovery preview는 재시작 또는 불일치 상황에서 복구 후보를 계산한다.
- reconciliation preview는 projection 결과와 기존 runtime/외부 기준 간 불일치를 검토한다.
- GUI update, SendOrder, Chejan 호출은 Runtime Layer Phase 1에서 수행하지 않는다.

Runtime Layer Phase 1의 후보 흐름:

```text
Lifecycle / Evidence Review Result
↓
Runtime Projection
↓
Runtime Persistence Preview
↓
Runtime Recovery Preview
↓
Runtime Reconciliation Preview
↓
Runtime Commit 후보 또는 Review 후보
```

정책 후보:

- Runtime Layer Phase 1은 runtime write 계층이 아니라 preview 계층이다.
- Projection 결과는 runtime 파일에 즉시 반영하지 않는다.
- Persistence는 preview 성격으로만 기록하며 실제 파일 write는 수행하지 않는다.
- Recovery는 복구 후보를 계산하지만 자동 복구 commit을 수행하지 않는다.
- Reconciliation은 불일치와 조정 후보를 제시하지만 자동 보정 write를 수행하지 않는다.

## 4. Projection 계층

Projection 계층은 lifecycle 처리 결과 또는 fill/evidence 기반 입력으로부터
runtime 상태 후보를 계산하는 계층이다.

대상 파일:

- `lifecycle_runtime_projection.py`

역할 후보:

- lifecycle transition 결과를 runtime projection 후보로 변환한다.
- position 후보를 계산한다.
- balance 후보를 계산한다.
- fill/evidence 기반 상태 재구성 후보를 계산한다.
- 계산 결과를 실제 runtime 파일에 쓰지 않고 preview payload로 반환한다.

입력 후보:

- lifecycle transition preview/review 결과
- chejan evidence review 결과
- fill 또는 execution evidence
- 기존 runtime snapshot 후보

출력 후보:

- projected position candidate
- projected balance candidate
- projected runtime state candidate
- projection status
- projection evidence
- preview safety flags

정책 후보:

- Projection은 계산 계층이며 write 계층이 아니다.
- Projection은 position/balance 변경 후보를 만들 수 있지만 실제 파일을 수정하지 않는다.
- Projection 결과는 Persistence Preview 또는 Reconciliation Preview의 입력 후보가 된다.

## 5. Persistence Preview 계층

Persistence Preview 계층은 Projection 결과를 runtime 저장 대상으로 반영하기 전,
어떤 파일 또는 상태에 어떤 변경 후보가 생기는지 검토하는 계층이다.

대상 파일:

- `lifecycle_runtime_persistence.py`

역할 후보:

- projection 결과의 저장 가능성을 검토한다.
- runtime persistence plan 후보를 만든다.
- 저장 대상과 변경 후보를 분리해 기록한다.
- 실제 runtime write 없이 persistence preview 결과만 반환한다.

입력 후보:

- runtime projection result
- projected position candidate
- projected balance candidate
- projected runtime state candidate
- runtime snapshot candidate

출력 후보:

- persistence preview result
- persistence plan candidate
- target runtime file candidate
- changed field candidate
- blocked reason 또는 invalid reason
- preview safety flags

정책 후보:

- Persistence Preview는 실제 파일 저장을 수행하지 않는다.
- runtime file write는 별도 Runtime Commit Executor 계층에서만 다뤄야 한다.
- Persistence Preview 결과는 Review 또는 Commit 후보로만 전달한다.

## 6. Recovery Preview 계층

Recovery Preview 계층은 runtime 상태가 없거나 불완전하거나 재시작 후 재구성이 필요한 상황에서,
복구 후보를 계산하는 계층이다.

대상 파일:

- `lifecycle_runtime_recovery.py`

역할 후보:

- runtime snapshot 또는 projection 결과를 기준으로 복구 후보를 계산한다.
- missing position, missing balance, missing fill/evidence 상태를 검토한다.
- 복구 가능/불가 상태를 preview result로 반환한다.
- 실제 runtime 복구 write를 수행하지 않는다.

입력 후보:

- runtime projection result
- persistence preview result
- runtime snapshot candidate
- lifecycle/evidence history candidate

출력 후보:

- recovery preview result
- recovery candidate
- recoverable 여부
- blocked reason 또는 invalid reason
- recovery evidence
- preview safety flags

정책 후보:

- Recovery Preview는 자동 복구 commit이 아니다.
- Recovery Preview는 runtime 파일을 생성하거나 수정하지 않는다.
- 복구 후보는 Review 또는 Runtime Commit Executor Preview의 입력 후보로만 전달한다.

## 7. Reconciliation Preview 계층

Reconciliation Preview 계층은 projection, persistence, recovery 결과와 기존 runtime 기준 사이의
불일치 여부를 검토하는 계층이다.

대상 파일:

- `lifecycle_runtime_reconciliation.py`

역할 후보:

- projection 결과와 runtime snapshot 후보를 비교한다.
- persistence plan 후보와 recovery candidate의 충돌 여부를 검토한다.
- position/balance/fill/evidence 불일치를 preview한다.
- 조정 후보를 만들되 실제 보정 write를 수행하지 않는다.

입력 후보:

- runtime projection result
- persistence preview result
- recovery preview result
- runtime snapshot candidate
- external balance 또는 broker 기준 후보

출력 후보:

- reconciliation preview result
- mismatch list
- reconciliation candidate
- review required 여부
- blocked reason 또는 invalid reason
- preview safety flags

정책 후보:

- Reconciliation Preview는 자동 보정 계층이 아니다.
- 불일치가 있어도 runtime 파일을 직접 수정하지 않는다.
- Reconciliation 결과는 Review 또는 Runtime Commit 후보로만 전달한다.

- `send_order_called=False`: SendOrder 또는 broker/Kiwoom 주문 호출이 없었음을 의미한다.
- `chejan_called=False`: Chejan 이벤트 호출 또는 자동 연결이 없었음을 의미한다.
