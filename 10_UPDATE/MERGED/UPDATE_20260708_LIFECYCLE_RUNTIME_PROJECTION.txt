요약
본 업데이트는 'Lifecycle Runtime Projection' 규격의 초안을 제공합니다. Projection은 runtime 데이터(positions, balances, fills 등)로부터 파생되는 집계·검증·재구성 규칙을 정의하며, Recovery 및 Audit 관점에서 필요한 일관성 보장 규칙을 포함합니다. 제안 위치는 02_Runtime_Data_Model의 새로운 하위절(예: 02.10)입니다.

1. 목적
- Runtime 데이터(positions, fills, balances)의 Projection 규칙을 정의하여 재시작/체결 누락/중복 이벤트 상황에서도 일관된 Position/Balance를 산출하고, Audit 및 Recovery 절차에서 근거로 사용할 수 있도록 한다.

2. 적용 범위
- runtime/positions.json, runtime/fills.json, runtime/order_executions.json, runtime/review_items.json
- Recovery 시점의 Projection 재계산, 주기적 Projection(옵션), Projection 결과 검증 규칙

3. 데이터 모델 요약
- positions: position_id, code, holding_qty, available_qty, avg_price, realized_pnl, source_fill_ids
- fills: fill_id, order_id, execution_id, quantity, price, kiwoom_order_no, created_at
- balances: account_id, cash, reserved_cash, updated_at

4. Projection 계산 원칙
- Projection은 Fill 이벤트를 근거로 Position을 재구성한다.
- 기본 알고리즘: fills 그룹화 → fill 합산 → 종목별 holding_qty/realized_pnl 재계산 → positions 상태 갱신
- idempotency: 동일 fill_id가 재처리되어도 Projection 결과는 동일해야 함.

5. 트리거와 타이밍
- 즉시 Projection: 중요한 Recovery 작업(재시작 복구, evidence 기반 finalize 시)에서는 즉시 Projection을 실행.
- 주기적 Projection: 운영 중 주기(예: 1분)으로 sanity check용 Projection을 실행하여 runtime 불일치 탐지.

6. 검증 및 불일치 처리
- 검증 항목: (a) positions와 fills 합계 정합성, (b) Kiwoom 잔고와 balances 일치 여부, (c) duplicate evidence 탐지
- 불일치 시: (a) Audit Log에 상세 기록, (b) 복구 플래그 설정 및 Review Management로 이관

7. 복구(Recovery) 절차
- 재시작 복구 시: 최신 journal/history 및 transitions를 이용해 마지막 정상 시점 이후의 fill을 재적용하여 Projection 수행
- 수동/자동 복구 정책: 자동 복구는 위험도가 낮은 범위에 한정하며, 검토관리(Review) 기준을 만족해야 자동 적용 가능

8. 테스트 케이스(권장)
- 재시작 후 Projection 재계산(부분체결 포함) 검증
- duplicate fill / duplicate evidence 처리 검증
- executor 실패로 인한 aborted 상태에서 Projection 재시도 검증

9. 문서 연결(참조)
- Execution Flow(29.8) — 운영/운용 관점(요약): Projection 트리거 시점 및 commit/finalize 연계
- Runtime Data Model(02) — 기술 규격(세부): positions/fills/balances 스키마
