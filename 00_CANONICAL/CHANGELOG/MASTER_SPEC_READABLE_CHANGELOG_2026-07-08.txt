Execution Queue Commit Pipeline
- Execution Preview 이후 Queue Commit 가능 여부를 판단하는 계층을 기록했다.
- Approval Gate, Readiness Validator, Contract Preview, Dry-run, Executor, Result Review를 분리했다.
- Queue Commit은 Preview 결과만으로 바로 수행하지 않는다는 정책을 유지했다.

Canonical SendOrder Path
- Queue Commit 이후 SendOrder로 바로 연결하지 않고, 별도 SendOrder 계층을 거치는 흐름으로 기록했다.
- 전체 흐름은 Execution Queue Commit, Canonical SendOrder, SendOrder Recorder, Chejan Entry, Chejan Event, Lifecycle Preview 순서로 정리했다.
- Call Preview는 실제 SendOrder 호출이 아니라는 점을 명시했다.

SendOrder Recorder
- SendOrder 결과를 lifecycle 전환으로 직접 넘기지 않고, recorder와 review를 거치도록 기록했다.
- SendOrder 결과는 Recorder Contract와 Recorder Review를 거친 뒤 Chejan Entry Adapter로 전달되는 구조로 정리했다.
- recorder의 저장 대상과 runtime write 여부는 별도 검토 필요로 남겼다.

Chejan Entry/Event Pipeline
- Chejan Entry는 SendOrder 결과에서 자동 연결되는 숨은 호출이 아니라 Open Policy와 Contract 기준으로 진입한다고 기록했다.
- Chejan Raw Event Contract를 후속 event pipeline의 입력 기준으로 기록했다.
- Chejan Event는 Classification Preview, Evidence Builder, Evidence Review로 분리했다.
- Chejan event는 자동 runtime write로 이어지지 않는다는 금지선을 유지했다.

Lifecycle Transition Preview
- Chejan Review 이후 lifecycle 전환은 자동 commit하지 않고 preview, approval, contract preview, dry-run으로 분리했다.
- SendOrder 성공만으로 Position을 변경하지 않는 기존 정책을 유지했다.
- SendOrder 성공만으로 청산 완료로 보지 않는 기존 정책을 유지했다.

AI Development Tools / Local Analyzer
- AI Development Tools는 실행 pipeline 자체가 아니라 개발/분석 보조 도구로 기록했다.
- `.ai` 디렉터리는 역할별 AI 운영 지침 구조로 기록했다.
- `tools/ai_analyzer`는 read-only 분석 보조 도구 후보로 기록했다.
- read-only 보장 여부는 실제 도구 동작 기준으로 검토 필요로 남겼다.
