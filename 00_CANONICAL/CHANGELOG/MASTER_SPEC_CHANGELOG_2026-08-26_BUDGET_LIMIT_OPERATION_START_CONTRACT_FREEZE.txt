3. Contracts Frozen
==================================================

Starting Budget:

- AMOUNT default uses Fresh Current Price multiplied by
  `starting_budget_defaults.amount_multiplier`.
- The current 1.5 value is a persisted setting value, not a hard-coded
  Canonical ratio.
- Last Known price is not a new-default calculation source.
- Resolved starting budget is not recalculated on every ordinary realtime Tick.
- AMOUNT invalid input is discarded with Toast and editor close, preserving a
  still-valid previous explicit value or returning to the default path when the
  previous explicit value is also invalid.

Limit:

- Recommended and minimum limits use effective/resolved starting budget
  multiplied by environment multipliers.
- Current recommended/minimum values 100 and 25 are multipliers, not
  percentages.
- `자리맞춤 ON` uses `round_money_to_two_significant_digits()`.
- `자리맞춤 OFF` uses the raw amount.
- Minimum does not use a separate ceiling rule, and leading-place ceiling is
  not the current Stock limit alignment contract.
- Invalid limit input restores a previous valid CONFIGURED state when one
  exists; otherwise it returns to UNSET.
- CONFIGURED single click edits; CONFIGURED double click unsets; UNSET single
  click is no-op; UNSET double click activates through the existing
  recommendation/guard contract.

Operation Start:

- Main global `▶ 운영시작` failure reason precedence is:
  lifecycle guard -> GLOBAL prerequisite -> Structural Target -> Operation Time
  -> Per-target Recovery -> Validation -> Start.
- GLOBAL login/account prerequisite is evaluated before operation time.
- Structural target provenance is preserved before operation-time split.
- Only time-eligible targets proceed to per-target Recovery and validation.
- Recovery-before-time provenance loss and generic no-target fallback are
  explicitly superseded.
