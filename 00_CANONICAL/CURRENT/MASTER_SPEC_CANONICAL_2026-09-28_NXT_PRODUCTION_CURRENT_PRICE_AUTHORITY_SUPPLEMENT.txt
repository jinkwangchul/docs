MASTER SPEC CANONICAL SUPPLEMENT
NXT Production CURRENT_PRICE Authority
Date: 2026-09-28
Status: CURRENT SUPPLEMENTAL

======================================================================
1. PURPOSE AND SUPERSESSION BOUNDARY
======================================================================

This supplement authorizes one narrowly bounded extension of the existing
KRX/NXT market-data contract:

- verified NXT realtime evidence may become Production CURRENT_PRICE evidence
  during explicitly authorized NXT-only windows;
- KRX and NXT identities remain separate;
- no integrated market-data identity is introduced.

This supplement supersedes only the earlier clauses that denied NXT evidence
all Production CURRENT_PRICE / pre-hash authority.

The following earlier protections remain unchanged:
- NXT does not become canonical candle authority;
- NXT does not become forming-candle authority;
- NXT does not become Historical/Validation candle authority;
- NXT does not change order-route authority;
- _AL / INTEGRATED identity remains unsupported;
- no simultaneous KRX/NXT source-priority policy is introduced.

The 2026-09-19 verified NXT eligibility contract remains authoritative for
eligibility evidence. Its statement that eligibility alone is not realtime
price authority is preserved: NXT eligibility is only one required gate. This
supplement adds a separate time/source/session/evidence authority selector.

======================================================================

Canonical stock ownership identity remains the broker-action canonical code.

======================================================================
3. CURRENT_PRICE AUTHORITY WINDOWS
======================================================================

For a verified NXT-eligible stock:

08:00 <= t < 08:50
- authorized CURRENT_PRICE source: NXT

08:50 <= t < 09:00
- no Production CURRENT_PRICE authority
- fail closed

09:00 <= t < 15:30
- authorized CURRENT_PRICE source: KRX

15:30 <= t < 15:40
- no Production CURRENT_PRICE authority
- fail closed

15:40 <= t < 20:00
- authorized CURRENT_PRICE source: NXT

Outside these windows:
- no authority from this selector.

For a stock whose verified NXT eligibility is false, unknown, missing, invalid,
or unavailable:
- NXT windows do not authorize CURRENT_PRICE;
- fail closed;
- no KRX or persisted fallback is admitted merely because a price exists.

There is no overlap policy in this contract. At every authorized instant the
selector admits at most one source.

======================================================================
4. SOURCE-TRANSITION AND FRESHNESS CONTRACT
======================================================================

A price observed before the start of the currently authorized source window
cannot be carried into that window as Production CURRENT_PRICE evidence.

Examples:
- at 09:00, a KRX Tick observed before 09:00 is insufficient;
- at 15:40, an NXT Tick observed before 15:40 is insufficient.

The authorized evidence must satisfy all of the following:
- Broker is connected;
- connection_epoch matches the current Broker session;
- login_session_id matches the current Broker session;
- canonical stock identity matches;
- broker quote identity matches the authorized source;
- source real type matches the authorized source;
- market date equals the current Seoul market date;
- market_datetime is not in the future;
- market_datetime falls inside the currently authorized authority window;
- price is positive and finite;
- receive sequence is positive;
- received_at exists.

A reconnect or new login session invalidates prior-session evidence.

This contract does not introduce an arbitrary fixed seconds-based TTL.
A no-trade interval is not by itself proof that the latest valid exchange Tick
is stale. Session, source, window, ordering, identity, and market-time evidence
are the governing freshness boundary for this phase.

======================================================================
5. PRODUCTION CURRENT_PRICE EVIDENCE
======================================================================

The selector projects one immutable ProductionCurrentPriceEvidence containing:

- canonical_stock_code
- broker_code_identity
- market_source
- source_real_type
- current_price
- market_datetime
- received_at
- receive_sequence
- connection_epoch
- login_session_id
- authority_window

The selector is read-only. It creates:
- no Runtime writer;
- no candle writer;
- no event-journal writer;
- no Position/PnL writer;
- no Broker request;
- no SendOrder call.

======================================================================
6. AUTHORIZED CONSUMER BOUNDARY
======================================================================

The evidence is authorized for the existing Production CURRENT_PRICE boundary.

Authorized Production consumers use the same evidence current_price for:
- CURRENT_PRICE final pre-hash revalidation;
- existing risk revalidation that already depends on that finalized price;
- Routine/actionable CURRENT_PRICE projection used by Main facts, Signal Probe,
  Indicator Follow BUY/SELL, ATS operations, close/liquidation, and the
  operation timer;
- the AutoTradeSettingWindow order-execution boundary;
- existing CURRENT_PRICE execution semantics reached through those shared
  Production boundaries.

When a Production consumer exposes production_current_price_evidence(), that
evidence is authoritative. Missing or invalid evidence must fail closed and
must not fall back to a legacy KRX realtime value.

Final pre-hash failure continues through the existing
current_price_pre_hash_unavailable path. Routine/actionable consumers continue
to expose unavailable CURRENT_PRICE as None and retain their existing
CURRENT_PRICE_VALUE_MISSING or equivalent fail-closed behavior.

The Configuration-price contract used for starting-budget/budget editing is
separate. It intentionally retains its existing current-session
Snapshot-or-Realtime Configuration evidence contract introduced by the
behavioral-parity checkpoint. This supplement does not silently replace that
Configuration contract with the Production actionable CURRENT_PRICE selector.

This supplement does not authorize NXT evidence for:
- SIGNAL_PRICE;
- RSI/MACD/MA/Bollinger/Price Box candle inputs;
- completed candle creation;
- forming candle creation;
- BAR_COMMITTED;
- canonical candles.json;
- Historical TR replacement;
- Signal Validation Historical source;
- realtime-primary canonical candle commit;
- Position/PnL source replacement.

======================================================================
7. REQUEST-HASH PROVENANCE
======================================================================

When the Production CURRENT_PRICE boundary has an authorized evidence object,
the final order captures the same evidence snapshot before request identity is
created.

The request hash binds the normalized CURRENT_PRICE provenance together with
the final order price.

The hash-bound provenance contains:
- canonical_stock_code
- broker_code_identity
- market_source
- source_real_type
- current_price
- market_datetime
- received_at
- receive_sequence
- connection_epoch
- login_session_id
- authority_window

The provenance current_price must equal the final order price. A mismatch,
incomplete provenance, invalid source identity, or invalid session/sequence
fails closed before request-hash authorization.

The same provenance is preserved in the execution_request and Queue record so
the final price can later be attributed to the exact KRX/NXT evidence used for
identity creation.

Legacy/test contexts that do not provide the evidence callback retain the
existing numeric CURRENT_PRICE resolver contract. Production binds the
evidence callback and therefore uses one evidence read for both price and
provenance, avoiding a two-read Tick race.

======================================================================
8. ORDER ROUTE IS INDEPENDENT
======================================================================

Market-data source does not select order route.

Examples allowed by the architecture:
- market_source=KRX with order route SOR;
- market_source=NXT with order route SOR.

This supplement does not activate live SOR success, NXT direct ordering, or any
new SendOrder route. Existing SOR reconciliation and safety contracts remain
authoritative.
