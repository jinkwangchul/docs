2. Git Workflow v2 공식 Workflow

kiwoom_auto 저장소는 Workflow v2를 공식 Git 운영 방식으로 사용한다.

공식 흐름:
- master
- Feature Branch
- Commit
- Push
- Pull Request
- Review
- Merge
- Branch Delete
- master 최신화

운영 원칙:
- master 직접 Commit 금지
- master 직접 Push 금지
- Feature 하나 = Branch 하나
- Feature 하나 = Pull Request 하나
- Merge 후 feature branch 삭제 확인
- Merge 후 master와 origin/master 일치 확인

docs 저장소는 Canonical 운영 저장소이며, 문서 갱신은 main 기준 Commit/Push로 운영한다.

3. Agent 역할

Codex:
- 코드 조사
- 영향 분석
- 구현
- 테스트
- 리팩터링
- Commit 직전 검증

General Agent:
General Agent는 AI의 추론, 사고, 구조 판단, 설계, 정책 결정이 필요하지 않은 입력과 출력이 명확한 기능적 작업만 수행한다.

담당:
- Git 상태 확인
- HEAD / origin 동기화 확인
- Branch 확인
- Feature Branch 생성/삭제
- Stage 확인
- Commit
- Push
- Pull Request 생성
- Pull Request 상태 확인
- Merge 수행
- master 최신화 확인
- 파일 존재 확인
- Test-Path
- Get-Item
- 체크리스트 기반 검증
- 결과 보고

수행하지 않는 작업:
- 설계
- 정책 결정
- 구조 판단
- 영향 분석
- 계약 설계
- 코드 구현
- Runtime 설계
- Preview 설계
- 구현 범위 결정
- AI 추론이 필요한 작업

High Reasoning:
- 정책
- 계약
- 아키텍처
- 프로젝트 방향
- 대규모 구조 변경
- 구현 범위 결정

Git 작업은 Codex와 General Agent가 협업할 수 있으나, Codex는 프로젝트 정책 결정을 하지 않는다. 실행 계약과 아키텍처 경계 변경은 High Reasoning 검토 대상으로 본다.
