==================================================
2. Purpose And Final Boundary
==================================================

Mock Validation is an isolated execution domain used to validate Routine behavior
against realtime market evidence without creating Production orders, fills,
positions, PnL, Events, Reviews, or operation state.

Fixed boundary:

`Production market read evidence -> immutable Mock market input -> Mock-only execution state`

The reverse direction is forbidden. Mock execution cannot be promoted into the
Production Queue, Runtime, Chejan, Position, PnL, Event, Review, or SendOrder path.

==================================================
4. Phase 1 - Isolated Foundation
==================================================

Implemented Mock-only contracts for:

- Validation Session identity and stock-level lifecycle
- atomic repository/writer and path guard
- Order, Fill, Position, PnL, Event, Review, and Reset state
- immutable Routine/Stock reference snapshots
- current session versus immutable history separation
- multi-Instance state isolation
- Production dependency/mutation AST guard

Mock mutable storage is rooted under `mock_validation/` only. Reset clears current
execution state and preserves Event history. A new registration creates a new
Validation Session identity and does not inherit the previous Position or PnL.

Broker Order/Chejan identifiers are not required and SendOrder is unreachable.

==================================================
8. Phase 5 - Continuation And Safety
==================================================

Mock continuation supports the implemented Routine policies for timeout/cancel,
reset, repeat, exit, and final residual progression. Existing ordering/precedence is
preserved. Durable decision evidence prevents duplicate progress after operation-cycle
replay or restart. Structural uncertainty stops the stock Session for Mock Review;
it does not stop another stock or create a Production Review.

==================================================
9. Phase 6 - Operation Lifecycle
==================================================

Stock-level operations are implemented for start, close, immediate liquidation,
Review Stop, reset, resume, and return eligibility.

Operation Session completion is distinct from Trading Cycle completion:

- liquidation with holding/pending quantity zero -> DONE
- approved long-hold carryover -> Operation Session ended while Position/average price
  and Trading Cycle continue
- unresolved close residual -> Mock Review, never automatic carryover

Restart recovery distinguishes WAITING, RUNNING, CLOSING, REVIEW_STOPPED,
CANCEL_PENDING, Carryover, and immediate-liquidation REQUESTED without duplicate
virtual Orders or Fills.

==================================================
11. Phase 8 - Coexistence Correction
==================================================

UI hiding alone was rejected as insufficient. A generic optional read-only operation
start exclusion callback was added at the common Production pre-mutation boundary.

For a current Mock stock:

- Main global/selective Production start excludes the stock
- AutoTradeSettingWindow global/selected/selected-row start excludes the stock
- mixed targets start normal Production stocks only
- all-Mock targets create no Production operation mutation/Event
- membership read failure is fail-closed
- after Mock archive, the underlying unchanged Production eligibility is visible again

Production assignment/status is not changed to implement this exclusion.

==================================================
12. Multi-Instance Contract
==================================================

For one stock with Instances A/B/C:

Shared:
- realtime trade/orderbook evidence
- immutable market snapshot identity

Independent per Instance:
- virtual Order/Fill and queue-ahead
- Position, average price, and PnL
- cycle, BUY round, generation, continuation, and liquidation state

One Instance Fill does not consume another Instance's virtual liquidity.

Control remains stock-level; root-cause attribution remains Instance-level. No public
Instance start/reset/resume operation is exposed.

==================================================
13. Event, Review, And Reset
==================================================

Mock Event and Mock Review have their own identities and writers. An Instance error
may stop the stock Session while retaining `source_routine_instance_id`. Production
Review uses its independent global collector and remains visible even when the Main
table projects a current Mock stock separately.

==================================================
14. Return Saga
==================================================

Fixed order:

`eligibility -> Production preflight -> user choice -> RETURN_REQUESTED -> Production command -> success -> Mock archive -> RETURN_COMPLETED`

If the Production command fails, the current Mock Session remains. Archive-before-command
is forbidden. `delete_stock_project_data()` is unreachable from the Mock return path.
