2. STRATEGY PRICE AXES

Strategy price comparison has exactly three semantic axes:
- CURRENT_PRICE / 현재가: live moving market price used for immediate comparison;
- SIGNAL_PRICE / 신호가: fixed reference captured from the source signal;
- AVG_PRICE / 평단가: confirmed position weighted average changed only by fills.

ORDER_PRICE is not a fourth strategy comparison axis.

Legacy strategy UI values 주문가 and ORDER_PRICE remain read-compatible only in
the explicit price-source fields covered by compatibility normalization. New
strategy rules are written as SIGNAL_PRICE.

Actual order price, fill price, hoga selection, and execution evidence remain
execution-domain values. They do not become strategy comparison operands.

4. ACTIVE_BUY CORRECTIVE CONTRACT

ACTIVE_BUY is corrective-only.

Let:
- S = fixed SIGNAL_PRICE for the BUY signal;
- A = confirmed pre-buy AVG_PRICE;
- A' = projected post-buy weighted average.

Allowed geometry:
- if S < A: S <= A' < A;
- if A < S: A < A' <= S.

A BUY may move the average toward SIGNAL_PRICE but must never cross it.

Actionable grammar:
- UP / 상향: only <= / 이하;
- DOWN / 하향: only <= / 이하;
- BOTH / 상하: only WITHIN / 이내.

Non-actionable:
- UP or DOWN with >= / 이상;
- BOTH with OUTSIDE / 이탈.

If whole-share rounding would make A' cross SIGNAL_PRICE, the result is no-order.

12. PERSISTENT FAIL-CLOSED INVALIDATION

Physical file deletion failure must not make a deleted stock reusable from stale
Validation cache.

The historical-cache owner therefore records a stock-level persistent cache-state
generation before physical deletion:
- delete begins by atomically recording INVALIDATED with a new generation;
- load(), load_covering(), and load_signal_entries() reject stale payloads while
  state is INVALIDATED or the payload generation does not match;
- this survives process restart because the invalidation state is persistent;
- a file left behind by Windows file locking is therefore not reusable.

A fresh broker history store:
- writes and verifies a payload bound to the current generation;
- only after successful persistence changes the state to ACTIVE;
- allows the fresh generation to be reused normally.

Older sibling count/timeframe artifacts and old settings-hash signal entries that
do not match the active generation remain blocked.
