3. Connected Production Scope
==================================================

A. Previous-Round Price Skip

UI meaning: `직전회차주문가 대비 현재주문가`.

When its condition is satisfied, only the current BUY generation is skipped.
The skip does not increment a confirmed round, consume the normal maximum-round
budget, terminate the cycle, create a Candidate, or enqueue an Order. A later
new BUY signal may be evaluated again. Missing, conflicting, or stale previous
order evidence fails closed.

B. Last+1

Supported methods:
- MARKET;
- CURRENT_PRICE;
- ACTIVE.

Eligibility requires normal maximum-round completion, a new valid BUY signal,
and no pending, deferred, uncertain, or unresolved obligation. Last+1 is one
separate closing generation with its own identity. It reuses existing budget
authority and safety gates. Queueing, send acceptance, rejection, cancellation,
or partial fill is not terminal completion. Confirmed completed Fill evidence
is required. SEND_UNCERTAIN is never blindly retried.

C. Multi-Point Last-Round Active Buy

UI meaning: `마지막회차 능동매수`.

It is available only for MULTI_TIME or MULTI_RATIO and applies only to the
final child. It is not a budget policy. A true condition preserves the original
child price, quantity, and budget. A false condition terminally skips that
final child without replacement Order, extra quantity, budget override, or
rollback of earlier children.

D. Signal-Scoped Cycle

A BUY source signal is mandatory. The cycle is not an autonomous scheduler.
Supported execution uses the existing SINGLE, MULTI_HOGA, MULTI_TIME, and
MULTI_RATIO planners and already connected timeout/cancel and price-reset
primitives. Children share source-signal lineage and deterministic identity.
Child count is not confirmed BUY round count. Restart restores only incomplete
children from durable evidence. The same source signal cannot reopen a
completed cycle; a new BUY signal is required.

5. User-Adjustable Numeric Contract
==================================================

Ratio and percent values are `USER-ADJUSTABLE PARAMETER` values.

Examples such as `0.15`, `0.45`, `0.62`, `0.77`, and `5` are historical UI
examples or user-entered values, not semantic constants. The governing rules
are:

- an explicit saved value has precedence;
- UI -> collect -> save/load -> Mapper -> execution preserves the value;
- load/apply does not force a particular number;
- validation checks finite, non-negative, and applicable range/format rules;
- no feature is identified by comparing its numeric value to a fixed literal;
- Last+1 ACTIVE and Last-Round Active Buy values are independent.

==================================================

`설정가에 평단이 [방향] [사용자 입력 비율] [비교조건]`.

Its raw widget state may remain saved while an unmet Multi-Point prerequisite

saved user value.

disabled and its detail is disabled. Returning to a supported non-conflicting
state restores the normal ability to select exit-time. Cycle is no longer
