2. CURRENT USER-CONFIRMED TIMEFRAME CONTRACT
======================================================================

The operator timeframe choices are:
- 1분, 3분, 5분, 10분, 15분, 30분, 60분, 120분, 240분, 일, 주, 년.

Identity rules:
- minute choices use M1/M3/M5/M10/M15/M30/M60/M120/M240 internally;
- 일 = D1, 주 = W1, 년 = Y1;
- D1/W1/Y1 must never be represented by fake minute integers;
- minute UI-state compatibility remains numeric strings such as "15";
- day/week/year UI state uses the period label identity.

Source-dialog round trip:
- the current Registration/Edit timeframe enters Validation unchanged;
- changing the Validation timeframe causes a new validation run on that
  timeframe's actual historical candles;
- indicators and BUY/SELL results are recalculated from that validation data;
- explicit Settings Apply returns the validated timeframe/UI candidate to the
  source Registration/Edit dialog;
- Validation Apply is not direct Production activation.

Request identity:
- explicit top-level validation_timeframe metadata is authoritative;
- for a legacy request without that metadata, explicit request
  timeframe_minutes maps to M{n};
- Production bar.bar_minutes must not silently redefine a Validation request.

3. READ-ONLY HISTORICAL CONTRACT
======================================================================

Broker source mapping:
- minute -> OPT10080;
- D1 -> OPT10081;
- W1 -> OPT10082;
- Y1 -> OPT10094.

Period broker rows are normalized into stable 14-digit Validation candle times.
The Validation provider/cache/replay identity includes the explicit timeframe
key so D1/W1/Y1 cannot collide solely because Production bar_minutes is equal.

Completed-candle admission is semantic:
- minute candles use their minute bucket;
- D1 uses the trading-day period;
- W1 uses the ISO-week period;
- Y1 uses the calendar-year period.

These paths are read-only Validation paths. They do not authorize a Production
candle writer or mutation of Production MarketDataHost state.

5. ENTRY / SEED IDENTITY CORRECTION
======================================================================

Independent criticism found a post-timeframe-expansion identity defect:
- an explicit D1/W1/Y1 snapshot could be projected through stale or missing
  embedded UI state and become M5 at immutable seed/request entry.

The defect was reproduced on Python 3.11.9 32-bit:
- source=D1;
- UI=일;
- projected seed=M5;
- request=M5.

The bounded correction in project_signal_validation_rules now preserves an
explicit validation_timeframe mapping when no live ui_state is supplied.
When a live ui_state is explicitly supplied, the current operator selection
continues to take precedence. Legacy rules with no explicit metadata retain
their embedded-UI fallback.

No global precedence rewrite or Production bar_minutes change was introduced.
