5. Runtime Commit Preview Contract

Module:
- sell_runtime_commit_preview.py

Input:
- SELL_EXECUTION_FULL_PREVIEW

Output:
- preview_type = SELL_RUNTIME_COMMIT_PREVIEW
- ownership = MASTER_ENGINE
- domain = Execution / Runtime Commit Preview
- routine_dependency = None

Responsibility:
- Validate the full SELL execution preview result at the Runtime Commit boundary.
- Preserve candidate identity, source_signal_id, order_id, execution_request, request_hash, lock_id, summary, warnings, and reasons.
- Keep commit_allowed aligned with preview-only readiness.

Boundary:
- No Runtime Commit.
- No Runtime file write.
- No Queue Commit.
- No SendOrder.
- No broker API.
- No OrderRequest creation.
- No REAL_READY mutation.

6. Runtime Commit Validator Contract

Module:
- sell_runtime_commit_validator.py

Input:
- SELL_RUNTIME_COMMIT_PREVIEW

Output:
- validation_type = SELL_RUNTIME_COMMIT_VALIDATOR
- commit_allowed = True | False
- status = READY | BLOCKED | INVALID

Responsibility:
- Validate whether the Runtime Commit Preview can proceed to dry-run execution.
- Reject identity gaps, safety flag violations, summary count mismatches, and partial candidate validity.
- Preserve every candidate without priority selection.

Boundary:
- No Runtime Commit.
- No Queue Commit.
- No file write.
- No external dispatch.

7. Runtime Commit Dry-run Executor Contract

Module:
- sell_runtime_commit_dryrun_executor.py

Input:
- SELL_RUNTIME_COMMIT_VALIDATOR

Output:
- dryrun_type = SELL_RUNTIME_COMMIT_DRYRUN_EXECUTOR
- dry_run = True
- commit_allowed = True | False
- commit_actions
- blocked_commit_actions
- validation_summary
- execution_summary

Responsibility:
- Generate in-memory commit actions as if Runtime Commit would be performed later.
- Require all candidates READY for overall READY.
- Treat structural identity errors as INVALID.
- Treat policy non-approval as BLOCKED.

Boundary:
- runtime_commit_executed = False
- runtime_write = False
- queue_write = False
- queue_committed = False
- send_order = False
- broker_api_called = False

8. Runtime Commit Approval Gate Contract

Module:
- sell_runtime_commit_approval_gate.py

Input:
- SELL_RUNTIME_COMMIT_DRYRUN_EXECUTOR

Output:
- approval_type = SELL_RUNTIME_COMMIT_APPROVAL_GATE
- approval_granted = True | False
- commit_allowed = True | False
- approved_commit_actions
- blocked_approval_actions

Approval rule:
- upstream status must be READY
- upstream commit_allowed must be True
- dry_run must be True
- preview_only must be True
- all commit_actions must be READY
- blocked_commit_actions must be empty
- dryrun_invalid_count must be 0
- dryrun_blocked_count must be 0
- dryrun_ready_count must equal len(commit_actions)

Invalid rule:
- READY dry-run with blocked_commit_actions is INVALID.
- READY dry-run with blocked or invalid summary counts is INVALID.
- ready_count mismatch is INVALID.
- identity mismatch or missing fields are INVALID.

Boundary:
- No actual approval side effect.
- No Runtime Commit.
- No Queue Commit.
- No SendOrder.

9. Runtime Commit Execution Plan Contract

Module:
- sell_runtime_commit_execution_plan.py

Input:
- SELL_RUNTIME_COMMIT_APPROVAL_GATE

Output:
- plan_type = SELL_RUNTIME_COMMIT_EXECUTION_PLAN
- plan_only = True
- execution_plan_ready = True | False
- commit_allowed = True | False
- execution_actions
- blocked_execution_actions
- approval_snapshot

Each execution action contains:
- plan_action = RUNTIME_COMMIT
- source_signal_id
- order_id
- candidate_id
- queue_pending_id
- execution_id
- request_hash
- lock_id
- execution_request
- order_queued_record_preview
- source_approval_action

Ready rule:
- approval status must be READY
- approval_granted must be True
- commit_allowed must be True
- approved_commit_actions must not be empty
- blocked_approval_actions must be empty
- all approved actions must be READY
- all identities must match
- summary counts must match
- all safety flags must be False

Invalid rule:
- READY approval with empty approved_commit_actions is INVALID.
- READY approval containing BLOCKED action is INVALID.
- Any blocked_execution_actions make the whole plan INVALID.
- If approved action count and execution_actions count differ, the plan is INVALID.
- Partial execution plans are prohibited.

10. Safety Boundary

The following values must remain False in every layer:

- execution_connected
- runtime_write
- queue_write
- file_write
- send_order
- broker_api_called
- queue_committed
- actual_order_sent
- order_request_created
- real_ready_state_changed
- runtime_commit_executed

The following are prohibited:

- actual Runtime Commit
- Runtime file write
- Queue write
- Queue commit
- SendOrder
- broker API call
- actual OrderRequest creation
- actual REAL_READY mutation
- partial candidate approval
- partial execution planning
- first-candidate-only processing
- automatic priority selection
