======================================================================
2. SELL EXPRESSION-AWARE VALIDATION
======================================================================

SELL UI validation follows this order:

  expression syntax
  -> referenced groups
  -> active filters
  -> detailed price-reference requirements needed by those active filters

An unreferenced ui_condition_a/b/c group does not block validation because of
its price-reference state. A referenced group whose price-gap check is disabled
also does not require a price-reference selection. Only a referenced, active
filter that actually needs the price reference may fail on an unresolved
selection.

SELL input failures continue through the existing gui_toast boundary. They do
not replace the chart's validation result summary. This changes validation
admission only; it does not change SELL expression evaluation, Runtime signal
meaning, rules persistence, Candidate payload, or price-comparison arithmetic.

======================================================================
3. SILENT SUCCESS AND NORMAL COMPLETION
======================================================================

A successful [설정적용] remains fully functional: it validates the current V2
state, emits the detached Candidate through the existing handoff, updates the
parent Working UI, and preserves repeatable apply behavior. Success is silent.
It does not persist the action acknowledgement "설정 적용 완료" in
validation_status_label or move that acknowledgement to another UI surface.

A normal Historical Replay completion is also silent:

  validation_status_label == ""

The label remains responsible for active Historical/Replay progress and real
errors. Failed apply/validation and user-actionable errors retain their existing
Toast/error behavior. Silent success does not alter Candidate emission,
fingerprints, strict SELL validation, persistence boundaries, or Replay state.

======================================================================
4. CANDLE AND MARKER TOOLTIP CONTRACT
======================================================================

The Candle hover tooltip keeps the actual timestamp and OHLC values. Its first
line is the timestamp value itself; the redundant label "평가 시각:" is not
shown. Tooltip position, style, High-to-Low hit range, current time/price scale,
and Candle data source are unchanged.

Marker Evidence remains the first hit-test priority. A marker hit shows Marker
Evidence; otherwise a valid Candle hit shows Candle timestamp/OHLC; otherwise
the V2 path requests tooltip dismissal with QToolTip.hideText(). When visible
tooltip content changes, the existing tooltip is hidden before the replacement
is shown.

The contract distinguishes dispatch from native visibility timing:

  QToolTip.hideText() requested
  != proof that the operating-system tooltip became invisible immediately

Qt 5.15 may apply an internal hide delay. Actual immediate disappearance must
therefore be verified from the real visible Qt runtime, not solely from a mock
hideText call count. No V2-owned replacement tooltip widget is approved here.

5. TOP RESULT SUMMARY
======================================================================

The normal result summary uses the operator-facing Korean form:

  005930 삼성전자 | 5분봉 | 100캔들 | 매수신호 n | 매도신호 n |
  기간내 추정손익 x.xx%

The displayed line does not use the previous English result labels Candle,
BUY, or SELL. It does not use the prior label "추정 손익률".

Estimated-return formatting is:

- positive: +1.23%
- negative: -0.05%
- zero: 0.00%
- no completed-cycle aggregate available: 0.00%

The underlying aggregate remains the completed-cycle cost-weighted return
defined by the September 14 owner. Only the no-result display changes from "-"
to 0.00%; no cycle, Candle, BUY/SELL, or return calculation changes.

The result summary and estimated-return segment use the same normal-weight
presentation. The separate estimated-return bold emphasis is retired. Font,
weight, and color are unified without changing result ownership or layout.
