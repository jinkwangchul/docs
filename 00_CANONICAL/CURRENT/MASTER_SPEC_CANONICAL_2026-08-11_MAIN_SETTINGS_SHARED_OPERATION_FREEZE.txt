2. Shared Production Architecture

The confirmed ownership structure is:

Common Production Backend
<- Main Monitoring UI Adapter
<- AutoTradeSettingWindow UI Adapter

- AutoTradeOrderExecutionBoundary owns the shared Queue snapshot, execution
  preflight, Runtime commit, final Gate, durable dispatch claim, automatic
  ORDER_QUEUED processing, pending cancel, and SendOrder environment contract.
- AutoTradeOperationHost does not dynamically borrow AutoTradeSettingWindow
  methods. The host and settings window explicitly call the same boundary.
- Runtime Stock State Mutation Boundary is shared by ordinary state changes,
  emergency stop/release, signal probe, and Review return paths.
- Context-menu actions, labels, ordering, enablement, and dispatch are shared
  between Main Monitoring and AutoTradeSettingWindow.
- Stock schedule change and default-time reset use the same Backend.
- MainWindow is the multi-view owner. One screen does not directly invoke the
  other screen's refresh_all().

3. Operation Start Contract

- Main Monitoring and AutoTradeSettingWindow have two UI entry points for one
  operation-start contract.
- MainWindow owns program operation and both entry points use the same
  MainWindow Recovery context, participation set, and Backend.
- Under the same state, both buttons must present matching text and enablement.
- A persisted RUNNING value alone does not establish current participation.
  Participation requires a valid current Recovery session,
  operation_excluded=False, and a valid actual operation state.
- A stock registered before operation starts is operation-eligible.
- A stock registered during operation is written operation_excluded=True and is
  not immediately enrolled in the current operation.
- Before operation starts, multi-select context-menu start enrolls the selected
  stocks and excludes unselected assigned stocks.
- Bottom operation start enrolls only stocks whose operation_excluded is False.
- During operation, context-menu start on an excluded stock may clear exclusion
  and enroll it only after the common Guard and Recovery checks pass.

4. Read-only Refresh And Projection

- AutoTradeSettingWindow table refresh is read-only with respect to Runtime
  stock state. Display-only changes use local projection.
- Session-status projection is shared by both screens.
- View synchronization is performed through
  MainWindow.refresh_auto_trade_assignment_views().

5. Safety Boundaries

- Queue, Approval, Gate, SendOrder, Chejan, Recovery, Review, close, and state
  transition contracts are unchanged by this integration.
- Tests install a fail-closed Production mutable guard before project tests.
- Protected mutable data includes runtime, stocks, routine_instances,
  archived_stocks, Event Journal, PROJECT_CHANGELOG, and realized-PnL ledger.
- GUI test modules are executed in isolated 32-bit Python processes to prevent
  cumulative PyQt QWidget lifecycle termination from hiding results.
