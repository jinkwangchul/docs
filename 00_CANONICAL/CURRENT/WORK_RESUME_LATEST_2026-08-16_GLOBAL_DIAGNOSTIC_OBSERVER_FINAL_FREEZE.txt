2. Completed Big Feature

The existing Event Journal is now the Global Diagnostic Observer: a fail-open,
program-wide observation layer for meaningful operator, setting, Operation,
Routine, Signal, execution, Broker, Fill, close, Recovery, integrity, warning,
error, and exception events. It observes Production results but never changes
them.

Command uses command_id and Recovery uses recovery_session_id. No new durable
correlation identity exists. `parent_event_id` is a bounded 4,096-key,
append-success-only, process-memory best-effort link and is not durable proof.

9. Security And Non-Intervention

Raw account, credential/token/API key, user-home absolute path, traceback,
Broker payload, Chejan FID map, and full professional Evidence records are not
stored or displayed. Exception text is limited to 512 characters, general
diagnostic text to 2,048, and identities to 256.

Observer, sanitizer, writer, Reader, and GUI failures cannot change Production
results. Event UI has no Writer call, Production action, Runtime mutation,
Recovery action, Broker action, or SendOrder call.
