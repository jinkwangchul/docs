1. Main Monitoring Operation Contract

- The Main monitoring window owns the persistent Operation Host lifecycle.
- Opening, closing, or reopening Auto Trade Setting does not create a second
  operation timer, signal consumer, Queue dispatcher, or SendOrder path.
- Operation exclusion and release use one existing Source of Truth and common
  Backend in Main monitoring and Auto Trade Setting.
- Main monitoring provides the operation-excluded stock view without creating
  a second exclusion list or Runtime schema.
- Situation and status remain separate display and sorting axes. Situation uses
  its situation sort value; status uses the established status priority.
- The manual Stability Check entry point and its Legacy mutation flow are
  removed. Retained integrity checks run at their established automatic
  lifecycle boundaries.

2. Event Journal And Decision Trace Contract

- Event Journal is an append-only diagnostic evidence path with a Reader and
  an operator-facing Event Record window.
- Production observation covers application and Recovery events, signal,
  approval, policy, execution, SendOrder, Broker response, Chejan/fill, close,
  liquidation, emergency, and operation exclusion boundaries implemented in
  the frozen code.
- Decision Trace records decision-stage evidence and preserves correlation,
  market evidence, rules/settings identity, engine identity, and stage
  observations without becoming a Production decision Source of Truth.
- Diagnostic recording is fail-open with respect to Production trading flow:
  evidence write failure must not create a second order path or mutate the
  trading decision.
- The operator default Event Record view hides only ORDER_QUEUED,
  OPERATION_HOST_STARTED, RECOVERY_COMPLETED, and
  SEND_ORDER_REQUEST_ACCEPTED. Writer, JSONL, Reader, identity, and correlation
  evidence remain intact.
- Event Journal category/severity normalization and Legacy read compatibility
  are retained by the frozen implementation.

3. Account Funds Foundation Contract

- The existing selected account remains the account identity Source used by
  MainWindow, Recovery, order Guard, and Auto Trade Setting.
- AccountFundsSnapshot is a memory-only UI Projection. It is not persisted to
  Runtime and is not a Recovery, Budget, or order-authorization Source.
- KiwoomAccountFundsAdapter requests OPW00001 after successful Recovery for the
  currently selected account.
- The request uses the selected account, blank password, media code `00`, and
  query code `2`; the response reads summary-row `예수금` and
  `주문가능금액`.
- GetServerGubun maps `1` to simulation account display, other non-empty values
  to real account display, and an empty value to an unconfirmed display.
- Account changes invalidate the previous Projection. Timeout, one in-flight
  request per account, one coalesced follow-up, account identity, request
  identity, and stale callback checks prevent an old response from replacing
  the current account display.
- READY money values use the existing money normalization and display format.
  Blank or invalid required values fail; a numeric zero remains a valid READY
  value.
- The account funds Projection is not connected to SendOrder, Operation Policy,
  Execution Gate, project Budget, or `매수가능상태` authorization.
