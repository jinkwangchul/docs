2. CHART PRESENTATION AND HOVER
======================================================================

The former fixed right-side selected-Candle and BUY/SELL signal summary panel
and its splitter are removed. The chart stack directly occupies the complete
result width. The lower Completed Cycle table remains present and unchanged.

Hovering a valid Candle displays only the Candle's existing replay data:

  evaluation time
  open
  high
  low
  close

No value is recalculated and no Replay is run for hover. A pointer outside the
actual first-to-last Candle span does not clamp to a false first/last Candle.

BUY/SELL marker Evidence remains a separate projection and has priority over
the Candle tooltip. A marker hit displays the existing operator Evidence; a
non-marker Candle hit displays OHLC/time; any other location hides the tooltip.
The removal of the fixed panel does not delete reason, matched_groups, details,
trace, marker, or immutable replay data.

======================================================================
3. ADAPTIVE X-AXIS DENSITY
======================================================================

The Canvas owns one current_candle_slot_width used by every X-coordinate
consumer: Candle body and wick, marker, selection, time labels, hit testing,
index conversion, and content width. _x_for_index remains the common coordinate
source.

Default density uses a 100-Candle reference, not the current result count:

  usable_width = viewport width - left margin - right margin
  base slot = usable_width / 100

The slot is clamped by V2-local minimum and maximum values. With 100 Candles the
first-to-last Candle span uses the available chart width without the former
large right-side blank. A 200- or 500-Candle result does not divide the slot by
its own count. It keeps the current 100-reference density, increases content
width, and uses the native horizontal scrollbar.

Before manual zoom, viewport resize recalculates base/current density from the
100-Candle reference. After manual zoom, viewport resize updates layout and
scroll range without discarding the operator's current slot width. Changing
Candle count also preserves current density and manual-zoom state. No new scale
persistence is introduced; a new Window starts from default density.

======================================================================
4. WHEEL ZOOM AND NAVIGATION
======================================================================

Vertical wheel input over the chart changes X-axis Candle density only:

- wheel up increases slot width;
- wheel down decreases slot width; and
- V2-local clamps prevent unusable extreme widths.

Zoom is cursor-centered. The pre-zoom continuous Candle position beneath the
cursor is projected through the new slot width and the horizontal scrollbar is
adjusted, within its legal range, so that the same Candle remains under the
cursor within pixel rounding tolerance.

Navigation uses the native horizontal scrollbar. New left-button drag panning
is not part of this contract because Candle click selection already owns that
interaction. Wheel zoom does not change Y-axis _ValidationPriceScale, Fixed
Axis, marker size, selected index, marker index, time-label index, or Evidence
identity.

Hover, wheel, scrollbar movement, and viewport resize only redraw existing
results. They do not call ValidationHistoricalReplay.evaluate, rebuild
indicators, recalculate completed cycles, or recalculate aggregate return.
