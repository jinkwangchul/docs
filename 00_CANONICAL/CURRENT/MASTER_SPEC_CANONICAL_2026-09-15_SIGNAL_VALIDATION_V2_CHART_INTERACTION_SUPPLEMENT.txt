2. CHART PRESENTATION AND HOVER
======================================================================

The former fixed right-side selected-Candle and BUY/SELL signal summary panel
and its splitter are removed. The chart stack directly occupies the complete
result width. The lower Completed Cycle table remains present and unchanged.

Hovering a valid Candle displays only the Candle's existing replay data:

  evaluation time
  open
  high
  low
  close

No value is recalculated and no Replay is run for hover. Candle X hit testing
uses the current visible-time transform and existing Candle slot semantics; a
pointer outside the actual first-to-last Candle span does not clamp to a false
first/last Candle. Candle Y hit testing uses the current Price Scale's
y_for_price() result for the Candle's actual High and Low wick endpoints. The
hit interval is the intersection of that High-to-Low pixel range and the
current plot area. A missing/non-finite High or Low, a fully clipped Candle, or
a pointer in empty plot space above/below the visible wick produces no Candle
tooltip. Price zoom therefore changes the hover hit range through the same live
transform used for rendering; no old Y coordinate is cached.

BUY/SELL marker Evidence remains a separate projection and has priority over
the Candle tooltip. A marker hit displays the existing operator Evidence; a
non-marker Candle hit displays OHLC/time; any other location hides the tooltip.
The removal of the fixed panel does not delete reason, matched_groups, details,
trace, marker, or immutable replay data.

======================================================================
3. FIXED VIEWPORT AND TIME SCALE
======================================================================

The chart Canvas is always the physical size of the chart viewport. Candle
count and scale interaction never increase the Canvas width or height. The old
large child-widget content width, current_candle_slot_width, and native
QScrollArea child scrolling are not part of the current contract.

The Window owns three distinct timeline facts:

  candle_count
  visible_start_index
  visible_candle_span

Initial visible_candle_span is min(100, candle_count). The initial range is
right-anchored so evaluated_end_index is visible. For 100, 200, and 500 Candle
results the physical Canvas width remains equal to the current viewport width;
only the logical visible range differs.

Every X-coordinate consumer uses the same fixed-viewport transform:

  plot_width = Canvas width - left margin - right margin
  pixels_per_candle = plot_width / visible_candle_span
  x(index) = left margin
             + ((index - visible_start_index) + 0.5)
             * pixels_per_candle

Only the visible index range is painted and hit-tested. Candle body and wick,
marker, selection, time labels, Candle hover, Evidence hit testing, and inverse
mouse-X-to-index mapping share this transform. Time labels are selected again
from actual Candle timestamps in the current visible range; no time is invented
or interpolated.

Window resize changes physical viewport pixels but preserves the logical
visible span. A new Replay Snapshot resets the time view to its initial
min(100, candle_count), evaluated-end-anchored state. No new scale persistence
is introduced.

======================================================================
4. TIME-SCALE DRAG AND LOGICAL NAVIGATION
======================================================================

Horizontal left-button drag changes the X-axis time scale inside the fixed
viewport. Right drag decreases visible_candle_span and zooms in; left drag
increases visible_candle_span and zooms out. The scale factor is a smooth
exponential function of drag distance relative to plot width. V2-local clamps
limit the span to at least 10 Candles, or all available Candles when fewer than
10 exist, and at most candle_count.

At press time the continuous Candle position and its cursor ratio within the
plot are recorded. While scaling:

  new_start = anchor_index + 0.5 - anchor_ratio * new_span

The result is clamped to the available timeline, keeping the press anchor at the
same screen X whenever the dataset boundary permits. Movement below the click
threshold remains normal Candle selection; an actual scale drag does not emit a
selection click.

Navigation is a separate QScrollBar under the fixed viewport. It changes only
visible_start_index. Its range is zero when all Candles fit and otherwise maps
the fractional start to 1000 integer units per Candle; pageStep represents the
current visible span. It never changes time scale or price scale. The internal
QScrollArea horizontal scrollbar remains disabled with a zero range.

Selecting a Candle or Completed Cycle outside the visible range minimally moves
visible_start_index so the target appears without changing visible span.

======================================================================
5. WHEEL PRICE SCALE AND FIXED AXIS
======================================================================

Vertical wheel input over the chart changes only the Y-axis price range:

- wheel up divides the current range by 1.15 per wheel step and zooms in;
- wheel down multiplies the current range by 1.15 per wheel step and zooms out;
- minimum range is 0.001 of the Snapshot's default OHLC range; and
- maximum range is 100 times the Snapshot's default OHLC range.

_ValidationPriceScale provides price_for_y(), the exact inverse of y_for_price().
The price beneath the cursor before zoom remains at the same Y coordinate after
zoom whenever the range clamps do not require boundary normalization:

  anchor_price = price_for_y(cursor_y)
  new_max = anchor_price + cursor_ratio * new_range
  new_min = new_max - new_range

The Fixed Axis reads the same current price scale as Candle/grid rendering and
refreshes its five tick labels and required width immediately. Marker Y meaning
is unchanged: BUY/SELL Evidence markers remain attached to the plot boundary,
not converted into price markers.

Wheel input does not change visible_start_index, visible_candle_span, Canvas
size, selection, or replay data. Window resize preserves manually adjusted
price bounds. A new Replay Snapshot resets price bounds to the existing whole-
Snapshot OHLC minimum/maximum contract.

Hover, wheel, time-scale drag, logical scrollbar movement, and viewport resize
only redraw existing results. They do not call
ValidationHistoricalReplay.evaluate, rebuild indicators, recalculate completed
cycles, or recalculate aggregate return.
