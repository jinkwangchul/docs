Final history contract
----------------------

1. The selected timeframe candle series remains the Indicator Input SoT.
2. Minimum formula warmup and retained indicator history are separate concepts.
3. `warmup_bars` is the minimum history required for an indicator to become
   evaluable.
4. `history_target_bars` is the desired retained/evaluation context and does
   not become a minimum-availability gate.
5. The Indicator Follow project history target is:
   DEFAULT_INDICATOR_HISTORY_TARGET_BARS = 600.
6. Effective history context is max(600, required warmup).
7. When fewer than 600 target-timeframe candles are available but minimum
   warmup is satisfied, evaluation may proceed with all available history.
8. When more than 600 target-timeframe candles are available, the active
   indicator context is capped to the newest 600 bars where this contract
   applies.
9. The value 600 is the project's normalized history target. It is not a claim
   that Kiwoom HTS internally uses a universally fixed 600-bar limit.
Production retention contract
-----------------------------

The Routine projection request now declares both:
- minimum `warmup_bars`; and
- `history_target_bars`.

Production MarketData standby/retention sizing uses the history target when it
is present, rather than sizing retention only from minimum warmup.

The raw one-minute requirement may therefore exceed 600 rows for larger target
timeframes because enough source minutes must be retained to project the target
timeframe history.

Projection output remains bounded by the target-timeframe history target.
History target overflow and warmup insufficiency remain distinct states.

No new Broker writer, Runtime writer, Queue mutation, or SendOrder path is
created by this contract.
Validation history contract

required_validation_history_context_bars(rules)

The Validation flow uses this context for:

A persistent cache fixture was corrected so its historical snapshot preserves

mixed timeframe identity.

The visible chart candle count remains distinct from hidden indicator context.
Corrected Price Box calculation
-------------------------------

Canonical owner:
engines/indicator_engine.py::price_box()

Default configured period:
24 bars.

For each evaluable bar:
- Middle is the rolling configured-period CLOSE average.
- A causal local history window is selected, capped at 600 bars by default.
- Inside that local history, a rolling configured-period center is calculated.
- Each valid deviation is CLOSE minus that bar's own rolling center.
- Positive and negative deviations are separated.
- Upper = current Middle + AvgIf(positive deviations)
  + 2 * StdevIf(positive deviations).
- Lower = current Middle + AvgIf(negative deviations)
  - 2 * StdevIf(negative deviations).
- The existing population-variance convention is retained.
- Future candles cannot rewrite already calculated historical points.

Therefore Price Box is causal, but its outer statistics are not restricted to
only the current 24 CLOSE values.
RSI and MACD history behavior
-----------------------------

RSI:
- Formula remains the project's Wilder-style RSI implementation.
- rsi_causal_history() evaluates each point from at most the causal trailing
  history target.
- Before the history cap is reached, all available prefix history is used.

MACD / Signal / OSC:
- Formula family remains fast EMA minus slow EMA, Signal EMA, and OSC difference.
- macd_series_causal_history() evaluates each point from at most the causal
  trailing history target.
- Before the history cap is reached, all available prefix history is used.

The purpose of these wrappers is history-context parity, not a new RSI/MACD
formula definition.
Cross-path parity
-----------------

The normalized history contract is wired through:
- common indicator engine;
- Routine Production evaluation;
- Production MarketData projection/retention;
- Signal Validation historical flow;
- Validation Replay;
- Validation Batch behavior through shared indicator series;
- Validation visualization / indicator cache.

Replay history capping preserves global evidence indexes when a local trailing
window is used.

Production and Validation may acquire candles through different read paths, but
they must evaluate the same target-timeframe candle semantics and the same
history-context contract.
