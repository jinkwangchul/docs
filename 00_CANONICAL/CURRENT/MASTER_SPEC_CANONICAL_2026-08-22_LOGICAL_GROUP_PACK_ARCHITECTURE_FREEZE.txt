==================================================
2. Production Group Source And Identity
==================================================

Production discovers Groups only through:

- `groups/registry.json`
- `groups/<GROUP_UUID>/group.json`

`group_id` is a stable UUID. Physical paths, Group display names,
`stock.routines`, and project-root `_Group` folder names are not Group identity
or membership Sources of Truth.

Each logical Group records its `definition_id`, fixed developer-defined
`base_name`, system-generated `display_name`, and numeric `slot`. Users cannot
rename a Group. User naming and rename authority applies only to subordinate
RoutineInstances.

==================================================
3. Group Naming And Slot Allocation
==================================================

Repeated registration of the same Group Pack is allowed. Names are generated
from the fixed `base_name`:

`지표추종매매`
`지표추종매매_1`
`지표추종매매_2`

Slot 0 uses the base name without a suffix. Later Groups use
`<base_name>_<slot>`. Allocation always chooses the lowest available slot, so
a deleted slot is reused before a higher slot is allocated. UUIDs remain
unique even when a display-name slot is reused.

==================================================
4. Relationship Sources Of Truth
==================================================

The durable relationship contracts are:

- Group to RoutineInstance: `routine_instances/<UUID>/instance.json.group_id`
- RoutineInstance to Stock: `assigned_routine_instance_id`

Main and AutoTrade Projection, Summary, selection scope, operation scope, and
complete deletion use these identities. Group names and `stock.routines`
strings are not authoritative Group membership evidence. A zero-stock
RoutineInstance remains attributable through its explicit UUID `group_id`.

==================================================
5. Group Pack Registration
==================================================

Main displays the top-right actions in this order:

`[그룹등록] [조기마감]`

`그룹등록` accepts a `.group.zip`, validates the shared manifest and SHA-256
payload hashes, installs missing strategy files, validates Routine Definition
discovery, and atomically creates a Logical Group. No Group-name input is
shown. Existing identical strategy files are reused without rewrite. If an
existing file differs, registration is blocked without overwrite or update.

Group Packs have no version, update, or patch lifecycle. Registration is an
additive Group operation only.

==================================================
6. Developer Group Packing
==================================================

`그룹패킹` is available only when
`KIWOOM_AUTO_DISTRIBUTION_PROFILE=developer`. The action is not created for
`beta`, `production`, an unset value, or an invalid value. Unset and invalid
profiles fail closed as `production`.

Packing uses the selected Group's `definition_id` and a developer-authored
pack specification. The Pack contains only declared strategy Definition,
Engine, rules, and strategy-specific UI/helper files. It excludes Group UUID,
slot, display-name suffix, RoutineInstances, Stocks, Runtime, logs, account,
order, execution, and performance data. The generated Pack uses the exact
registration manifest schema and is reopened and hash-verified before atomic
promotion.

==================================================
7. Logical Group Complete Deletion
==================================================

`그룹삭제` removes the selected Logical Group, all RoutineInstances whose
explicit `group_id` matches it, and only the related Stock attribution. Stock
records themselves and the shared Routine Definition/Engine are preserved.
The Group UUID is removed from `groups/registry.json` atomically.

Deletion preserves the established safety boundary:

- preflight failure creates no marker and changes no data
- a durable delete transaction marker is written before destructive steps
- complete rollback clears the marker
- incomplete or uncertain rollback retains the marker and remains fail-closed
- success removes the Group and clears the marker after read-back validation

==================================================
8. Removed Legacy Architecture
==================================================

The following are removed from Production:

- project-root `_Group` discovery
- `_Group/budget.json` as a Group marker
- path-based `group_id`
- `group_recovery/` snapshot storage
- automatic and manual Group recovery
- Recovery control rows and Recovery Toast queues
- the `그룹복구` menu and callback
- Group-name and `stock.routines` membership fallback

Transaction temp paths, validation, atomic promotion, durable markers,
rollback, and read-back verification remain active safety techniques. They are
not Group Recovery.
