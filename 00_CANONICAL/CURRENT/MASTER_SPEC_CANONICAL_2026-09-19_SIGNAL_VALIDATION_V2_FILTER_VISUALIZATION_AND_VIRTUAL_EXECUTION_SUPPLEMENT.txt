======================================================================
2. HISTORICAL CANDLE AND VIRTUAL PRICE CONTRACT
======================================================================

Validation operates only on completed Historical Candle rows.

The latest row is excluded only when it is identified as the currently forming
Seoul-time timeframe bucket under the existing 09:00 market-bucket anchor.
The implementation does not blindly drop the final row. A latest row belonging
to an already completed bucket remains eligible. After the regular-session
closing boundary, the last regular-session bucket is not removed merely because
it is the latest row.

Virtual execution price is Validation-only:

    virtual_fill_price = (OPEN + HIGH + LOW + CLOSE) / 4

The same representative price is used for virtual BUY and virtual SELL. All four
OHLC values must be finite and positive. Missing/invalid OHLC does not silently
fall back to Close.

This is Historical OHLC-based approximate validation. It is not an assertion of
the broker's actual historical execution price.

Signal-indicator evaluation keeps its existing price semantics except where the
approved Validation average-price context is explicitly supplied.

======================================================================
3. SIMPLIFIED VALIDATION EXECUTION / AVERAGE CONTRACT
======================================================================

The Validation execution model is intentionally smaller than Production.

Approved Validation execution semantics:

- first BUY quantity: exactly 1 share;
- BUY hoga mode: SINGLE only;
- SELL hoga mode: SINGLE only;
- repeated BUY modes:
  - ROUND;
  - BUDGET;
  - ACTIVE_BUY;
- SELL closes the entire Validation virtual holding;
- same evaluation index with both SELL and BUY is SELL-first and does not
  immediately reopen BUY on that same index.

Repeat-mode quantity calculation reuses the existing pure
buy_execution_policy.py evaluator. Validation does not invoke Production Runtime,
queue, broker, or writer ownership.

After each virtual BUY:

    weighted_average =
        (previous_average * previous_quantity + fill_price * buy_quantity)
        / new_quantity

SELL return uses the same quantity-weighted average and the same completed-
Candle CLOSE price used by signal/filter evaluation.

The V2 "간이 평단관리 검증" controls are Validation-local. They may enter the
Validation Run Snapshot and Reset baseline, but they are removed from the
Settings Apply payload and do not overwrite the source dialog's Production
execution configuration.

Not included:

- multi-hoga execution;
- pending-order / cancel simulation;
- actual broker fill replay;
- Production quantity/budget mutation;
- fees, tax, spread, or slippage modeling;
- SendOrder / Chejan.

======================================================================
4. AVG_PRICE REPLAY CONTEXT
======================================================================

The same incremental ValidationVirtualPositionTracker owns:

- Replay-local AVG_PRICE supplied to evaluation;
- position quantity;
- contributing filled BUY indexes; and
- completed virtual cycles.

Therefore SELL conditions that compare against AVG_PRICE use the same
quantity-weighted CLOSE-based virtual position average shown by Validation cycle
results.

When the Validation execution policy is present, BUY quantities remain
quantity-weighted while every Validation BUY fill price is the corresponding
signal/evaluation Candle CLOSE.

======================================================================
5. CONFIGURED FILTER UNIVERSE
======================================================================

The chart does not display all possible filters unconditionally.

The persistent visualization universe is the union of filters actually configured
for BUY or SELL in the Validation snapshot:

    configured universe = BUY used filters ∪ SELL used filters

The eight supported visualization families are:

1. MOVING_AVERAGE;
2. MA_ARRANGEMENT;
3. BOLLINGER;
4. PRICE_BOX;
5. PRICE_COMPARISON;
6. RSI;
7. MACD_SIGNAL;
8. OCR_OSC.

A filter series identity includes calculation family and parameters. Therefore,
for example:

- MA20 and MA60 are different identities;
- RSI9 and RSI14 are different identities.

If BUY and SELL use the exact same calculation identity, the displayed series
may be shared while BUY/SELL Evidence ownership remains distinct.

Disabled / unconfigured filters are not shown.

======================================================================
6. SUPPORTED VS UNSUPPORTED VISUALIZATION
======================================================================

Visualization availability and signal-evaluation support are separate facts.

A configured series may be visually projectable while one side is not currently
evaluated by V2. The descriptor therefore preserves supported_sides and
unsupported_sides.

Current important case, amended 2026-09-23:

- new strategy Price Comparison uses SIGNAL_PRICE rather than ORDER_PRICE;
- Validation SIGNAL_PRICE is the same completed-Candle CLOSE used by
  signal/filter evaluation and Validation-estimated BUY/SELL execution;
- legacy ORDER_PRICE comparison tokens remain read-compatible and project through
  the same CLOSE-aligned signal-price visualization path;
- visualization availability and contributing Evidence remain separate: a
  configured condition with no evaluated V2 evidence remains marked unsupported
  rather than being presented as contributing Evidence.

Unsupported or error states must never be presented as ordinary non-contributing
Evidence.

======================================================================
7. PREFIX-CORRECT VISUALIZATION CACHE
======================================================================

Visualization uses immutable precomputed data derived from the Replay result.
Mouse Hover, Click, Wheel, Drag, Resize, Crosshair movement, and logical scrolling
must not re-run Replay, signal evaluation, or indicator construction.

Price Box is prefix-sensitive. Historical Price Box display values are therefore
constructed at each historical prefix/cutoff. Appending future Candle values must
not alter already-computed earlier Price Box points.

The cache is descriptor-scoped so parameter-distinct series do not overwrite one
another.

======================================================================
8. STATIC CHART LAYOUT
======================================================================

Price-axis overlays include configured:

- Moving Average;
- MA Arrangement;
- Bollinger;
- Price Box;
- Price Comparison.

Independent lower-axis families are:

- RSI;
- MACD / Signal;
- OCR / OSC.

Lower-area geometry contract:

- zero configured lower families -> no lower area;
- one lower family -> H;
- two lower families -> H / 2 each;
- three lower families -> H / 3 each.

The current V2 UI implementation constant is:

    H = 180 px

H is a presentation constant, not a signal or calculation contract.

No Volume fallback and no representative indicator is inserted when there are
zero lower families.

Once lower-pane composition is determined from the Validation snapshot, Marker
Hover/Click changes styling only. It does not create/remove panes or change H.

======================================================================
9. EVIDENCE VISUAL STATE
======================================================================

Without a focused Marker, configured supported series remain normally visible.

With Marker Hover or Pin:

- ACTIVE:
  the descriptor contributed to the already-produced final signal Evidence;
  use its assigned normal color with stronger emphasis;
- INACTIVE:
  configured and supported but did not contribute to this signal;
  remain visible as faint gray;
- UNSUPPORTED:
  configured/displayable but outside the current V2 evaluation boundary for the
  focused side;
  use distinct gray/dashed treatment and "[미지원]" labeling;
- ERROR:
  required display series is unavailable/invalid;
  use distinct error treatment and "[오류]" labeling.

Evidence selection comes from the existing structured Trace / final expression
survivor logic. Tooltip strings are not parsed back into Evidence and filters are
not re-evaluated on Hover.

======================================================================
10. MARKER HOVER AND CLICK PIN
======================================================================

Marker identity is logical:

    (evaluation_index, side)

Marker Hover temporarily focuses that Marker's Evidence.

Marker Click pins the same logical identity. A Pin has priority over subsequent
Hover styling.

Clicking a non-Marker / blank chart location releases the Evidence Pin and
returns filters to the normal configured-universe display state.

Pin state is per Canvas / per V2 window. It is not shared between windows and
does not mutate Replay or Production state.

======================================================================
11. CROSSHAIR CONTRACT
======================================================================

Crosshair X is Candle-center snapped.

Normal pointer Hover uses the nearest visible Candle index. Marker Hover uses the
Marker evaluation index. Marker Pin fixes the Crosshair lookup index to the
pinned Marker identity.

The vertical Crosshair line spans the price chart and all configured lower
panes using the same logical Candle index.

The horizontal Crosshair exists only for the pane containing the pointer:

- price pane -> price-axis unit;
- RSI pane -> RSI unit;
- MACD / Signal pane -> its local indicator unit;
- OCR / OSC pane -> its local indicator unit.

Different panes never share one Y value.

Pin stores logical identity, not screen pixels. Resize, time Zoom, logical
Scroll, and repaint reproject X from the stored index. If the pinned index moves
outside the visible logical range, the Pin remains but the Crosshair is not
drawn until that index becomes visible again.

Leaving the chart removes ordinary Hover Crosshair state. A pinned vertical
Crosshair remains logically owned by the Pin.

======================================================================
12. CROSSHAIR VALUE LOOKUP
======================================================================

Crosshair lookup reads only existing Candle and immutable visualization cache
data.

At the active Crosshair index, lookup may expose:

- Candle time;
- OPEN / HIGH / LOW / CLOSE;
- configured price-overlay channel values;
- RSI;
- MACD;
- Signal;
- OCR / OSC; and
- other configured cached channels.

When Marker Evidence focus is active, lookup state may annotate values as
"[유효]" or "[비기여]".

UNSUPPORTED and ERROR descriptors are reported as "[미지원]" and "[오류]"
instead of presenting a numeric value as if it were validated Evidence.

Value lookup does not trigger Replay or indicator recomputation.
