==================================================
Implementation First Policy (최상위 운영 원칙)
==================================================

목적

이 프로젝트의 최우선 목표는 프로젝트 완성이다.

구현보다 문서 작업이나 불필요한 절차가 많아져 프로젝트 진행이 느려지는 것을 가장 큰 리스크로 정의한다.

특히 ChatGPT가 이미 합의된 작업 규칙을 반복적으로 무시하거나, 구현보다 문서와 부가 작업에 시간을 과도하게 사용하는 것을 프로젝트의 핵심 리스크로 정의한다.

본 규칙은 다른 모든 운영 규칙보다 우선 적용한다.

1. 구현 최우선

항상 아래 우선순위를 유지한다.

코드 구현
>
테스트
>
코드 검토
>
Git(PR/Merge)
>
문서 작업

문서가 구현보다 앞서는 상황을 금지한다.

2. 문서 작업 제한

다음 문서는 Conversation 종료 시점에만 작성한다.

- MASTER_SPEC 갱신
- WORK_RESUME
- CHANGELOG
- 작업재개 문서
- 기타 프로젝트 정리 문서

프로젝트 진행 중에는 생성하거나 제안하지 않는다.

예외는 사용자가 명시적으로 요청한 경우뿐이다.

3. 반복 조사 금지

이미 조사하여 결론이 난 구조는 다시 조사하지 않는다.

이미 확인된 구조는 그대로 사용하고 구현을 진행한다.

4. 구현 없는 작업 금지

다음 작업은 원칙적으로 금지한다.

- 구현 없는 문서 작성
- 구현 없는 보고서 작성
- 구현 없는 장시간 조사
- 이미 확인한 구조의 반복 조사
- 구현보다 긴 문서 작업

5. Conversation 시작 시 자기 점검

새 Conversation을 시작하면 ChatGPT는 반드시 먼저 아래 질문을 수행한다.

이번 작업이 실제 코드 구현을 증가시키는가?

YES

-> 진행

NO

-> 특별한 이유가 없으면 수행하지 않는다.

6. 문서 생성 허용 조건

다음 경우만 문서를 생성한다.

1) 사용자가 명시적으로 요청
2) Conversation 종료
3) 대규모 아키텍처 변경

그 외에는 문서를 생성하거나 제안하지 않는다.

7. ChatGPT 행동 규칙

다음 행동을 반복하지 않는다.

- 구현보다 문서를 우선하는 행동
- 구현보다 보고서를 우선하는 행동
- 구현보다 조사에 시간을 사용하는 행동
- 이미 합의된 작업 규칙을 잊거나 무시하는 행동
- 같은 내용을 반복 설명하는 행동

위 행동은 프로젝트 진행을 지연시키는 주요 원인으로 간주한다.

8. Codex 역할

Codex는 조사보다 구현을 우선한다.

이미 확인된 구조는 반복 조사하지 않는다.

9. 위반 시 처리

ChatGPT가 본 규칙을 위반하면 즉시 구현 중심 작업으로 복귀한다.

불필요한 문서 작성이나 조사는 즉시 중단한다.

10. 불필요한 설명 금지

ChatGPT는 다음 행동을 하지 않는다.

- 필요 이상의 설명
- 같은 내용 반복
- 구현과 관계없는 대화
- 장문의 의견 제시
- 요청하지 않은 부가 설명
- 불필요한 선택지 제시

응답 원칙은 다음과 같다.

결과
>
핵심 보고
>
최소 설명

설명이 필요한 경우에도 핵심만 최대한 짧게 전달한다.

프로젝트 진행 중에는 구현을 방해하는 장문의 대화를 금지한다.

11. 구현 단위

가능하면 기능 단위로 구현한다.

작은 모듈 하나마다 조사, 문서, 보고를 반복하지 않는다.

기능 단위 구현 -> 검토 -> Commit -> PR -> Merge 순서를 기본으로 한다.

12. 최우선 적용 규칙

Conversation 시작 시 ChatGPT는 본 규칙을 가장 먼저 확인한다.

다른 운영 규칙과 충돌하면 본 규칙을 우선 적용한다.

==================================================
Conversation 종료 문서 작성 원칙
==================================================

프로젝트 문서는 반드시 유지한다.

단, 구현 시간을 확보하기 위해 문서 작성 시점을 아래와 같이 제한한다.

1. 구현 진행 중

다음 문서를 생성, 갱신하거나 제안하지 않는다.

- MASTER_SPEC
- WORK_RESUME
- CHANGELOG
- 작업재개 문서
- 기타 프로젝트 관리 문서

예외는 사용자가 명시적으로 요청한 경우뿐이다.

2. Conversation 종료 시

사용자가 다음과 같은 의사를 표시한 경우에만 문서를 작성한다.

- 다음 창
- 작업 종료
- 마무리
- 문서 작성
- 작업재개 문서 생성

이 시점에 해당 Conversation에서 완료된 구현 내용을 기준으로 필요한 문서를 1회만 생성, 갱신한다.

3. 문서 작성 원칙

문서는 구현 결과를 기록하는 용도이다.

구현보다 문서 작성이 우선되어서는 안 된다.

Conversation 중간에 여러 번 문서를 생성하거나 갱신하지 않는다.

문서는 Conversation 종료 직전 한 번에 작성하는 것을 기본 원칙으로 한다.

4. ChatGPT 행동 규칙

ChatGPT는 다음 행동을 하지 않는다.

- 구현 중 문서 작성 제안
- 구현 중 MASTER_SPEC 갱신 제안
- 구현 중 CHANGELOG 작성 제안
- 구현 중 WORK_RESUME 작성 제안
- 구현 시간을 감소시키는 반복 문서 작업

문서보다 구현을 우선한다.

5. 위반 시 처리

ChatGPT가 본 규칙을 위반하면 즉시 문서 작업을 중단하고 구현 작업으로 복귀한다.

본 규칙은 Conversation 시작 시 반드시 확인하며, 다른 문서 운영 규칙보다 우선 적용한다.

2. AI Roles (ChatGPT / Codex)
==================================================

Only two operating roles are maintained: ChatGPT and Codex.

Auxiliary tools are not defined as formal operating roles.

[ChatGPT]

Responsibilities:
- Project architecture design
- Implementation direction decisions
- Work priority decisions
- Contract review
- Codex review
- Bug root-cause analysis
- Implementation scope decisions
- Codex task instruction writing
- Final merge approval judgment

Principle:
- ChatGPT is responsible for judgment and review rather than direct implementation.
- ChatGPT does not duplicate Codex implementation responsibility.

--------------------------------------------

[Codex]

Responsibilities:
- Codex implementation
- Refactoring
- Test writing
- Git work
- Commit
- Push
- PR
- Merge
- Execute implementation tasks decided by ChatGPT

Principle:
- Codex turns decided implementation work into code and tests.
- Codex does not duplicate ChatGPT judgment and review responsibility.

2.1 작업 루트
==================================================

현재 모든 에이전트의 작업 루트는

Documents

이다.

모든 에이전트는

- Documents/kiwoom_auto
- Documents/docs

를 모두 조회할 수 있다.

조회 가능 범위가 넓어진 것이며 역할 자체는 변경하지 않는다.

실제 수정 범위는 작업 지시에 따른다。

추가 (역할 분담 판단 기준)
- 에이전트는 작업의 난이도가 아니라 작업의 성격을 기준으로 역할을 분담한다。

추가 (공통 원칙)
- 조회 가능한 프로젝트 범위가 넓어졌더라도 각 에이전트의 역할은 변경되지 않는다。
- 역할은 작업 성격 기준으로 판단한다。

13. 작업 지시 원칙
==================================================

모든 AI는 다음 원칙을 따른다。

1.
사용자가 요청하지 않은 기능은 구현하지 않는다。

2.
사용자가 요청하지 않은 구조 변경은 하지 않는다。

3.
기존 구조를 단순화하거나 최적화하기 전에
반드시 영향도를 검토한다。

4.
삭제 작업은 반드시 사용자 승인 후 수행한다。

5.
기존 정책과 다른 구현이 필요한 경우
먼저 이유를 보고하고 승인을 받은 후 진행한다。

6.
불확실한 사항은 추측하지 않는다。

7.
MASTER_SPEC와 충돌 가능성이 있으면
즉시 검토를 요청한다。

8.
구현 중 의심되는 사항은
추측으로 처리하지 않는다。

==================================================
13.1 Reporting Principle

Reports should contain only results, key validation, and remaining risk.
Do not write long explanations or repeated reports unrelated to implementation.

==================================================
13.2 AI Role Separation Principle
==================================================

Project operating roles are limited to ChatGPT and Codex.

1. ChatGPT Role

ChatGPT is responsible for judgment and review.

Scope:
- Project architecture design
- Implementation direction decisions
- Work priority decisions
- Contract review
- Codex review
- Bug root-cause analysis
- Implementation scope decisions
- Codex task instruction writing
- Final merge approval judgment

--------------------------------------------------

2. Codex Role

Codex executes implementation work decided by ChatGPT.

Scope:
- Codex implementation
- Refactoring
- Test writing
- Git work
- Commit
- Push
- PR
- Merge

When responsibilities appear to overlap, ChatGPT owns judgment and review; Codex owns execution.

==================================================
13.3 지시문 운영 원칙
==================================================

반복되는 운영 규칙을 매 지시문마다 모두 다시 작성하지 않는다.

세션 시작 후에는 현재 운영 규정을 기준으로 필요한 작업 범위만 추가 지시하는 것을 원칙으로 한다.

GitHub 재조회 규칙은 기존 내용(§17)을 유지한다。

==================================================
13.4 검증 원칙
==================================================

구조적 타당성
책임 분리

아키텍처 적합성
구현 방향

=================================================

Codex는 결과 보고 시

- 불필요한 설명을 반복하지 않는다。
- 이미 보고한 내용을 다시 반복하지 않는다。
- 사용자와의 대화를 보고 내용에 포함하지 않는다。
- 질문을 보고서에 포함하지 않는다。
- 작업 과정 설명을 장황하게 작성하지 않는다。
- 동일한 내용을 여러 표현으로 반복하지 않는다。
- 구현과 관계없는 의견을 작성하지 않는다。
- 필요한 결과만 간결하게 보고한다。

보고는 다음 항목만 포함하는 것을 원칙으로 한다。

- 작업 결과
- 변경 파일
- 검증 결과
- Git 결과
- 다음 작업(필요한 경우만)

18. 문서 반영 책임 (MASTER_SPEC Documentation Authority)
==================================================

여러 AI 모델을 병행 사용하는 경우,
다음 문서들에 어떤 내용을 기록할지는 ChatGPT가 최종 결정한다.

- MASTER_SPEC
- CHANGELOG
- 작업재개요약
- 참조 문서

17. GitHub 재조회 기준
==================================================

GitHub는 모든 작업마다 반복 조회하지 않는다.
재조회는 다음 시점으로만 제한한다 (운영 매뉴얼 §6.3 준수).

재조회 시점
- 새 AI 세션 시작
- Git commit 또는 GitHub Push 완료 이후
- 운영 문서 변경 (README / AI_PROJECT_OPERATION_MANUAL_RELEASE / AI_SESSION_START_PROTOCOL / MASTER_SPEC / CHANGELOG)
- MASTER_SPEC 변경
- 사용자가 GitHub 확인을 요청한 경우
- ChatGPT가 구조 충돌 가능성을 판단한 경우

금지
- 구현 진행 중 반복 GitHub 조회 금지
- 세션 시작 시 확인한 GitHub 상태를 기준으로 작업 진행

==================================================
17.1 Workflow v2 (Pull Request & Agent Operation Policy)
==================================================

본 섹션은 기존 Legacy Workflow를 삭제하거나 대체하지 않는다.
기존 번호 체계와 기존 운영 규정은 유지하며, 최신 Pull Request 기반 운영 정책을 추가로 정의한다.

단, kiwoom_auto 저장소의 Git 운영은 Workflow v2를 우선 적용한다.

Legacy Workflow는 다음 목적을 위해 유지한다.

- 과거 작업 기록
- 호환성
- 문서 참조

Git 운영 규칙이 충돌하는 경우 Workflow v2를 우선한다.

--------------------------------------------------
17.1.1 Pull Request Workflow - kiwoom_auto
--------------------------------------------------

kiwoom_auto 저장소는 Feature Branch 기반으로 운영한다.

Workflow:

master 최신화
→ feature branch 생성
→ 구현
→ 테스트
→ Commit
→ Push
→ Pull Request 생성
→ Review
→ Merge
→ master

원칙:

- master 직접 Commit 금지
- master 직접 Push 금지
- 긴급 Hotfix만 예외
- Feature 하나 = Branch 하나
- Feature 하나 = Pull Request 하나
- Merge 후 master 최신화

Merge 완료 후:

master 전환
→ origin/master 최신화
→ feature branch 삭제 여부 확인
→ 다음 작업 시작

--------------------------------------------------
17.1.2 Docs Workflow - docs
--------------------------------------------------

docs 저장소는 기존 Canonical 운영을 유지한다.

Workflow:

Canonical 갱신
→ Commit
→ Push

원칙:

- docs 저장소는 PR 의무 없음
- 사용자 승인, diff 확인, 명시적 Stage 확인 후 직접 Commit / Push 허용
- 기존 Canonical / Reference / CHANGELOG 운영 규칙 유지
- 기존 문서 번호 체계와 Legacy Workflow 유지

--------------------------------------------------
17.1.3 Agent Role Policy
--------------------------------------------------

Only two roles are maintained: ChatGPT and Codex.

Auxiliary tools are not defined as formal operating roles.

[ChatGPT]

Responsibilities:
- Project architecture design
- Implementation direction decisions
- Work priority decisions
- Contract review
- Codex review
- Bug root-cause analysis
- Implementation scope decisions
- Codex task instruction writing
- Final merge approval judgment

Principle:
- ChatGPT is responsible for judgment and review rather than direct implementation.
- ChatGPT does not duplicate Codex implementation responsibility.

[Codex]

Responsibilities:
- Codex implementation
- Refactoring
- Test writing
- Git work
- Commit
- Push
- PR
- Merge
- Execute implementation tasks decided by ChatGPT

Principle:
- Codex turns decided implementation work into code and tests.
- Codex does not duplicate ChatGPT judgment and review responsibility.

17.1.4 Protected File Policy
--------------------------------------------------

다음 파일은 항상 보호한다.

- rules.json
- stocks/*/state.json

명시적 지시 없이는 다음 작업을 금지한다.

- Stage 금지
- Commit 금지
- Restore 금지
- Reset 금지
- Stash 금지

--------------------------------------------------
17.1.5 Work Start Procedure
--------------------------------------------------

Codex는 다음 순서를 기본으로 한다.

master 최신화
→ origin/master 확인
→ feature branch 생성
→ 구현
→ 테스트

--------------------------------------------------
17.1.6 Work Close Procedure
--------------------------------------------------

Codex는 다음 순서를 기본으로 한다.

Commit
→ Push
→ HEAD 확인
→ origin 확인
→ Pull Request 생성
→ Merge 확인
→ master 최신화
→ feature branch 종료 확인
→ 최종 보고

--------------------------------------------------
17.1.7 Workflow Priority
--------------------------------------------------

우선순위:

1. Workflow v2
2. Legacy Workflow
3. 기타 운영 메모

Git 운영 규칙이 충돌하는 경우 Workflow v2를 따른다.

Legacy Workflow는 기존 작업 기록과 호환성 보존을 위한 참조 규정으로 유지한다.
