13. 작업 지시 원칙
==================================================

모든 AI는 다음 원칙을 따른다。

1.
사용자가 요청하지 않은 기능은 구현하지 않는다。

2.
사용자가 요청하지 않은 구조 변경은 하지 않는다。

3.
기존 구조를 단순화하거나 최적화하기 전에
반드시 영향도를 검토한다。

4.
삭제 작업은 반드시 사용자 승인 후 수행한다。

5.
기존 정책과 다른 구현이 필요한 경우
먼저 이유를 보고하고 승인을 받은 후 진행한다。

6.
불확실한 사항은 추측하지 않는다。

7.
MASTER_SPEC와 충돌 가능성이 있으면
즉시 검토를 요청한다。

8.
구현 중 의심되는 사항은
추측으로 처리하지 않는다。

13.2 AI 역할 분리 원칙
==================================================

프로젝트는 AI별 역할을 분리하여 운영한다.

1. Codex 역할

Codex는 프로젝트의 주 구현 모델이다.

담당 범위

- 구조 설계
- 계층 설계
- Runtime / Execution Pipeline
- Engine 구현
- Rule Mapper
- Execution Policy
- Runtime Projection
- Runtime Commit 계층
- Order Candidate 계층
- 대규모 리팩토링
- 테스트 작성
- 구조 검증
- 복잡한 구현 작업

일반 코드 모델이 처리하기 어려운 구현은 Codex를 우선 사용한다.

--------------------------------------------------

2. 일반 코드 모델 역할

일반 코드 모델은 보조 모델로 사용한다.

담당 범위

- docs 저장소 관리
- Canonical 문서 갱신
- CHANGELOG 갱신
- WORK_RESUME 갱신
- REFERENCE 갱신
- Git 상태 확인
- Commit / Push
- GitHub 동기화
- 문서 구조 정리
- 프로젝트의 소규모 코드 수정
- 간단한 버그 수정
- 검증 작업
- 코드 리뷰
- 조사 및 분석

복잡한 구조 설계나 대규모 구현은 담당하지 않는다.

--------------------------------------------------

3. 작업 지시 원칙

Codex용 지시문과 일반 코드 모델용 지시문을 구분한다.

Codex용

- 구현 범위 제한 없음
- 대규모 구조 변경 가능
- 신규 계층 생성 가능
- 복잡한 구현 담당

일반 코드 모델용

- 한 번에 하나의 기능만 작업한다.
- 기존 구조를 우선 재사용한다.
- 대규모 설계는 수행하지 않는다.
- 새로운 계층 생성은 최소화한다.
- 문서 및 Git 작업을 우선 담당한다.
- 구현 범위는 일반 코드 모델이 안정적으로 처리 가능한 수준으로 제한한다.

프로젝트는 역할 분리를 유지하여 안정성과 구현 품질을 확보한다.


==================================================

일반 코드 모델은 결과 보고 시

- 불필요한 설명을 반복하지 않는다。
- 이미 보고한 내용을 다시 반복하지 않는다。
- 사용자와의 대화를 보고 내용에 포함하지 않는다。
- 질문을 보고서에 포함하지 않는다。
- 작업 과정 설명을 장황하게 작성하지 않는다。
- 동일한 내용을 여러 표현으로 반복하지 않는다。
- 구현과 관계없는 의견을 작성하지 않는다。
- 필요한 결과만 간결하게 보고한다。

보고는 다음 항목만 포함하는 것을 원칙으로 한다。

- 작업 결과
- 변경 파일
- 검증 결과
- Git 결과
- 다음 작업(필요한 경우만)

17. GitHub 재조회 기준
==================================================

GitHub는 모든 작업마다 반복 조회하지 않는다.
재조회는 다음 시점으로만 제한한다 (운영 매뉴얼 §6.3 준수).

재조회 시점
- 새 AI 세션 시작
- Git commit 또는 GitHub Push 완료 이후
- 운영 문서 변경 (README / AI_PROJECT_OPERATION_MANUAL_RELEASE / AI_SESSION_START_PROTOCOL / MASTER_SPEC / CHANGELOG)
- MASTER_SPEC 변경
- 사용자가 GitHub 확인을 요청한 경우
- ChatGPT가 구조 충돌 가능성을 판단한 경우

금지
- 구현 진행 중 반복 GitHub 조회 금지
- 세션 시작 시 확인한 GitHub 상태를 기준으로 작업 진행
