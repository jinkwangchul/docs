# 0. 문서 지위

본 문서는 기존 `MASTER_SPEC v1.1 Windows GUI Edition`을 대체하는 최신 기준 문서이다.

단, v1.1 원본은 삭제하거나 직접 수정하지 않는다.

코드가 아직 v1.2를 완전히 반영하지 않았더라도, 이후 구조개선 및 OpenAPI 연결 전 정책 기준은 본 문서를 따른다.

# 2. 최상위 운영 철학

1. 안정성 최우선.
2. 상태확인 없는 자동주문 금지.
3. 상태확인 없는 자동청산 금지.
4. 상태확인 없는 자동복귀 금지.
5. 자동매매 신뢰성이 훼손된 종목은 검토종목으로 격리.
6. 계좌 단위 문제는 긴급정지.
7. 종목 단위 문제는 해당 종목만 격리.
8. 루틴은 신호 생성기이고, 메인엔진이 실행 가능 여부를 최종 판정한다.
9. 운영자는 GUI에서 상태와 문제 위치를 즉시 이해할 수 있어야 한다.
10. 기존 MASTER_SPEC v1.1은 원본 보존하고, v1.2부터 최신 정책을 반영한다.

# 4. 최종 상태 체계

v1.2의 최종 상태는 아래 6개이다.

1. 감시/대기
2. 매수/매도
3. 감시/매도
4. 조기마감
5. 긴급정지
6. 검토종목

---

## 4.1 감시/대기

감시는 수행하지만 매수/매도 주문은 하지 않는 상태이다.

진입 예:

- 시작시간 이전
- 거래불가시간
- 보유수량 0
- 감시/매도 후 정리 완료
- 조기마감 후 전량 정리 완료

동작:

- 신규매수 금지
- 신규매도 금지
- 상태조회 가능
- 현재가 조회 가능
- 로그 확인 가능

이탈:

- 운영시간 시작 + 무결성 정상 + 검토종목 아님 + 긴급정지 아님 → 매수/매도

---

## 4.2 매수/매도

정상 자동매매 상태이다.

동작:

- 매수 가능
- 매도 가능
- 루틴 신호는 메인엔진의 최종 판정을 거쳐 실행

진입 조건:

- 운영시간 중
- 무결성 정상
- 검토종목 아님
- 긴급정지 아님
- 미체결 잠금 조건에 걸리지 않음

이탈:

- 운영시간 종료 → 감시/매도
- 조기마감 실행 → 조기마감
- 계좌 단위 문제 → 긴급정지
- 종목 단위 문제 → 검토종목

---

## 4.3 감시/매도

신규매수는 금지하고 매도만 허용하는 상태이다.

목적:

- 시간운영 종료 후 신규 진입을 막고, 보유 종목 정리만 허용

기본 동작:

- 매수신호 폐기
- 매도신호는 메인엔진 판정 후 실행 가능
- 기본 매도 판단은 루틴의 매도정책을 따른다
- +N% 익절, -N% 손절 등 루틴 기반 매도조건 허용

진입 예:

- 시간운영 종료
- 종료 후 정책이 감시/매도인 경우

이탈:

- 보유수량 0 → 감시/대기
- 조기마감 실행 → 조기마감
- 계좌 단위 문제 → 긴급정지
- 종목 단위 문제 → 검토종목

---

## 4.4 조기마감

운영자가 강제로 정리 절차를 시작한 상태 또는 표시상태이다.

조기마감은 감시/매도와 분리한다.

이유:

- 감시/매도는 일반 시간운영 종료 상태
- 조기마감은 운영자가 명시적으로 실행한 예외적 정리 상태

기본 동작:

- 신규매수 금지
- 루틴 유지
- 시간조건 제거
- 즉시 매도조건 평가

조기마감은 단순 시장가 강제청산이 아니다.

기본값:

```text
루틴 유지
+ 시간조건 제거
+ 즉시평가
```

예:

- 기존 루틴: 14:50 이후 매도 판단
- 조기마감 실행: 현재 시각 기준 즉시 매도 판단

추가 옵션 후보:

- 현재가 청산
- 시장가 청산
- 지정가 청산
- 익절 N% 이상 청산
- 손절 N% 이하 청산
- 익일이월

이탈:

- 전량 정리 완료 → 감시/대기
- 익일이월 → 검토종목
- 청산실패 → 검토종목
- 잔량발생 → 검토종목
- 계좌 단위 문제 → 긴급정지

---

## 4.5 긴급정지

계좌 단위 문제, 시스템 이상, API 이상, 운영자 강제중단 시 사용하는 비상 상태이다.

진입 예:

- 예수금 조회 실패
- 잔고 조회 실패
- 계좌 전체 조회 실패
- API 이상
- 주문 가능 상태 확인 실패
- 운영자 긴급정지

동작:

- 신규매수 금지
- 신규매도 금지
- 자동판단 중지
- 자동청산 중지
- 실시간 감시와 계좌조회는 가능하면 유지

해제:

```text
긴급정지 해제 요청
→ 무결성 검사
→ 현재조건 재판정
→ 복귀 또는 검토종목 이동 또는 긴급정지 유지
```

자동복귀:

- 금지

---

## 4.6 검토종목

자동매매 신뢰성이 훼손된 종목의 격리 상태이다.

검토종목은 자동매매 대상에서 제외한다.

진입 예:

- 수량불일치
- 주문불일치
- 잔고불일치
- 청산실패
- 잔량발생
- 익일이월
- 무결성실패
- 파일구조이상
- 설정파일이상
- 루틴 참조 누락

허용 기능:

- 상태조회
- 로그조회
- 미체결 취소
- 현재가 매도
- 시장가 매도
- 수동 무결성 검사
- 검토종목 해제 후보 처리

금지 기능:

- 자동매수
- 자동매도
- 루틴신호 자동실행
- 자동복귀
- 신규 루틴 자동연결

복귀:

```text
운영자 확인
→ 문제 해결
→ 수동 무결성 검사
→ 통과
→ 현재조건 재판정
→ 감시/대기 또는 매수/매도 또는 감시/매도
```

자동복귀:

- 금지

# 6. 루틴과 메인엔진 책임 분리

## 6.1 루틴 역할

루틴은 신호 생성기이다.

담당:

- 매수신호 생성
- 매도신호 생성
- 보유 또는 무신호 판단
- +N% 익절 조건 판단
- -N% 손절 조건 판단
- MACD 등 기술적 신호 판단
- 조기마감 시 시간조건 제거 후 즉시 평가

루틴은 주문을 직접 실행하지 않는다.

루틴은 시간판정, 긴급정지, 장마감 정책, 검토종목 정책을 직접 처리하지 않는다.

---

## 6.2 메인엔진 역할

메인엔진은 통합 통제기이다.

담당:

- 현재시간 판정
- 운영방식 판정
- 상태 판정
- 긴급정지 판정
- 검토종목 여부 판정
- 장마감 정책
- 조기마감 정책
- 이월 정책
- 미체결 주문 정책
- 계좌 무결성 검사
- 주문 실행 가능 여부 최종 결정
- 실제 주문 실행

원칙:

```text
루틴 = 신호 생성
메인엔진 = 실행 가능 여부 최종판정 + 주문집행
```

---

# 7. 루틴 매매조건 정책

루틴은 매수조건과 매도조건을 독립적으로 가질 수 있다.

예:

```text
매수 = MACD 조건
매도 = 매수가 대비 +N% 익절
매도 = 매수가 대비 -N% 손절
```

이 구조는 v1.2 상태체계와 충돌하지 않는다.

이유:

- 감시/매도는 매수만 금지하고 매도는 허용한다.
- 조기마감은 루틴 매도조건을 유지하되 시간조건만 제거한다.
- 긴급정지와 검토종목에서는 메인엔진이 주문 실행을 차단한다.

필수 입력:

- 매수가
- 현재가
- 수익률
- 보유수량
- 미체결 상태

---

# 8. 시간운영 정책

시간운영은 종목 또는 루틴에 설정된 운영시간을 기준으로 상태를 산출한다.

기본 흐름:

```text
시작시간 이전 → 감시/대기
운영시간 중 → 매수/매도
종료시간 이후 → 감시/매도
```

종료 후 기본 정책:

- 감시/매도

정지 표시명은 사용하지 않는다.

시간운영 종료 후 감시/매도 상태에서는 신규매수는 금지하고, 매도는 루틴의 매도정책을 따른다.

---

# 9. 수동운영 정책

수동운영은 시간운영 전역설정 영향을 직접 받지 않는다.

수동운영은 실제 거래 가능 시간 여부만 확인한다.

거래 가능 시간:

- 매수/매도 가능

거래 불가 시간:

- 감시/대기

거래구간 후보:

- 정규장
- 장전 시간외
- 장후 시간외
- 사용자 정의 구간

실제 주문 가능 여부는 키움 OpenAPI 또는 HTS의 거래 가능 상태를 우선한다.

---

# 10. 조기마감 정책

조기마감은 일반 감시/매도와 구분한다.

실행 위치:

- 상태 컬럼 우클릭 메뉴

좌클릭 정책:

- 수동 컬럼 클릭 → 수동운영 설정
- 시간 컬럼 클릭 → 시간운영 설정

우클릭 정책:

- 상태 컬럼 우클릭 → 조기마감, 긴급정지, 무결성 검사, 검토종목 이동 등 운영 명령

조기마감 기본값:

```text
루틴 유지
+ 시간조건 제거
+ 즉시평가
```

조기마감 후 상태 표시:

- 조기마감

감시/매도와 조기마감은 표시를 분리한다.

# 11. 장마감 / 청산정책

청산정책 후보:

- 루틴 유지 + 시간조건 제거 + 즉시평가
- 현재가 청산
- 시장가 청산
- 지정가 청산
- 익절 N% 이상 청산
- 손절 N% 이하 청산
- 익일이월

청산 실패:

```text
청산실패
→ 검토종목
```

잔량 발생:

```text
잔량발생
→ 검토종목
```

익일이월:

```text
익일이월
→ 검토종목
```

# 12. 검토종목 정책

## 12.1 목적

검토종목은 자동매매 신뢰성이 훼손되었거나 운영자 확인이 필요한 종목을 자동운영에서 분리하여 관리하는 격리 영역이다.

---

## 12.2 검토위치와 상세원인

v1.2에서는 `진입사유`라는 단일 표현을 사용하지 않는다.

대신 아래 두 값을 분리한다.

```text
검토위치 = 문제 유형
상세원인 = 발생 원인
```

검토위치 예:

- 수량불일치
- 주문불일치
- 잔고불일치
- 청산실패
- 잔량발생
- 익일이월
- 무결성실패
- 파일구조이상
- 설정파일이상
- 루틴참조이상
- 기타

상세원인 예:

- HTS 수동매도
- HTS 수동매수
- HTS 수동취소
- API 조회 실패
- 프로그램 재시작
- 파일 누락
- JSON 손상
- 루틴 폴더 삭제
- 종목 폴더명 변경

HTS 수동개입은 검토위치가 아니라 상세원인으로 기록하는 것을 기본으로 한다.

예:

```text
검토위치: 수량불일치
상세원인: HTS 수동매도
```

```text
검토위치: 주문불일치
상세원인: HTS 수동취소
```

# 13. 긴급정지 정책

긴급정지는 단일 체계로 운영한다.

다단계 긴급정지는 사용하지 않는다.

긴급정지 동작:

- 신규매수 금지
- 신규매도 금지
- 자동판단 중지
- 자동청산 중지
- 실시간 감시 유지
- 계좌조회 유지

긴급정지 해제:

```text
운영자 해제 요청
→ 무결성 검사
→ 현재조건 재판정
```

자동복귀:

- 금지

# 14. 무결성 검사 체계

무결성 검사는 3종류로 구분한다.

1. 자동 무결성 검사
2. 개별 무결성 검사
3. 전체 무결성 검사

공통 검사 순서:

```text
구조 무결성
→ 종목 무결성
→ 계좌 무결성
→ 최종판정
```

버튼은 1개로 유지하고 내부적으로 3단계를 순차 수행한다.

---

## 14.1 자동 무결성 검사

실행 시점:

- 종목 등록 시
- 프로그램 재시작 시

목적:

- 위험 종목이 정상 운영 상태로 진입하는 것을 차단

종목 등록 시 검사 항목:

- 보유수량 0 여부
- 미체결 매수 0 여부
- 미체결 매도 0 여부
- 계좌조회 정상 여부

판정:

- 정상 → 일반 등록 가능
- 이상 → 검토종목 이동

UI 원칙:

- 종목등록창에는 별도 무결성 검사 버튼을 두지 않는다.
- 등록 과정에서 내부 로직으로 자동 수행한다.

---

## 14.2 개별 무결성 검사

실행 위치:

- 검토종목 관리창

대상:

- 선택된 검토종목

목적:

- 검토종목이 정상 운영으로 복귀 가능한지 판정

흐름:

```text
검토종목 선택
→ 무결성 검사
→ 구조 무결성
→ 종목 무결성
→ 계좌 무결성
→ 통과 시 현재조건 재판정
→ 복귀 가능
```

실패 시:

- 검토종목 유지
- 실패 단계 기록
- 상세원인 기록

---

## 14.3 전체 무결성 검사

실행 위치:

- 관제센터 도구 메뉴

대상:

- 전체 종목
- 전체 파일/폴더 구조
- 전체 계좌 상태

목적:

- 시스템 건강검진

사용 예:

- 프로그램 시작 후 점검
- 대규모 설정 변경 후 점검
- 백업 복원 후 점검
- 운영자가 이상을 의심할 때

---

## 14.4 구조 무결성

검사 항목:

- 필수 폴더 존재 여부
- 필수 파일 존재 여부
- JSON 파일 파싱 가능 여부
- 루틴 참조 존재 여부
- 종목데이터 경로 정상 여부
- 설정파일 손상 여부

실패 예:

- state.json 누락
- orders.json 누락
- config.json 누락
- JSON 손상
- 루틴 폴더 삭제
- 종목 폴더명 변경
- 필수 경로 누락

실패 처리:

- 종목 단위 구조 문제 → 검토종목
- 전체 구조 문제 → 긴급정지 검토

---

## 14.5 종목 무결성

검사 항목:

- 프로그램 내부 보유수량 기록
- 프로그램 내부 주문기록
- 종목별 상태값
- 종목별 설정값
- 루틴 연결 정보
- 검토위치 해소 여부

실패 예:

- 상태값 없음
- 알 수 없는 상태값
- 주문기록 손상
- 루틴 연결 정보 불일치
- 종목 설정 누락

실패 처리:

- 검토종목 유지 또는 검토종목 이동

---

## 14.6 계좌 무결성

검사 항목:

- HTS/계좌 실제 보유수량
- 프로그램 기록 보유수량
- HTS/계좌 실제 미체결 매수
- HTS/계좌 실제 미체결 매도
- 프로그램 기록 미체결
- 잔고조회 가능 여부
- 현재가 조회 가능 여부
- 주문 가능 상태 여부

실패 예:

- 보유수량 불일치
- 미체결 매수 불일치
- 미체결 매도 불일치
- 잔고조회 실패
- 현재가 조회 실패
- 계좌정보 조회 실패

실패 처리:

- 종목 단위 문제 → 검토종목
- 계좌 전체 문제 → 긴급정지

# 15. 파일 / 폴더 구조 정책

v1.1은 루틴별 종목폴더 구조를 기본으로 했다.

v1.2에서는 종목데이터 중앙집중화 방향을 채택한다.

목표 구조:

```text
kiwoom_auto/
├─ gui_main.py
├─ gui_windows.py
├─ state_policy.py
├─ runtime_io.py
├─ gui_order_utils.py
├─ gui_schedule_utils.py
├─ gui_config_utils.py
├─ gui_routine_policy.py
├─ gui_routine_service.py
├─ gui_routine_guard.py
├─ gui_review_utils.py
├─ data/
│  └─ stocks/
│     └─ 005930_삼성전자/
│        ├─ state.json
│        ├─ orders.json
│        ├─ config.json
│        └─ stock_log.txt
├─ routines/
│  └─ 루틴명/
│     ├─ routine_config.json
│     └─ routine_logic.py
├─ logs/
│  ├─ operation.log
│  ├─ policy.log
│  ├─ order.log
│  └─ exception.log
└─ docs/
   ├─ spec_archive/
   │  └─ MASTER_SPEC_v1.1_윈도우창버전_키움자동매매.txt
   └─ MASTER_SPEC_v1.2_structure_phase2.md
```

원칙:

- 종목별 상태, 주문, 설정은 종목데이터 쪽에 단일화한다.
- 루틴폴더는 루틴 설정과 신호 생성에 필요한 자료만 보유한다.
- `기초종목.txt`는 현재 루틴 지정 또는 종목 마스터 목록 역할만 담당한다.
- 실제 상태 판단은 중복된 루틴폴더 state가 아니라 중앙 종목데이터를 기준으로 한다.

주의:

- 기존 폴더 구조는 코드 영향 범위 검토 후 단계적으로 이관한다.
- 즉시 전체 이관하지 않는다.

# 16. 미체결 정책

현재 확정:

```text
동일 종목 미체결 존재 시 신규주문 금지
```

미체결 매수 존재:

- 신규매수 금지

미체결 매도 존재:

- 신규매도 금지 또는 기존 매도 주문 유지
- 세부정책은 주문정책 구현 단계에서 확정

보류:

- 장시간 미체결 자동취소
- 재주문 정책
- 부분체결 세부규칙
- 가격 허용범위

# 17. 상태 우선순위

상태 판정 우선순위는 아래 순서를 따른다.

1. 검토종목
2. 긴급정지
3. 계좌 무결성
4. 종목 무결성
5. 조기마감 / 청산정책
6. 운영방식
7. 루틴신호

원칙:

- 검토종목은 어떤 루틴신호보다 우선한다.
- 긴급정지는 일반 운영방식보다 우선한다.
- 계좌 단위 문제는 전체 긴급정지로 처리한다.
- 종목 단위 문제는 해당 종목만 검토종목으로 격리한다.

# 22. 실계좌 안전장치

실계좌 자동매매는 기본 비활성화한다.

실계좌 자동매매 실행은 사용자 수동 승인 후에만 허용한다.

실계좌 전환 전 필수 확인:

- 자동 무결성 검사 통과
- 전체 무결성 검사 통과 권장
- 긴급정지 아님
- 검토종목 아님
- 주문 가능 상태 확인
- 현재가 조회 가능

# 25. v1.2 최종 판정

v1.2의 핵심 변경은 단순 UI 개선이 아니라 자동매매 안정성 중심의 상태체계 재정립이다.

핵심 결론:

1. 감시/매도와 조기마감을 분리한다.
2. 긴급정지는 단일 체계로 운영한다.
3. 검토종목은 자동매매 격리구역으로 사용한다.
4. 익일이월은 검토종목으로 이동한다.
5. 무결성 검사는 자동/개별/전체 3종류로 나눈다.
6. 루틴은 신호만 만들고 메인엔진이 실행 가능 여부를 판정한다.
7. 파일/폴더 구조 이상도 무결성 검사 대상에 포함한다.
8. MASTER_SPEC v1.1은 원본 보존하고 v1.2를 최신 기준으로 사용한다.
