MASTER_SPEC 누락보강 10
주제 : 프로젝트 철학 및 설계 원칙 종합

1. 목적
본 문서는 프로젝트 전반에 공통 적용되는 핵심 철학과 설계 원칙을 정리하여
향후 기능 추가와 구조 변경 시 기준 문서로 활용한다.

2. 프로젝트 철학
- 기능보다 구조를 우선한다.
- 구조보다 철학을 우선한다.
- 임시 해결보다 확장 가능한 설계를 우선한다.
- 구현보다 검증을 우선한다.

3. 자동매매 철학
- 루틴은 '언제 매매할 것인가'를 판단한다.
- 메인은 '어떻게 주문할 것인가'를 수행한다.
- 루틴과 메인의 책임은 명확히 분리한다.

4. 설계 원칙
- 공통 구조를 최대한 재사용한다.
- 동일 기능은 동일한 정책을 사용한다.
- UI와 엔진은 독립성을 유지한다.
- 정책 변경이 엔진 변경으로 이어지지 않도록 설계한다.

5. UI 철학
- 실행 흐름을 그대로 표현한다.
- 사용자가 한 화면에서 전체 흐름을 이해할 수 있어야 한다.
- 설정 순서와 실제 처리 순서를 최대한 일치시킨다.

6. 데이터 관리 원칙
- 설정은 데이터로 저장한다.
- 위젯 상태를 직접 저장하지 않는다.
- 공통 데이터 구조를 사용한다.

7. 유지보수 원칙
- 기존 구조를 존중한다.
- 필요한 부분만 수정한다.
- 변경 범위를 명확히 기록한다.
- 변경 이유를 문서화한다.

8. 검증 원칙
- UI 검증
- 저장 검증
- 엔진 검증
- 통합 검증
단계를 거쳐 기능을 확정한다.

9. 장기 목표
- 루틴 추가 시 동일 구조 재사용
- 설정창 공통화
- 엔진 공통화
- 정책 공통화
- 유지보수 비용 최소화

10. 최종 원칙
프로젝트의 모든 구현은
'확장 가능성, 일관성, 안정성'을 유지하는 방향으로 진행하며,
임시 구현이나 예외 처리는 최소화한다.
