MASTER_SPEC_추가갱신_프로젝트_의사결정기록_ADR_Index_2026-07-03

목적
- 프로젝트에서 이미 확정된 중요한 구조적 의사결정을 한 곳에 기록한다.
- 향후 동일한 논의를 반복하거나 기존 결정을 뒤집는 일을 줄이기 위한 기준 문서이다.

==================================================
ADR-001
==================================================
주제
루틴은 주문을 실행하지 않는다.

결정
- 루틴의 책임은 Signal 생성까지이다.
- 주문 실행은 별도 주문 파이프라인이 담당한다.

==================================================
ADR-002
==================================================
주제
Preview와 Apply를 분리한다.

결정
- evaluate_* : 메모리 결과만 반환
- build_* : 객체 생성
- apply_* : Runtime 반영

==================================================
ADR-003
==================================================
주제
실주문은 단일 진입점만 허용한다.

결정
- SendOrder는 Boundary/Executor 계층만 호출 가능하다.
- GUI, Timer, Engine에서 직접 호출하지 않는다.

==================================================
ADR-004
==================================================
주제
상태 전이는 State Machine만 따른다.

결정
- Controller만 상태를 변경한다.
- 임의 상태 변경을 금지한다.

==================================================
ADR-005
==================================================
주제
Position은 Fill 결과이다.

결정
- SendOrder 성공으로 Position을 변경하지 않는다.
- Fill만 Position을 변경할 수 있다.

==================================================
ADR-006
==================================================
주제
마감과 청산은 구분한다.

결정
- 마감은 운영 절차
- 청산은 Position 종료 절차

==================================================
ADR-007
==================================================
주제
Runtime 파일은 역할별로 분리한다.

결정
- Signal
- Order
- Guard
- Execution
- Fill
- Position
- Review
- Audit
각각 독립 책임을 가진다.

==================================================
ADR-008
==================================================
주제
안전성을 기능보다 우선한다.

결정
- Preview 검증을 우선한다.
- 테스트와 문서 없이 구조를 변경하지 않는다.
- 실주문 연결은 마지막 단계에서만 수행한다.

최종 원칙
ADR은 프로젝트의 구조적 합의 사항이며,
새로운 결정이 기존 ADR과 충돌할 경우 기존 ADR을 먼저 검토한 후 변경 여부를 판단한다.
