MASTER_SPEC 누락보강 35
주제 : 상태 동기화 및 이벤트 처리 정책

1. 목적
UI, 저장 데이터, 루틴 엔진, 메인 엔진의 상태를 항상 동일하게 유지하기 위한
상태 동기화 및 이벤트 처리 기준을 정의한다.

2. 기본 원칙
- 하나의 상태는 하나의 기준값만 가진다.
- 표시 상태와 내부 상태가 서로 달라지지 않아야 한다.
- 이벤트는 항상 상태 변경을 통해 처리한다.

3. 상태 동기화 대상
- UI 활성/비활성
- 설정 데이터
- rules.json
- 루틴 상태
- 주문 상태
- 종목 상태

4. 이벤트 흐름
① 사용자 입력
② UI 이벤트 발생
③ 상태 검증
④ 데이터 갱신
⑤ 화면 갱신
⑥ 엔진 전달(필요 시)

5. 처리 원칙
- 동일 이벤트는 동일 처리 함수 사용
- 중복 이벤트 처리 금지
- 상태 변경 없이 화면만 변경 금지

6. 예외 처리
- 데이터 불일치 감지
- 이벤트 중복 발생
- 잘못된 상태 전이
- 런타임 오류 발생 시 이전 정상 상태 유지

7. 구현 원칙
- 상태 변경은 공통 관리 계층에서 수행
- UI는 상태 표시 역할에 집중
- 엔진은 상태 변경 요청만 수행

8. 검증 항목
□ UI 표시와 내부 상태 일치
□ 저장 데이터 일치
□ 이벤트 중복 여부
□ 상태 전이 정상 여부
□ 복구 동작 확인

9. 향후 보강
- 이벤트 큐 관리
- 상태 변경 로그
- 상태 변경 이력 추적
- 이벤트 디버깅 도구

10. 결론
상태 동기화는 프로젝트 전체 안정성의 핵심이며,
모든 이벤트는 공통 상태 관리 원칙을 기반으로 처리한다.
