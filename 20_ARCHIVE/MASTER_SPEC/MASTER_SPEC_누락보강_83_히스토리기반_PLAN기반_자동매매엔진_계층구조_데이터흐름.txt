MASTER_SPEC 누락보강 83
주제 : 히스토리 기반 PLAN 기반 자동매매 엔진의 계층 구조 및 데이터 흐름

출처 : 작업진행상황대화히스토리_3~8 비교 반영

1. 목적
PLAN 기반 자동매매 엔진의 계층 구조와 데이터 흐름을 표준화하여
루틴, PLAN, 주문 엔진 간의 역할과 데이터 이동 경로를 명확히 정의한다.

2. 기본 철학
- 계층은 단방향으로 데이터를 전달한다.
- 하위 계층은 상위 전략을 임의로 변경하지 않는다.
- 공통 인터페이스를 통해서만 정보를 교환한다.

3. 계층 구조
① 루틴(Routine)
- 신호 생성
- 정책 정의
- 종료 조건 정의

② PLAN
- 주문 계획 생성
- 상태 관리
- 생명주기 관리

③ 주문 엔진
- 주문 생성
- 주문 전송
- 체결 감시
- 주문 상태 반영

④ 운영 관리
- 로그 기록
- 상태 저장
- 복구
- 검토관리 연계

4. 데이터 흐름
신호 생성
→ PLAN 생성
→ 주문 요청
→ 주문 실행
→ 체결 결과
→ 상태 갱신
→ 종료 및 기록

5. 구현 원칙
- 각 계층은 자신의 책임만 수행한다.
- 계층 간 직접 참조를 최소화한다.
- 공통 인터페이스를 통해서만 데이터를 전달한다.

6. 검증 항목
□ 계층 분리
□ 데이터 흐름 일관성
□ 상태 동기화
□ 로그 일치
□ 복구 일치
□ 계층 책임 준수

7. 반영 원칙
본 기준은 히스토리에서 확정된 PLAN 기반 자동매매 엔진의 계층 설계 철학이며,
향후 모든 루틴과 주문 처리 구조의 공통 아키텍처 기준으로 적용한다.
