MASTER_SPEC_추가갱신_Close_Liquidation_Model_청산모델_설계_2026-07-03

목적
- Position 종료(청산) 절차와 주문 파이프라인의 연결 기준을 정의한다.
- 프로젝트의 기존 정책인 '마감'과 '청산'을 명확히 구분한다.

1. 용어
- 마감: 운영 종료 절차.
- 청산: 보유(Position)를 없애는 거래 절차.

2. 기본 원칙
- 청산 대상은 Position이다.
- Position이 없으면 청산하지 않는다.
- 청산 완료는 마지막 Fill로 확정한다.
- SendOrder 성공은 청산 완료가 아니다.

3. 흐름
Position
→ 청산 결정
→ SELL Order
→ Execution
→ Fill
→ Position 감소
→ holding_qty==0
→ Close History 생성

4. Position 감소 규칙
- 부분체결: holding_qty 부분 감소
- 전량체결: holding_qty=0
- avg_price는 남은 수량 기준 유지
- realized_pnl은 Fill마다 누적

5. Close History 권장 필드
- close_history_id
- position_id
- close_order_id
- close_fill_ids
- reason
- close_type
- requested_at
- completed_at
- realized_pnl

6. 검토관리
자동 정상 처리 금지
- 청산 주문번호 불일치
- 체결 누락
- Position 잔량 불일치
- Kiwoom 잔고와 불일치

7. Recovery
재시작 시
- Position
- Close History
- Fill
- Kiwoom 잔고
를 비교한다.

8. Audit Log
기록
- 청산 시작
- 부분청산
- 청산 완료
- 청산 실패

9. 금지
- Position 없이 청산 완료 처리
- SendOrder만으로 청산 완료
- 서버 확인 없는 자동 종료

10. 최종 원칙
청산은 Fill 기반으로 Position을 종료하는 과정이며,
마감은 운영 절차이다. 두 개념을 혼용하지 않는다.
