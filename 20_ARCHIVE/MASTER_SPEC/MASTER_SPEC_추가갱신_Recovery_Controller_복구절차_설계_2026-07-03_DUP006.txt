MASTER_SPEC_추가갱신_Recovery_Controller_복구절차_설계_2026-07-03

목적
- 프로그램 재시작, 긴급정지 해제, 비정상 종료 후 Runtime 상태를 안전하게 복구하기 위한 Recovery Controller 기준을 정의한다.
- 본 문서는 설계 문서이며 코드 구현을 포함하지 않는다.

1. 기본 원칙
- 서버 상태를 확인하기 전 내부 상태를 정상으로 간주하지 않는다.
- 불명확한 항목은 자동 실행하지 않고 검토관리 대상으로 분류한다.
- Recovery는 주문 실행 기능이 아니라 상태 검증 기능이다.

2. Recovery 시작 조건
- 프로그램 재시작
- 긴급정지 해제
- 운영자 수동 복구
- 비정상 종료 감지

3. 검증 순서
1) Runtime 파일 무결성
2) routine_signals
3) order_queue
4) order_locks(향후)
5) order_executions(향후)
6) real_trade_guard
7) Kiwoom 로그인/계좌
8) 서버 미체결/잔고
9) Position 비교
10) Review Management 이동 여부

4. 확인 대상
- signal_id
- order_id
- execution_id(향후)
- lock_id(향후)
- request_hash(향후)
- kiwoom_order_no(향후)

5. 자동 복구 금지
- SendOrder 재호출
- execution_enabled 자동 true
- operator_confirmed 자동 true
- Lock 자동 재생성
- ORDER_QUEUED 자동 생성

6. 검토관리 이동
다음은 검토관리 우선
- Runtime와 서버 불일치
- 주문번호 매칭 실패
- Lock 불일치
- Position 불일치
- 체결 추적 실패
- Runtime 손상

7. Audit Log
Recovery 시작/종료/판정 결과를 기록한다.

8. 완료 조건
- Runtime와 서버 상태 일치
- 미확정 항목 없음
- 검토관리 대상 분리 완료
- 자동 실행 없음

최종 원칙
Recovery Controller는 '실행'이 아니라 '검증과 복구 판단'만 담당한다.
