MASTER_SPEC 누락보강 97
주제 : 히스토리 기반 PLAN 중심 자동매매 프레임워크 최종 통합 설계 기준

출처 : 작업진행상황대화히스토리_3~8 비교 반영

1. 목적
PLAN 중심 자동매매 프레임워크의 핵심 구조를 하나의 통합 기준으로 정의하여
향후 모든 기능 구현과 구조 개선의 기준으로 사용한다.

2. 통합 설계 원칙
- PLAN을 자동매매의 중심 단위로 사용한다.
- 전략(Routine), 계획(PLAN), 실행(Execution), 관리(Management)를 분리한다.
- 모든 상태는 이벤트 기반으로 전이한다.
- 로그와 상태는 항상 동일성을 유지한다.

3. 통합 아키텍처
① Routine Layer : 신호·정책
② PLAN Layer : 계획·상태
③ Execution Layer : 주문·체결
④ Management Layer : 로그·복구·운영

4. 유지 기준
- 공통 인터페이스 유지
- 공통 상태 머신 유지
- 공통 이벤트 처리 유지
- 공통 로그/복구 유지

5. 확장 기준
- 신규 루틴은 기존 PLAN 구조를 재사용한다.
- 공통 엔진 수정은 최소화한다.
- 정책은 루틴에서, 실행은 엔진에서 처리한다.

6. 검증 기준
□ 계층 분리
□ 상태 일관성
□ 이벤트 일관성
□ 로그 일관성
□ 복구 일관성
□ 기존 루틴 호환성

7. 결론
PLAN 중심 구조는 프로젝트 전체의 최상위 아키텍처이며,
향후 구조 변경은 본 기준과의 호환성을 우선 검토한다.

8. 반영 원칙
본 문서는 히스토리에서 확정된 PLAN 중심 설계 철학을 통합 정리한 기준으로,
MASTER_SPEC 상위 설계 기준으로 유지한다.
