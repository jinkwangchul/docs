주제 : 상태 전이 검증 시나리오 및 운영 판정 사례집 (신규)

※ 본 문서는 기존 01~121과 중복되지 않으며, 실제 프로젝트에서 검증한
운영 시나리오를 기준으로 상태 전이와 운영 판정 기준을 정리한다.

1. 목적
운영 중 발생 가능한 대표 시나리오를 표준화하여 상태 전이의 일관성과
운영 정책의 재현성을 확보한다.

2. 기본 상태
- 감시/대기
- 매수/매도
- 조기마감
- 자동마감
- 청산
- 긴급정지
- 검토관리

3. 대표 시나리오
① 프로그램 최초 시작
② 프로그램 재시작
③ 장전 운영
④ 정규장 운영
⑤ 장후 운영
⑥ 수동운영 + ATS
⑦ 시간정책 변경
⑧ 조기마감 진입
⑨ 청산 완료
⑩ 데이터 불일치
⑪ 주문 실패
⑫ 체결 불일치
⑬ 운영자 수동 개입

4. 상태 전이 규칙
- 이벤트를 통해서만 상태가 변경된다.
- 동일 조건에서는 항상 동일한 결과를 보장한다.
- 상태 전이는 로그에 기록한다.

5. 검토관리 진입 기준
- 복구 실패
- 데이터 불일치
- 반복 오류
- 운영 정책 위반
- 수동 확인 필요

6. 검증 체크리스트
□ 상태 전이 정상
□ UI 표시 일치
□ 로그 기록
□ 예산 일치
□ PLAN 일치
□ 주문/체결 일치

7. 구현 원칙
- 시나리오 기반 테스트를 표준으로 사용한다.
- 신규 기능은 기존 시나리오를 통과해야 한다.
- 정책 변경 시 사례집도 함께 갱신한다.

반영 원칙
본 문서는 상태 전이 검증 시나리오와 운영 판정 사례를 신규 정의한 설계 문서이다.
