MASTER_SPEC_추가갱신_설계검토_체크포인트_Architecture_Review_Checkpoints_2026-07-03

목적
- 새로운 기능을 구현하거나 구조를 변경하기 전에 반드시 확인해야 하는 설계 검토 항목을 정의한다.
- 변경으로 인해 기존 아키텍처가 훼손되는 것을 방지한다.

==================================================
1. 변경 전 확인
==================================================
□ 변경 목적이 명확한가
□ 기존 구조로 해결 가능한가
□ 새 상태값이 정말 필요한가
□ 새 Runtime 파일이 필요한가

==================================================
2. 책임 검토
==================================================
□ 책임이 기존 계층과 충돌하지 않는가
□ Engine/Controller/Boundary 역할을 침범하지 않는가
□ Preview가 상태를 변경하지 않는가

==================================================
3. 데이터 검토
==================================================
□ 기존 ID 체계를 유지하는가
□ Runtime 구조를 깨지 않는가
□ Recovery 가능한 구조인가
□ Audit 추적이 가능한가

==================================================
4. 상태 검토
==================================================
□ State Machine 규칙을 지키는가
□ 허용되지 않은 상태 전이가 없는가
□ execution_enabled 정책을 위반하지 않는가

==================================================
5. 운영 검토
==================================================
□ Review Management 기준을 만족하는가
□ Recovery 정책과 충돌하지 않는가
□ Kiwoom Boundary를 우회하지 않는가

==================================================
6. 테스트 검토
==================================================
□ 단위 테스트 작성 예정인가
□ 회귀 테스트 대상이 정의되었는가
□ 운영 Runtime을 변경하지 않는가

==================================================
7. 문서 검토
==================================================
□ MASTER_SPEC 갱신
□ 작업재개요약 갱신
□ 구현 체크리스트 반영
□ Definition of Done 충족 여부 확인

==================================================
8. 승인 기준
==================================================
아래 중 하나라도 '아니오'이면 구현을 보류한다.

- 책임이 명확한가
- 테스트 가능한가
- Recovery 가능한가
- Audit 가능한가
- Runtime 안정성이 유지되는가
- 실주문 위험이 없는가

최종 원칙
모든 구조 변경은 구현 전에 설계 검토 체크포인트를 통과해야 한다.
