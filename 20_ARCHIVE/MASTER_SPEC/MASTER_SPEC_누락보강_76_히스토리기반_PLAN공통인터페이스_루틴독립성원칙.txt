MASTER_SPEC 누락보강 76
주제 : 히스토리 기반 PLAN 공통 인터페이스 및 루틴 독립성 원칙

출처 : 작업진행상황대화히스토리_3~8 비교 반영

1. 목적
모든 자동매매 루틴이 동일한 PLAN 인터페이스를 사용하면서도
각 루틴은 독립적으로 전략을 정의할 수 있도록 하는 구조 원칙을 정의한다.

2. 기본 철학
- PLAN 인터페이스는 공통이다.
- 전략은 루틴마다 독립적이다.
- 실행 계층은 루틴 종류를 직접 알 필요가 없다.

3. PLAN 공통 인터페이스
- PLAN 생성
- PLAN 시작
- 주문 요청
- 체결 반영
- 상태 갱신
- 종료 처리
- 로그 기록
- 복구 지원

4. 루틴 독립성
각 루틴은 다음만 정의한다.
- 신호 생성
- 진입 정책
- 종료 정책
- 유효 조건
- 재시도 정책

공통 실행 로직은 변경하지 않는다.

5. 구현 원칙
- 신규 루틴 추가 시 주문 엔진 수정은 최소화한다.
- 공통 인터페이스를 유지한다.
- 루틴별 예외 처리는 루틴 내부 정책으로 해결한다.

6. 확장 기준
- BUY/SELL 외 새로운 PLAN 유형도 동일 인터페이스를 따른다.
- 공통 상태명과 생명주기를 유지한다.
- 로그와 복구 형식도 동일 규격을 사용한다.

7. 검증 항목
□ 인터페이스 일관성
□ 루틴 독립성
□ 공통 상태 관리
□ 공통 로그
□ 공통 복구
□ 신규 루틴 확장성

8. 반영 원칙
본 기준은 히스토리에서 확정된 PLAN 기반 구조 설계 철학이며,
향후 모든 자동매매 루틴의 공통 인터페이스 기준으로 적용한다.
