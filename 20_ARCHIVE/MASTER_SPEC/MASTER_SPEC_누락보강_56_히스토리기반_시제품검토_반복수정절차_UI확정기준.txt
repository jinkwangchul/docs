MASTER_SPEC 누락보강 56
주제 : 히스토리 기반 시제품 검토·반복 수정 절차 및 UI 확정 기준

출처 : 작업진행상황대화히스토리_8 비교 반영

1. 목적
UI를 한 번에 확정하지 않고 시제품을 반복 검토하여 최종안을 도출하기 위한
공식 절차를 정의한다.

2. 기본 원칙
- 최초 구현은 시제품으로 간주한다.
- 실제 화면 확인 결과를 우선한다.
- 기능보다 가독성을 함께 검토한다.

3. 반복 절차
① 시제품 구현
② 화면 확인
③ 문제점 기록
④ 부분 수정
⑤ 재확인
⑥ 확정 또는 추가 수정

4. 검토 대상
- 문구 잘림
- 정렬
- 들여쓰기
- 줄간격
- 그룹 구성
- 시선 흐름
- 설정 입력 편의성

5. 수정 원칙
- 한 번에 많은 요소를 변경하지 않는다.
- 변경 후 반드시 화면으로 검증한다.
- 만족스럽지 않으면 이전 방향에 얽매이지 않고 재구성한다.

6. 확정 기준
- 기능 정상
- 화면 가독성 확보
- 항목 간 일관성 유지
- 프로젝트 전체 UI 규칙과 충돌 없음

7. 기록 원칙
- 폐기된 시안도 결정 이유를 남긴다.
- 최종 채택 이유를 함께 기록한다.
- 동일한 시행착오를 반복하지 않는다.

8. 반영 원칙
본 기준은 실제 UI 설계 과정에서 반복 검토를 통해 확정된 운영 절차이며,
향후 모든 루틴 설정 화면 설계의 공통 기준으로 사용한다.
