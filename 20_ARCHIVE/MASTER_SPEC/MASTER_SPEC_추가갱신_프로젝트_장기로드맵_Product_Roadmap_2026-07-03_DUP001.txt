MASTER_SPEC_추가갱신_프로젝트_장기로드맵_Product_Roadmap_2026-07-03

목적
- 프로젝트의 장기 발전 방향과 구현 단계를 시간순이 아니라 기능 성숙도 기준으로 정의한다.

==================================================
1단계 : 기반 아키텍처 (완료 수준)
==================================================
완료
- Signal Pipeline
- Order Pipeline
- Approval
- Policy
- Preflight
- Adapter Preview
- Runtime 기본 구조
- State Machine
- Controller 역할 정의
- Architecture 문서화

==================================================
2단계 : 실주문 준비
==================================================
구현 대상
- hoga / order_type Mapper
- ExecutionController
- Final Execution Guard
- Order Lock
- Request Hash
- Execution Request

완료 조건
- Preview와 실제 요청 일치 검증
- 실주문 미연결 유지

==================================================
3단계 : 실주문 계층
==================================================
구현 대상
- Kiwoom Boundary
- KiwoomOrderExecutor
- ORDER_QUEUED
- ORDER_SENT
- 주문 응답 처리

완료 조건
- 단일 SendOrder 진입점
- 중복 주문 방지
- Runtime 일관성 유지

==================================================
4단계 : 체결 및 보유
==================================================
구현 대상
- Chejan 수신
- Fill Runtime
- Position Runtime
- Close History

완료 조건
- Fill 기반 Position 관리
- 청산 이력 관리

==================================================
5단계 : 운영 자동화
==================================================
구현 대상
- Recovery Runtime
- Review Runtime
- Audit Runtime
- 운영 대시보드
- 관리자 검토 기능

==================================================
6단계 : 고도화
==================================================
후보 기능
- 성능 최적화
- 통계 분석
- 전략 비교
- 백테스트 연계
- 운영 리포트
- 모니터링 강화

==================================================
장기 원칙
==================================================
- 설계를 유지하며 구현을 확장한다.
- Runtime 호환성을 우선한다.
- 실주문보다 안전성을 우선한다.
- 기능 추가보다 구조 일관성을 우선한다.

최종 결론
현재 프로젝트는 기반 아키텍처가 정리된 단계이며,
다음 핵심 목표는 '실주문 준비 계층'의 안정적인 구현이다.
