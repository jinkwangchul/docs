MASTER SPEC v4.0 - FINAL INTEGRATED MASTER SPEC

============================================================
0. SYSTEM OVERVIEW
============================================================
This document is the FINAL MASTER SPECIFICATION v4.0 for MACD trading system.

Architecture is fully frozen and consists of:

- ROUTINE : Judgment Engine
- MAIN    : Execution Engine
- UI      : Interface Layer

============================================================
1. CORE DESIGN PRINCIPLE
============================================================
- Strict separation of judgment and execution
- ROUTINE never executes trades
- MAIN is the only execution authority
- UI only displays and sends requests

============================================================
2. SIGNAL SYSTEM
============================================================
Allowed signals:
- BUY   : entry decision
- SELL  : exit decision
- None  : no action state

STRICT RULES:
- HOLD is prohibited
- No additional signal types
- No partial signals

============================================================
3. ROUTINE (JUDGMENT ENGINE)
============================================================
Responsibilities:
- market analysis
- condition evaluation
- signal generation

Forbidden:
- order execution
- budget control
- account management

Output:
- deterministic signals only
- error => None

============================================================
4. MAIN (EXECUTION ENGINE)
============================================================
Responsibilities:
- order execution
- capital management
- position handling
- risk control
- final decision authority

MAIN is absolute execution authority.

============================================================
5. UI (INTERFACE LAYER)
============================================================
Responsibilities:
- display system state
- receive user input
- forward requests to MAIN

UI has no decision authority.

============================================================
6. RISK & CAPITAL SYSTEM (PART26)
============================================================
- hierarchical capital structure
- strict risk-first priority
- automated risk levels (normal/warn/limit/stop)
- MAIN enforces all constraints

============================================================
7. UI & EXECUTION STRUCTURE (PART27)
============================================================
- UI is display/input only
- event flow: UI → MAIN → ROUTINE → MAIN → UI
- no direct execution path from UI or ROUTINE

============================================================
8. EXCEPTION & EXTENSION (PART28)
============================================================
- all exceptions routed to MAIN
- no auto-recovery in ROUTINE
- system isolation for failures
- extensions must not modify core architecture

============================================================
9. RUNTIME & INTEGRATION (PART29)
============================================================
- MAIN controls runtime state
- full system synchronization required
- single source of truth = MAIN state
- failure isolation enforced

============================================================
10. FINAL DECLARATION (PART30)
============================================================
- system is fully frozen
- no new signal types allowed
- no structural mutation allowed
- MAIN is final authority
- all execution flows converge to MAIN

============================================================
END OF MASTER SPEC v4.0
============================================================
