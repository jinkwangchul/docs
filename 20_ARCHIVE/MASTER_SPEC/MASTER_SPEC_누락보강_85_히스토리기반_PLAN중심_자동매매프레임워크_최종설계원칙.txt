MASTER_SPEC 누락보강 85
주제 : 히스토리 기반 PLAN 중심 자동매매 프레임워크 최종 설계 원칙

출처 : 작업진행상황대화히스토리_3~8 비교 반영

1. 목적
프로젝트 전반에서 채택한 PLAN 중심 자동매매 프레임워크의 최종 설계 원칙을
정리하여 향후 구현과 확장의 최상위 기준으로 사용한다.

2. 최상위 설계 철학
- 모든 자동매매는 PLAN을 중심으로 동작한다.
- 전략은 루틴이 정의하고 실행은 엔진이 담당한다.
- 공통 기능은 프레임워크에, 전략 차이는 루틴에 위치한다.

3. 프레임워크 구성
① Routine Layer
- 신호 생성
- 정책 정의

② PLAN Layer
- 주문 계획
- 상태 관리
- 생명주기 관리

③ Execution Layer
- 주문 실행
- 체결 처리
- 재시도 처리

④ Management Layer
- 로그
- 복구
- 검토관리
- 운영 상태 관리

4. 공통 원칙
- 계층 간 책임을 명확히 분리한다.
- 공통 인터페이스를 유지한다.
- 이벤트 기반 상태 전이를 사용한다.
- 로그와 상태를 항상 동기화한다.

5. 확장 원칙
- 신규 루틴은 기존 프레임워크를 재사용한다.
- 공통 엔진 수정은 최소화한다.
- BUY/SELL 외 새로운 PLAN도 동일 구조를 따른다.

6. 유지보수 원칙
- 정책 변경은 루틴에서 해결한다.
- 실행 계층은 전략과 독립적으로 유지한다.
- 공통 기능은 중복 구현하지 않는다.

7. 검증 기준
□ 계층 분리
□ PLAN 일관성
□ 상태 머신 일관성
□ 이벤트 처리 일관성
□ 로그·복구 일관성
□ 신규 루틴 확장성

8. 반영 원칙
본 기준은 히스토리에서 확정된 PLAN 중심 자동매매 프레임워크의 최종 설계 원칙이며,
향후 프로젝트 전체 아키텍처의 최상위 기준으로 적용한다.
