MASTER_SPEC 누락보강 104
주제 : 테스트 정책 및 검증 절차 통합 기준

출처 : 작업진행상황대화히스토리 3~8 비교 반영

목적
프로젝트 전반의 테스트 철학, 검증 절차, 회귀 테스트 기준을 하나의 문서로 통합한다.

1. 테스트 기본 원칙
- 기능 구현과 테스트를 분리한다.
- 변경 후 반드시 회귀 테스트를 수행한다.
- UI와 로직을 각각 검증한다.
- 테스트 결과는 재현 가능해야 한다.

2. 테스트 분류
- 단위 테스트(Unit)
- 통합 테스트(Integration)
- UI 테스트
- Mock 테스트
- 운영 시나리오 테스트
- 회귀 테스트

3. 검증 절차
① 구현
② 단위 테스트
③ UI 확인
④ 통합 테스트
⑤ 예외 상황 테스트
⑥ 회귀 테스트
⑦ 승인

4. Mock 테스트
- 주문 Mock
- 체결 Mock
- 상태 Mock
- 시간 정책 Mock
- 복구 Mock

5. 예외 검증
- 주문 실패
- 통신 오류
- 부분 체결
- CANCEL
- 재시작
- 복구

6. 회귀 테스트 기준
- 기존 기능 영향 여부 확인
- 상태 전이 확인
- JSON 저장/복원 확인
- UI 표시 확인
- 로그 확인

7. 구현 원칙
- 테스트는 실제 운영 흐름과 동일하게 수행한다.
- 테스트 코드와 운영 코드를 명확히 분리한다.
- 버그 수정 시 동일 시나리오를 회귀 테스트에 추가한다.

반영 원칙
본 문서는 기존 누락보강 131~140 수준의 테스트 정책 및 검증 절차를 통합한 기준 문서이다.
