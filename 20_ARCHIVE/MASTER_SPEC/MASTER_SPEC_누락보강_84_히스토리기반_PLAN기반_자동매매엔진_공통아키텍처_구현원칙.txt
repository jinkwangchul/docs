MASTER_SPEC 누락보강 84
주제 : 히스토리 기반 PLAN 기반 자동매매 엔진의 공통 아키텍처 및 구현 원칙

출처 : 작업진행상황대화히스토리_3~8 비교 반영

1. 목적
PLAN 중심 자동매매 엔진의 공통 아키텍처를 정의하고,
모든 루틴이 동일한 구현 원칙을 따르도록 기준을 확립한다.

2. 핵심 철학
- 전략(Strategy)과 실행(Execution)을 분리한다.
- PLAN은 전략과 실행을 연결하는 표준 계층이다.
- 공통 기능은 엔진에서 제공하고 전략은 루틴이 정의한다.

3. 공통 아키텍처
① Routine Layer
- 신호 생성
- 정책 정의

② PLAN Layer
- 주문 계획
- 상태 관리
- 생명주기 관리

③ Execution Layer
- 주문 전송
- 체결 확인
- 재시도 수행

④ Management Layer
- 로그
- 복구
- 검토관리
- 운영 상태 관리

4. 구현 원칙
- 계층 간 책임을 혼합하지 않는다.
- 동일 기능을 중복 구현하지 않는다.
- 공통 인터페이스를 우선 사용한다.
- 루틴 추가 시 기존 엔진 수정은 최소화한다.

5. 확장 원칙
- 새로운 루틴은 PLAN 인터페이스만 구현한다.
- 엔진은 루틴 종류를 직접 판단하지 않는다.
- 공통 상태와 이벤트 체계를 유지한다.

6. 검증 항목
□ 계층 책임 분리
□ PLAN 일관성
□ 공통 인터페이스 유지
□ 이벤트 처리 일관성
□ 로그/복구 일관성

7. 반영 원칙
본 기준은 히스토리에서 확정된 PLAN 기반 자동매매 엔진의 공통 아키텍처이며,
향후 모든 자동매매 기능 구현의 최상위 설계 기준으로 적용한다.
