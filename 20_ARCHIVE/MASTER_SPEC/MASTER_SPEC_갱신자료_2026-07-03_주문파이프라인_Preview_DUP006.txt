1. 주문 파이프라인 상태 전이 사양

현재 주문 파이프라인은 실주문 전송 전 Preview 단계까지만 구현한다.

상태 전이:

PENDING
  -> APPROVED
  -> BLOCKED

APPROVED
  -> EXECUTABLE
  -> BLOCKED_POLICY

EXECUTABLE
  -> REAL_READY
  -> BLOCKED_REAL

REAL_READY
  -> Adapter Request Preview

주의:
- REAL_READY 이후 현재 단계에서는 ADAPTER_READY 파일 전이를 수행하지 않는다.
- Adapter Request Preview는 메모리 dict 반환만 의미한다.
- SendOrder는 연결하지 않는다.

2. 상태 의미

PENDING
- routine signal에서 생성된 order 후보의 최초 상태.
- 아직 approval 미통과.
- 실주문 불가.

APPROVED
- 후보 자체가 주문 후보로 적합하다고 approval engine이 판정한 상태.
- 실주문 허용 상태가 아니다.
- execution_enabled=false 유지.

BLOCKED
- approval 단계에서 차단된 상태.
- 예: 수량 없음, 예산 없음, candidate_status 미준비.

EXECUTABLE
- operation policy gate를 통과한 상태.
- Real Preflight 전 단계이다.
- 실주문 허용 상태가 아니다.
- execution_enabled=false 유지.

BLOCKED_POLICY
- operation policy gate에서 차단된 상태.

REAL_READY
- real_order_preflight를 통과한 상태.
- 테스트 전용으로 execution_enabled=true order에서만 REAL_READY 파일 반영 검증 가능.
- 현재 운영 자동 흐름에서는 execution_enabled=false 유지로 인해 자동 REAL_READY 승격을 목표로 하지 않는다.
- REAL_READY라도 현재 단계에서는 SendOrder 미연결.

BLOCKED_REAL
- real_order_preflight에서 차단된 상태.
- guard 실패, execution_enabled=false, 계좌 미선택, 로그인 미확인 등.

Adapter Request Preview
- REAL_READY order 1건을 키움 주문 요청 dict로 변환한 메모리 preview.
- order_queue.json status 변경 없음.
- send_order_stub 미호출.
- SendOrder 미호출.

3. 핵심 파일별 책임

order_queue.py
- routine signal을 order 후보로 변환한다.
- 최초 status=PENDING.
- execution_enabled=false 고정.

order_approval_engine.py
- PENDING order만 approval 대상.
- 통과 시 APPROVED.
- 실패 시 BLOCKED.
- execution_enabled=false 유지.

operation_policy_gate.py
- APPROVED order만 정책 gate 대상.
- 통과 시 EXECUTABLE.
- 실패 시 BLOCKED_POLICY.
- execution_enabled=false 유지.
- 단건 helper:
  apply_operation_policy_gate_for_order(order_id, queue_path=None)

real_order_preflight.py
- EXECUTABLE order만 real preflight 대상.
- 통과 시 REAL_READY.
- 실패 시 BLOCKED_REAL.
- guard_path 없음 또는 guard 파일 없음이면 기본 guard 자동 생성 금지.
- 단건 helper:
  apply_real_order_preflight_for_order(order_id, queue_path=None, guard_path=None)

kiwoom_order_adapter.py
- build_kiwoom_order_request(order, guard):
  order dict와 guard dict를 키움 주문 요청 preview 형태로 변환한다.
- send_order_stub(request):
  실제 SendOrder 대신 stub 결과를 반환한다. 현재 preview helper에서는 호출하지 않는다.
- build_kiwoom_order_request_preview_for_order(order_id, queue_path=None, guard_path=None):
  REAL_READY order 1건만 request_preview로 변환한다.
  파일 저장 없음.
  status 변경 없음.
  send_order_stub 미호출.
  SendOrder 미호출.

real_order_executor_stub.py
- REAL_READY order를 읽어 build_kiwoom_order_request()와 send_order_stub()을 호출할 수 있는 stub.
- 실행 시 order_queue.json을 ADAPTER_READY로 변경한다.
- 현재 자동 연결 금지.

order_executor.py
- 현재 queue executor가 아니다.
- DryRunOrderExecutor는 order_manager 경로의 dry-run callable.
- KiwoomOrderExecutor는 NotImplementedError 상태.
- 실제 SendOrder 미구현.

routine_signal_consumer.py
- PENDING routine signal을 dry-run 소비한다.
- mark_previewed=True일 때 routine signal status를 PREVIEWED/BLOCKED/ERROR로 변경할 수 있다.
- write_order_queue=True, apply_approval=True 옵션에서만 order_queue 후보 생성 및 approval 반영.
- SendOrder, Preflight, Executor 미연결.

gui_auto_trade_timer.py
- signal_probe_only=True 종목이 있을 때만 probe 이후 consumer 제한 실행.
- 연결 범위는 order_queue 후보 생성 및 approval까지.
- Real Preflight, Adapter, Executor, SendOrder 미연결.

gui_auto_trade_setting_window.py
- 주문후보검증 버튼은 summary 표시용.
- 기본 동작은 dry-run preview.
- 실주문 연결 없음.

9. 다음 단계 위험 지점

1) hoga/order_type
- 현재 request_preview는 hoga="UNDECIDED"이다.
- 실제 주문 전송 전에 주문유형, 호가구분, 가격 정책을 확정해야 한다.

2) execution_enabled
- 현재 자동 흐름은 false 유지가 안전장치이다.
- true 전환 정책 없이 SendOrder 연결 금지.

3) operator_confirmed
- 수동 확인 없이는 실주문 단계 진입 금지.

4) 중복 실행 방지
- order_id 기준으로 이미 처리된 주문을 재실행하지 않는 잠금 정책 필요.

5) queue 상태 충돌
- ADAPTER_READY는 현재 사양상 preview 이후 자동 상태가 아니다.
- 실제 adapter 단계로 승격하기 전 별도 상태 전이 정책이 필요하다.

10. 다음 구현 가능 최소 범위

1) Adapter Request Preview 결과를 GUI 또는 CLI에서 표시만 한다.
