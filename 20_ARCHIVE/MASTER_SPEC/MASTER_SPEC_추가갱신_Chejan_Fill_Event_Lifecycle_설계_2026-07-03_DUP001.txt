MASTER_SPEC_추가갱신_Chejan_Fill_Event_Lifecycle_설계_2026-07-03

목적
- Kiwoom 체결(Chejan) 이벤트를 내부 주문 파이프라인과 연결하는 기준을 정의한다.
- 체결 이벤트는 주문을 생성하지 않으며, 이미 생성된 주문의 상태를 갱신하는 역할만 수행한다.

1. 기본 원칙
- Chejan은 주문 판단을 하지 않는다.
- Chejan은 새로운 Order를 생성하지 않는다.
- 체결 정보는 기존 execution/order와 매핑되어야 한다.

2. 연결 흐름

Kiwoom Chejan
    ↓
Kiwoom Boundary
    ↓
FillEventController
    ↓
Execution
    ↓
Order
    ↓
Position
    ↓
Audit Log
    ↓
Review Management(필요 시)

3. 필수 매핑 키
- kiwoom_order_no
- execution_id
- order_id
- source_signal_id
- code

4. 체결 상태 후보
- 접수
- 확인
- 부분체결
- 전량체결
- 취소
- 거부
- 정정
- 정정완료

상태값 추가는 추후 별도 승인 후 구현한다.

5. Position 갱신 원칙
- Position은 Fill 결과로만 변경한다.
- SendOrder 성공만으로 Position을 변경하지 않는다.
- 부분체결도 Fill 단위로 누적한다.

6. 검토관리 이동
다음 경우 자동 정상 처리 금지
- 주문번호 매칭 실패
- Fill 중복
- 체결수량 불일치
- Position 불일치
- 서버와 내부 데이터 불일치

7. Audit Log
기록 대상
- Chejan 수신
- Fill 생성
- Position 변경
- 체결 오류
- 검토관리 이동

8. Recovery
재시작 시
- Kiwoom 주문번호
- Fill
- Position
을 함께 비교한다.

9. 금지
- Chejan에서 전략 판단
- Chejan에서 SendOrder
- Chejan에서 Approval/Policy
- Chejan에서 execution_enabled 변경

최종 원칙
Chejan/Fill 계층은 '실제 발생한 체결 사실'만 반영하며,
주문 생성이나 전략 판단에는 관여하지 않는다.
