MASTER_SPEC 누락보강 24
주제 : 매도설정 UI 변경 이력 및 최종 확정 과정

1. 목적
매도설정 UI가 최종 프로토타입 구조에 도달하기까지의 변경 이력과
채택·보류·폐기 과정을 기록한다.

2. 초기 구조
- 기능 중심의 단순 설정 나열 방식.
- 항목 간 실행 관계를 파악하기 어려웠다.

3. 검토된 구조
- 기존 박스형
- 카드형
- 시나리오 중심
- 수행 단계 중심

4. 폐기된 구조
① 카드형 UI
- 공간 활용 저하
- 설정 요약 영역 부족
- 시선 분산

② 설정 나열형
- 실행 순서 표현 부족
- 확장성 저하

5. 최종 채택 구조
상단
- 신호검출조건
- 매도방식지정(A/B/C)

시나리오 내부
- 수행1 : 최초 매도방식
- 수행2 : 후속매도반복설정
- 수행3 : 미체결/가격비교
- 수행4 : 반복이탈조건
- 수행5 : 매도완료정책

6. UI 확정 사항
- 소제목 좌측 정렬
- 설정은 반칸 들여쓰기
- 입력 컨트롤 높이 통일
- 콤보박스 폭 확대
- 줄간격 통일
- 흰색 배경 제거
- 그림자 효과 제거

7. 연계 규칙
- 수행2 시간 반복 사용 시 수행4 제한시간 비활성
- 수행4 사용 여부에 따라 수행5 표시 자동 변경
- 공통 상태제어 함수 사용

8. 공통 설계 철학
- 실행 순서와 화면 순서를 동일하게 유지
- 하나의 수행은 하나의 목적만 담당
- UI와 엔진을 직접 연결하지 않는다.

9. 프로토타입 상태
- 구조는 확정 단계
- 로직 연결은 후속 단계
- 디자인은 일부 보완 가능

10. 향후 과제
- 엔진 매핑
- JSON 저장 구조
- 시나리오 복제
- 최종 UI 다듬기
- 운영 단계 전환
