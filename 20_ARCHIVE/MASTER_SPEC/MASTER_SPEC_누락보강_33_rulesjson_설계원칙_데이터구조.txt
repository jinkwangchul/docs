MASTER_SPEC 누락보강 33
주제 : JSON(rules.json) 설계 원칙 및 데이터 구조

1. 목적
루틴 설정을 UI와 엔진으로부터 독립된 데이터 구조로 관리하기 위한
rules.json 설계 원칙을 정의한다.

2. 기본 원칙
- rules.json은 정책 데이터만 저장한다.
- UI 위젯 정보는 저장하지 않는다.
- 엔진이 직접 사용할 수 있는 구조를 유지한다.

3. 역할
- 루틴 정책 저장
- 기본값 제공
- 엔진 입력 데이터 제공
- 버전 호환 기준 제공

4. 포함 대상
- 신호검출조건
- 적용필터
- 매수 정책
- 매도 정책
- 미체결 정책
- 완료 정책
- 공통 옵션

5. 제외 대상
- QWidget 정보
- 화면 좌표
- 색상 및 UI 스타일
- 런타임 객체
- 임시 계산값

6. 구조 원칙
- 계층형 JSON 사용
- 의미 단위로 그룹화
- 동일 정책은 하나의 위치에만 저장
- 중복 키 생성 금지

7. 버전 관리
- schema_version 유지
- 신규 키 추가는 하위 호환 우선
- 삭제보다 비활성 또는 변환 정책 우선

8. UI 매핑
UI → 설정 데이터 → rules.json → 엔진

UI는 JSON을 직접 해석하지 않고
공통 매핑 계층을 통해 변환한다.

9. 검증 항목
□ JSON 생성
□ JSON 로드
□ 키 누락 여부
□ 기본값 적용
□ 엔진 입력 일치
□ 버전 호환성

10. 향후 보강
- JSON Schema 정의
- 키 명명 규칙
- 자동 검증
- 마이그레이션 정책
