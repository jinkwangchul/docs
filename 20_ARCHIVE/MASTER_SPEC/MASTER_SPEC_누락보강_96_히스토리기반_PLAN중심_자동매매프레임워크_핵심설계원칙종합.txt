MASTER_SPEC 누락보강 96
주제 : 히스토리 기반 PLAN 중심 자동매매 프레임워크 핵심 설계 원칙 종합

출처 : 작업진행상황대화히스토리_3~8 비교 반영

1. 목적
PLAN 중심 자동매매 프레임워크의 핵심 설계 원칙을 하나의 기준으로 정리하여
향후 기능 추가와 구조 개선 시 최우선 참조 문서로 사용한다.

2. 핵심 설계 원칙
- 모든 자동매매는 PLAN 단위로 관리한다.
- 전략과 실행을 명확히 분리한다.
- 상태는 이벤트 기반으로만 변경한다.
- 로그와 상태는 항상 동일한 정보를 유지한다.

3. 공통 구조
① Routine Layer
② PLAN Layer
③ Execution Layer
④ Management Layer

각 계층은 자신의 책임만 수행하며 다른 계층의 역할을 침범하지 않는다.

4. 공통 유지 기준
- PLAN 생명주기 유지
- 공통 상태 머신 유지
- 공통 이벤트 처리 유지
- 공통 인터페이스 유지
- 공통 로그 및 복구 체계 유지

5. 확장 기준
- 신규 루틴은 기존 PLAN 구조를 그대로 사용한다.
- 신규 기능은 공통 구조를 변경하지 않는 범위에서 추가한다.
- 공통 엔진은 전략에 의존하지 않는다.

6. 구현 기준
- 구조보다 정책을 변경한다.
- 공통 기능의 중복 구현을 금지한다.
- 변경 시 구현과 문서를 동시에 갱신한다.

7. 최종 검증
□ 구조 일관성
□ 상태 일관성
□ 이벤트 일관성
□ 로그 일관성
□ 복구 일관성
□ 장기 확장성

8. 반영 원칙
본 기준은 히스토리에서 확정된 PLAN 중심 자동매매 프레임워크의 핵심 설계 원칙을
종합한 문서이며 향후 프로젝트 전체의 상위 설계 기준으로 적용한다.
