MASTER_SPEC 누락보강 65
주제 : 히스토리 기반 루틴과 메인의 책임 분리 - BUY PLAN 운영 기준

출처 : 작업진행상황대화히스토리_3~8 비교 반영

1. 목적
BUY PLAN 처리 과정에서 루틴과 메인 프로그램의 책임을 명확히 분리하여
구조적 일관성을 유지한다.

2. 설계 원칙
- 루틴은 '무엇을 할지'를 결정한다.
- 메인은 '어떻게 수행할지'를 담당한다.
- 동일 기능을 양쪽에서 중복 판단하지 않는다.

3. 루틴의 책임
- BUY 신호 생성
- BUY PLAN 생성 조건
- 목표 금액/수량 정의
- 재매수 허용 여부
- 유효 봉, 유효 시간, 가격 조건
- 완료 및 종료 정책 정의

4. 메인의 책임
- 주문 실행
- 체결 확인
- 잔여 목표 계산
- BUY PLAN 상태 관리
- 주문 재시도 실행
- 상태 저장 및 복구

5. 공통 처리 흐름
① 루틴이 BUY PLAN 생성
② 메인이 주문 수행
③ 메인이 체결 상태 갱신
④ 루틴 정책에 따라 계속/종료 판단
⑤ 완료 또는 미완성 상태 반영

6. 구현 원칙
- 루틴은 실행 로직을 직접 수행하지 않는다.
- 메인은 전략을 임의로 변경하지 않는다.
- 정책과 실행의 경계를 유지한다.

7. 검증 항목
□ 루틴은 정책만 결정
□ 메인은 실행만 담당
□ 중복 판정 없음
□ 상태 일관성 유지
□ BUY PLAN 정상 종료

8. 반영 원칙
본 기준은 히스토리에서 확정된 역할 분리 철학이며,
향후 모든 루틴과 메인 엔진 구현의 공통 기준으로 적용한다.
