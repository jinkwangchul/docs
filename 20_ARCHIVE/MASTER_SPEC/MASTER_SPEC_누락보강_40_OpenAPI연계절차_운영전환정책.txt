MASTER_SPEC 누락보강 40
주제 : OpenAPI 연계 절차 및 운영 전환 정책

1. 목적
프로토타입 UI와 루틴 엔진을 실제 OpenAPI 환경으로 안전하게 연결하기 위한
운영 전환 절차와 정책을 정의한다.

2. 운영 전환 원칙
- UI 구조가 확정된 후 OpenAPI를 연계한다.
- 엔진 검증 없이 실주문을 허용하지 않는다.
- 운영 단계는 테스트 단계를 모두 통과한 후 시작한다.

3. 연계 순서
① UI 구조 확정
② 설정 저장 구조 확정
③ 루틴 엔진 검증
④ 메인 엔진 검증
⑤ 모의 데이터 테스트
⑥ OpenAPI 연결
⑦ 모의 주문 테스트
⑧ 실주문 테스트
⑨ 운영 전환

4. OpenAPI 역할
- 시세 수신
- 주문 요청
- 체결 이벤트
- 계좌 정보
- 서버 상태 확인

5. 운영 전환 체크리스트
□ UI 구조 확정
□ 상태 동기화 완료
□ JSON 저장/복원 검증
□ 루틴 엔진 검증
□ 메인 엔진 검증
□ 예외 처리 검증
□ 로그 확인
□ 복구 절차 확인

6. 실운영 원칙
- 신규 기능은 테스트 후 운영 반영
- 운영 중 구조 변경 최소화
- 장애 발생 시 안전 정지 우선
- 데이터 무결성 유지

7. 장애 대응
- OpenAPI 연결 실패
- 주문 오류
- 체결 불일치
- 서버 상태 이상
- 재시작 복구
모든 상황은 공통 복구 정책을 따른다.

8. 문서 관리
- 운영 단계 변경 시 MASTER_SPEC 갱신
- 변경 이력 기록
- 운영 정책과 구현 정책을 분리 관리

9. 향후 보강
- 실시간 이벤트 처리
- 운영 로그 분석
- 자동 장애 감지
- 운영 체크리스트 고도화

10. 결론
OpenAPI 연계는 프로젝트의 최종 단계이며,
모든 구조와 정책이 안정화된 이후에만 운영 환경으로 전환한다.
