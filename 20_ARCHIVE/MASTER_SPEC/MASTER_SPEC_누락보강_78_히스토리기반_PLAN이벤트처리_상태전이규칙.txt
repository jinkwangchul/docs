MASTER_SPEC 누락보강 78
주제 : 히스토리 기반 PLAN 이벤트 처리 및 상태 전이 규칙

출처 : 작업진행상황대화히스토리_3~8 비교 반영

1. 목적
PLAN(BUY/SELL)의 상태 전이가 이벤트 기반으로만 수행되도록
공통 처리 규칙을 정의한다.

2. 기본 원칙
- 상태는 이벤트에 의해 변경된다.
- 이벤트 없이 상태를 직접 변경하지 않는다.
- 하나의 이벤트는 하나의 상태 전이만 수행한다.

3. 주요 이벤트
- 신호 생성
- PLAN 생성
- 주문 요청
- 주문 접수
- 부분 체결
- 전체 체결
- 재시도
- CANCEL
- 유효조건 종료
- 운영 종료

4. 이벤트 처리 순서
① 이벤트 발생
② 현재 상태 확인
③ 전이 가능 여부 검증
④ 상태 전이 수행
⑤ 로그 기록
⑥ 후속 이벤트 대기

5. 전이 규칙
- 허용되지 않은 상태 전이는 거부한다.
- 종료 상태에서는 신규 이벤트를 처리하지 않는다.
- 동일 이벤트의 중복 처리를 방지한다.

6. 구현 원칙
- 이벤트 처리와 상태 변경은 원자적으로 수행한다.
- 상태 변경 후 즉시 로그와 내부 상태를 동기화한다.
- 예외 발생 시 이전 상태를 보존한다.

7. 검증 항목
□ 이벤트 중복 방지
□ 허용 전이만 수행
□ 종료 상태 보호
□ 로그 동기화
□ 상태 복원 일치

8. 반영 원칙
본 기준은 히스토리에서 확정된 PLAN 이벤트 기반 처리 철학이며,
향후 모든 자동매매 루틴의 공통 상태 전이 기준으로 적용한다.
