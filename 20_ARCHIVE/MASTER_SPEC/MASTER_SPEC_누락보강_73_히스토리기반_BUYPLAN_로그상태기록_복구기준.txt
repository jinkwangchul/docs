MASTER_SPEC 누락보강 73
주제 : 히스토리 기반 BUY PLAN 로그·상태기록 및 복구 기준

출처 : 작업진행상황대화히스토리_3~8 비교 반영

1. 목적
BUY PLAN의 전 과정에서 상태 변경 이력과 로그를 일관되게 기록하고,
프로그램 재시작이나 복구 상황에서도 동일한 상태를 재현하기 위한 기준을 정의한다.

2. 기본 원칙
- BUY PLAN의 모든 주요 상태 변화는 기록한다.
- 로그와 내부 상태는 서로 일치해야 한다.
- 복구 시 기록을 기준으로 상태를 재구성한다.

3. 기록 대상
- BUY PLAN 생성
- 주문 요청
- 체결 결과
- 부분 체결
- 재매수 수행
- CANCEL 처리
- 완료
- 미완성
- 실패
- 종료

4. 복구 기준
프로그램 재시작 또는 복구 시에는
저장된 BUY PLAN 상태와 주문 정보를 바탕으로 현재 상태를 재구성한다.

5. 역할 분리
루틴
- 정책 및 판정 근거 제공

메인
- 상태 저장
- 로그 기록
- 상태 복원
- 복구 처리

6. 구현 원칙
- 상태 변경과 로그 기록은 동일 이벤트에서 수행한다.
- 기록 누락으로 상태 불일치가 발생하지 않도록 한다.
- 복구 후 동일 BUY PLAN을 중복 생성하지 않는다.

7. 검증 항목
□ 생성 기록
□ 체결 기록
□ 재매수 기록
□ CANCEL 기록
□ 종료 기록
□ 재시작 복구
□ 상태 일치

8. 반영 원칙
본 기준은 히스토리에서 확정된 BUY PLAN 상태기록 및 복구 철학을 기반으로 하며,
향후 모든 루틴의 상태 관리와 복구 기준으로 적용한다.
