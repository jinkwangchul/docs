9.  AI 잘못 및 재발방지 반영

9.1 AI 잘못

다음 행위는 AI 잘못으로 기록한다.

-   사용자 확정 없는 HOLD 개념 생성
-   비신호를 HOLD라는 신호로 승격
-   코드, 테스트, 문서에 BUY/SELL/HOLD 구조 반영
-   CANCEL의 기존 논의 위치를 즉시 파악하지 못함
-   현재 코드 상태와 과거 설계 철학을 혼동
-   수익률 매도 구현을 다음 작업으로 단정
-   확정/추정/미확정을 분리하지 않고 말함
-   사용자 승인 전 구현 방향을 앞서 제시

9.2 재발방지 원칙

향후 AI는 다음 원칙을 반드시 지킨다.

-   문서에 없는 신호 생성 금지
-   문서에 없는 상태값 생성 금지
-   문서에 없는 엔진 생성 금지
-   문서에 없는 정책 생성 금지
-   문서에 없는 용어 생성 금지
-   구현 전 반드시 방향 확인
-   확정 / 구현 / 추정 / 미확정 분리
-   현재 코드 상태와 설계 철학 분리
-   사용자에게 물어야 할 지점에서 임의 결론 금지
-   패치 전 관련 파일 실제 확인
-   테스트 통과 전 완료 선언 금지

원칙 종합

목적 프로젝트 전체를 관통하는 아키텍처, 운영 철학, 구현 원칙을 하나의
기준으로 정리하여 향후 모든 개발과 유지보수의 최상위 참조 문서로

1.  핵심 철학

-   전략과 실행을 분리한다.
-   PLAN 중심 구조를 유지한다.
-   공통 기능은 재사용하고 중복 구현을 지양한다.
-   운영 안정성을 기능 추가보다 우선한다.

2.  아키텍처 원칙

-   Routine Layer : 전략 및 신호
-   PLAN Layer : 계획 및 상태
-   Execution Layer : 주문 및 체결
-   Management Layer : 로그, 복구, 운영 관리
-   UI Layer : 사용자 표시 및 설정

3.  운영 원칙

-   이벤트 기반 상태 전이

-   상태와 로그의 일관성 유지

-   예외 발생 시 복구 우선

-   자동 처리 불가 상황은 검토관리 연계

-   계층 간 책임 분리

-   하위
