MASTER_SPEC 누락보강 09
주제 : 루틴 엔진 연계 및 UI-엔진 매핑 원칙

1. 목적
- 루틴 설정 UI와 실제 엔진의 역할을 명확히 분리한다.
- UI는 정책을 정의하고, 엔진은 정책을 실행한다.

2. 역할 분리
UI
- 사용자 설정 입력
- 정책 구성
- 활성/비활성 관리
- 저장 대상 생성

루틴 엔진
- BUY/SELL/CANCEL 신호 판단
- 조건 평가
- 실행 정책 제안

메인 엔진
- 주문 실행
- 주문취소
- 체결 관리
- 자금 관리
- 상태 관리

3. UI → 엔진 매핑
신호검출조건 → 조건엔진
적용필터 → 필터엔진
매수/매도방식 → 주문정책
미체결정책 → 주문취소 정책
완료정책 → 후속 처리 정책

4. 구현 원칙
- UI는 엔진 내부를 직접 제어하지 않는다.
- 엔진은 UI 위젯을 직접 참조하지 않는다.
- 설정값만 전달한다.

5. 설정 저장
- UI 객체를 저장하지 않는다.
- 설정 데이터만 저장한다.
- 공통 데이터 구조를 사용한다.

6. 엔진 연결 순서
① UI 구조 확정
② 저장 구조 확정
③ 로드 구조 확정
④ 엔진 매핑
⑤ 검증
⑥ 실주문 연계

7. 금지사항
- UI에서 직접 주문 실행
- UI에서 OpenAPI 호출
- UI와 엔진의 상호 직접 참조
- 엔진에서 QWidget 접근

8. 검증 항목
- UI와 저장 데이터 일치
- 저장 데이터와 엔진 입력 일치
- 엔진 결과와 UI 표시 일치

9. 향후 보강
- UI-JSON 매핑표
- JSON-엔진 매핑표
- 엔진 상태전이
- 정책별 실행 흐름도

10. 결론
UI, 저장구조, 엔진은 서로 독립성을 유지하며
데이터 구조를 통해서만 연결하는 것을 기본 원칙으로 한다.
