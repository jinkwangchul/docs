주제 : 파일 시스템(Storage) 관리 체계 (신규)

※ 본 문서는 기존 01~137과 중복되지 않으며 프로젝트에서 사용하는 파일 저장 구조와
Storage 관리 원칙을 정의한다.

1. 목적
프로젝트의 모든 파일을 일관된 규칙으로 관리하여 유지보수성과 데이터 안전성을 확보한다.

2. 관리 대상
- 설정 파일
- Runtime 파일
- 로그 파일
- 루틴 패키지
- 종목 데이터
- 백업 파일
- 테스트 데이터
- 문서

3. 저장 구조
① Config
② Runtime
③ Stocks
④ Routines
⑤ Logs
⑥ Backup
⑦ Docs
⑧ Temp

4. 파일 정책
- 목적별 디렉터리 분리
- 파일명 규칙 통일
- 중복 저장 금지
- 임시 파일 자동 정리

5. 저장 정책
- 중요 데이터 즉시 저장
- Runtime 주기 저장
- 로그 Append 방식
- 백업 세대 관리

6. 무결성
- 파일 존재 확인
- 손상 검사
- 참조 관계 확인
- 버전 호환성 확인
- 백업 검증

7. 장애 대응
- 손상 파일 격리
- 자동 백업 복원
- 복구 실패 기록
- 검토관리 연계

8. 향후 확장
- 압축 백업
- 암호화 저장
- 클라우드 Storage
- 증분 백업

9. 구현 원칙
- Storage 계층은 업무 로직과 분리한다.
- 동일 데이터는 단일 저장 위치를 원칙으로 한다.
- 저장 경로는 Configuration을 통해 관리한다.

반영 원칙
본 문서는 파일 시스템(Storage) 관리 체계를 신규 정의한 설계 문서이다.
