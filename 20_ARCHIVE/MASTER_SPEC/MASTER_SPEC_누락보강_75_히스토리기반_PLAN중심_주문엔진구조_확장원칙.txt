MASTER_SPEC 누락보강 75
주제 : 히스토리 기반 PLAN 중심 주문 엔진 구조 및 확장 원칙

출처 : 작업진행상황대화히스토리_3~8 비교 반영

1. 목적
주문 엔진을 BUY/SELL 개별 기능 중심이 아니라 PLAN 중심 구조로 설계하기 위한
공통 원칙을 정의한다.

2. 기본 철학
- 주문 엔진은 PLAN을 실행하는 공통 실행 계층이다.
- BUY PLAN과 SELL PLAN은 동일한 실행 구조를 공유한다.
- 전략은 루틴이 정의하고, 실행은 주문 엔진이 담당한다.

3. 공통 처리 흐름
① PLAN 생성
② 주문 요청 생성
③ 주문 전송
④ 체결 감시
⑤ 상태 갱신
⑥ PLAN 종료

4. 역할 구분
루틴
- 전략 정의
- 신호 생성
- 정책 제공

주문 엔진
- 주문 생성
- 주문 실행
- 체결 확인
- PLAN 상태 반영

5. 확장 원칙
- 새로운 루틴이 추가되어도 주문 엔진은 변경을 최소화한다.
- PLAN 인터페이스를 공통으로 유지한다.
- 실행 로직은 전략에 종속되지 않는다.

6. 구현 원칙
- BUY와 SELL을 별도의 엔진으로 분리하지 않는다.
- 공통 상태 관리와 공통 실행 절차를 사용한다.
- 로그와 복구 체계도 동일한 인터페이스를 따른다.

7. 검증 항목
□ PLAN 생성
□ 주문 실행
□ 체결 처리
□ 상태 전이
□ 종료 처리
□ 복구 처리

8. 반영 원칙
본 기준은 히스토리에서 확정된 PLAN 중심 주문 엔진 설계 철학을 기반으로 하며,
향후 모든 자동매매 루틴의 공통 실행 구조로 적용한다.
