아키텍처 (신규)

※ 본 문서는 기존 01~110의 재통합이 아니라, 아직 독립적으로 정리되지 않은

-   TR 관리자

3.  로그인 정책

-   프로그램 시작 시 로그인 확인
-   서버 연결 상태 감시

4.  실시간 처리

-   종목 등록/해제
-   이벤트 분배
-   중복 등록 방지

5.  TR 처리

-   요청 큐
-   응답 대기
-   연속조회
-   요청 제한 관리
-   실패 재시도 정책

6.  주문 처리

-   주문 요청 표준 인터페이스
-   주문번호 관리
-   정정/취소 처리
-   주문 상태 추적

7.  체결 처리

-   접수
-   확인
-   부분체결
-   전체체결
-   미체결
-   취소
-   내부 PLAN 상태와 동기화

8.  이벤트 브로커 OpenAPI 이벤트를 직접 루틴으로 전달하지 않고 공통
    이벤트 브로커를 통해 PLAN 엔진 → 운영엔진 → UI로 전달한다.

9.  장애 대응

-   서버 끊김
-   이벤트 누락
-   주문 응답 지연
-   체결 불일치
-   재로그인
-   상태 복구

10. 로그

-   로그인
-   TR
-   실시간
-   주문
-   체결
-   오류
-   복구

11. 구현 원칙

-   OpenAPI 의존성은 Adapter 계층으로 제한한다.
-   루틴은 OpenAPI 객체를 직접 사용하지 않는다.
-   이벤트는 공통 인터페이스를 통해 전달한다.

※ 본 문서는 기존 01~111과 중복되지 않는 종목관리 엔진의 내부 설계를 신규

    표준화한다.

2.  종목 생명주기 ① 등록 대기 ② 등록 완료 ③ 루틴 지정 ④ 운영 준비 ⑤ 운영
    중 ⑥ 일시정지 ⑦ 검토관리 ⑧ 복귀 ⑨ 운영 종료 ⑩ 보관/삭제

-   PLAN 상태
-   예산 상태
-   주문 상태
-   보유 상태
-   로그 참조

4.  종목 상태 전이 상태 변경은 이벤트 기반으로만 수행하며, 운영 엔진이
    단일 관리 주체가 된다.

5.  종목 등록 정책

-   루틴 미지정 허용 여부 정책
-   자동 초기화
-   설정 검증 후 활성화

6.  검토관리 연계 다음 상황은 검토관리 대상으로 전환할 수 있다.

-   상태 불일치
-   주문 이상
-   체결 이상
-   복구 실패
-   운영 정책 위반

7.  복구 정책

-   재시작 시 종목 상태 복원
-   PLAN 및 주문 상태 재동기화
-   운영 가능 여부 재판정

8.  UI 연계

-   관제창
-   종목 등록창
-   검토관리창
-   상태 표시
-   색상 정책

9.  구현 원칙

-   종목은 독립 객체로 관리한다.
-   루틴과 종목을 직접 결합하지 않는다.
-   운영 상태는 공통 인터페이스로 조회한다.

10. 향후 확장

-   다중 계좌
-   다중 시장
-   종목 그룹
-   우선순위 운영

문서이다.

1.  목적 자동매매 전반의 자금 흐름을 표준화하고 전체·루틴·종목 예산을
    일관되게 관리한다.

    예산

상위 예산은 하위 예산의 한계를 결정하지만, 하위 예산이 상위 정책을
변경하지 않는다.

3.  예산 객체

-   총예산
-   사용예산
-   예약예산
-   가용예산
-   손익반영예산
-   제한상태

4.  자금 흐름 예산 확보 → 루틴 배정 → 종목 배정 → PLAN 예약 → 주문 사용
    → 체결 반영 → 예산 반환 또는 유지

5.  예약 예산

-   주문 전 예약
-   체결 후 사용예산 전환
-   취소 시 예약 반환
-   부분체결은 잔여 예약 유지

6.  충돌 방지

-   동일 예산 중복 예약 금지
-   PLAN 간 예산 경쟁 방지
-   종목 한도 우선 적용
-   루틴 한도 초과 방지

7.  완충영역

-   완충 비율 관리
-   경고 단계
-   자동 조기마감 연계
-   운영자 알림 연계

8.  운영 정책

-   예산 부족 시 신규 PLAN 생성 제한
-   예산 변경 이력 기록
-   재시작 시 예약예산 재검증
-   예산 불일치 시 검토관리 연계

9.  향후 확장

-   계좌별 예산
-   시장별 예산
-   통화별 예산
-   전략별 예산 풀

10. 구현 원칙

-   예산 계산은 단일 엔진에서 수행한다.
-   루틴은 예산을 직접 수정하지 않는다.
-   모든 주문은 예산 검증 이후에만 생성한다.
