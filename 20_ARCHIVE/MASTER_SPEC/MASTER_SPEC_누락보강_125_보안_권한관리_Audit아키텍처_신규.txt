주제 : 보안·권한관리·감사(Audit) 아키텍처 (신규)

※ 본 문서는 기존 01~124와 중복되지 않으며 프로젝트의 보안, 권한관리,
감사(Audit) 체계를 정의한다.

1. 목적
운영 환경의 안전성을 확보하고 모든 중요 작업을 추적 가능한 형태로 관리한다.

2. 보호 대상
- 계좌 정보
- API 연결 정보
- 운영 설정
- 루틴 설정
- 종목 설정
- 예산 정보
- 로그 데이터

3. 권한 계층
① 시스템 관리자
② 운영 관리자
③ 개발자
④ 읽기 전용 사용자

4. 권한 정책
- 최소 권한 원칙
- 기능별 접근 제어
- 중요 설정 변경 제한
- 운영 중 위험 기능 확인 절차

5. 감사(Audit) 대상
- 로그인/로그아웃
- 설정 변경
- 루틴 등록 및 삭제
- 종목 등록 및 삭제
- 예산 변경
- 운영 시작/중지
- 긴급정지
- 검토관리 복귀

6. 감사 기록
- 수행 시각
- 수행 주체
- 대상 기능
- 변경 전 상태
- 변경 후 상태
- 결과
- 사유

7. 이상 행위 감지
- 반복 실패
- 비정상 설정 변경
- 권한 없는 접근
- 동일 작업 반복
- 예상치 못한 운영 중단

8. 복구 지원
- 설정 변경 이력 복원
- Audit 기반 원인 분석
- 변경 시점 비교
- 운영 이력 추적

9. 향후 확장
- 전자서명
- 다중 승인
- 원격 감사
- 변경 비교 리포트
- 보안 정책 자동 점검

10. 구현 원칙
- 모든 중요 변경은 Audit 로그를 남긴다.
- Audit 데이터는 일반 로그와 분리 관리한다.
- 권한 정책은 운영 정책보다 우선 적용한다.

반영 원칙
본 문서는 프로젝트 보안·권한관리·감사(Audit) 체계를 신규 정의한 설계 문서이다.
