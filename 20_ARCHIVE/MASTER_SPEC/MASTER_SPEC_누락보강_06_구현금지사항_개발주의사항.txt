MASTER_SPEC 누락보강 06
주제 : 구현 금지사항 및 개발 주의사항

1. 목적
본 문서는 프로젝트 진행 중 반복적으로 발생했던 오류와 복구 사례를 바탕으로
반드시 준수해야 할 구현 원칙을 정리한다.

2. 구현 전 원칙
- 구현 전 현재 파일을 반드시 확인한다.
- 이전 버전이나 추측을 기준으로 수정하지 않는다.
- 사용자가 지정한 최신 파일만 기준으로 작업한다.

3. 절대 금지
- 임의 리팩토링
- 임의 구조 변경
- 사용자가 지시하지 않은 기능 추가
- 용어 임의 변경
- 신규 개념 생성
- 저장 기능 구현
- 실주문 연결
- rules.json 저장 로직 구현
- 전체 문자열 일괄 치환
- 함수 단위 정규식 삭제
- 불필요한 ZIP 생성

4. UI 수정 원칙
- UI 작업 중 로직 수정 금지
- 기존 객체명 유지
- 기존 Signal/Slot 참조 유지
- 위젯 삭제 시 참조 제거까지 완료

5. 공통 구현 원칙
- 동일 기능은 공통 함수 재사용
- 중복 코드 최소화
- BUY/SELL 공통 정책은 동일 규칙 유지
- 공통 위젯은 동일 스타일 유지

6. 검증 절차
수정 후 반드시 확인
- py_compile
- 런타임 실행
- AttributeError 여부
- 콤보 표시 규칙
- 상태 동기화
- UI 잘림 여부

7. 문서 반영 원칙
- 확정 사항만 MASTER_SPEC 반영
- 논의 단계는 보류로 기록
- 폐기된 설계는 폐기 사유와 함께 기록

8. AI 작업 원칙
- 확정되지 않은 내용을 사실처럼 구현하지 않는다.
- 구현 방향은 사용자 확인 후 진행한다.
- 설명보다 실제 구현 기준을 우선한다.
- 이미 확정된 내용을 반복 질문하지 않는다.

9. 복구 기준
- 문제가 발생하면 최신 정상본 기준으로 복원한다.
- 부분 수정보다 정상 기준 비교를 우선한다.
- 변경 범위를 명확히 기록한다.

10. 향후 보강
- 엔진 연결 체크리스트
- UI 수정 체크리스트
- MASTER_SPEC 반영 체크리스트
- 코드 리뷰 체크리스트
