MASTER_SPEC_추가갱신_코딩규약_Implementation_Standards_2026-07-03

목적
- 프로젝트 전체에서 구현 시 반드시 따라야 하는 코딩 규약을 정의한다.
- 아키텍처 원칙을 실제 코드 수준까지 일관되게 유지하기 위한 기준이다.

==================================================
1. 책임 규칙
==================================================
Engine
- 판단만 수행
- 파일 저장 금지
- GUI 접근 금지

Controller
- 호출 순서만 관리
- 판단 최소화
- 상태 전이만 조정

Boundary
- OpenAPI 통신만 담당
- 전략 판단 금지

Runtime
- 데이터 저장/조회만 담당

==================================================
2. 함수 규칙
==================================================
- 함수는 하나의 책임만 가진다.
- Preview 함수는 상태를 변경하지 않는다.
- apply_* 함수만 Runtime 변경 가능.
- evaluate_* 함수는 메모리 결과만 반환한다.
- build_* 함수는 객체 생성만 담당한다.

==================================================
3. 상태 변경 규칙
==================================================
- 상태 변경은 단일 함수에서만 수행한다.
- 상태 변경 후 즉시 검증 가능해야 한다.
- 우회 변경 금지.

==================================================
4. 테스트 규칙
==================================================
- 신규 기능마다 단위 테스트 추가.
- 회귀 테스트 필수.
- TemporaryDirectory 기반 테스트 우선.
- 운영 Runtime 사용 금지.

==================================================
5. Runtime 규칙
==================================================
- JSON 구조 임의 변경 금지.
- 필드 삭제보다 신규 필드 추가 우선.
- ID는 생성 후 변경 금지.

==================================================
6. 금지 사항
==================================================
- SendOrder 직접 호출
- GUI에서 Engine 직접 수정
- Preview에서 Runtime 변경
- 테스트 없는 구조 변경
- Controller 우회

==================================================
7. 문서 규칙
==================================================
구조 변경 시
1. MASTER_SPEC 갱신
2. 작업재개요약 갱신
3. 테스트 결과 기록

최종 원칙
코드는 설계를 구현하는 수단이며,
설계 원칙을 위반하는 편의 구현은 허용하지 않는다.
