MASTER_SPEC_추가갱신_프로젝트_용어사전_Domain_Glossary_2026-07-03

목적
- 프로젝트 전반에서 사용하는 핵심 용어를 일관된 의미로 정의한다.

==================================================
아키텍처 용어
==================================================
MASTER_SPEC
- 프로젝트의 최상위 기준 문서.

ADR
- 구조적 의사결정 기록.

Runtime
- 실행 중 유지되는 JSON 기반 데이터.

Controller
- 흐름과 상태 전이를 관리하는 계층.

Engine
- 판단과 계산만 수행하는 계층.

Boundary
- 외부 시스템(OpenAPI)과 통신하는 계층.

==================================================
주문 파이프라인
==================================================
Signal
- 루틴이 생성한 매매 판단.

Order Candidate
- 주문 가능성을 계산한 후보.

Approval
- 주문 후보 승인 단계.

Policy
- 운영 정책 검증 단계.

Preflight
- 실주문 직전 최종 검증.

Preview
- 실제 주문 없이 요청을 생성하는 검증 단계.

Execution
- 실제 주문 요청 수행.

Fill
- 체결 결과.

Position
- 체결 결과로 유지되는 보유 상태.

==================================================
운영 용어
==================================================
Review
- 수동 검토가 필요한 항목.

Recovery
- 재시작 또는 장애 이후 상태 복구.

Audit
- 운영 이력 및 추적 기록.

==================================================
문서 용어
==================================================
작업재개요약서
- 다음 작업을 이어가기 위한 문서.

MASTER_SPEC 갱신자료
- MASTER_SPEC 반영 전 변경사항 정리 문서.

==================================================
최종 원칙
==================================================
동일 용어는 프로젝트 전체에서 동일한 의미로 사용하며,
새로운 용어를 추가할 경우 기존 용어와의 관계를 함께 정의한다.
