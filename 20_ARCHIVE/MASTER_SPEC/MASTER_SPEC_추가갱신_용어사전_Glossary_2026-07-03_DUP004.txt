MASTER_SPEC_추가갱신_용어사전_Glossary_2026-07-03

목적
- 프로젝트 전반에서 사용하는 핵심 용어의 의미를 단일 기준으로 정의한다.
- 동일 용어를 다른 의미로 사용하는 것을 방지한다.

==================================================
1. Signal
==================================================
루틴이 생성한 매수/매도 판단 결과.
주문이 아니다.

==================================================
2. Order Candidate
==================================================
Signal로부터 생성된 주문 후보.
실주문 대상이 아니다.

==================================================
3. Approval
==================================================
주문 후보의 형식과 기본 조건을 검증하는 단계.

==================================================
4. Operation Policy
==================================================
운영 정책을 기준으로 주문 후보를 실행 가능 후보로 승격하는 단계.

==================================================
5. Real Preflight
==================================================
실주문 직전 Guard 조건을 검증하는 단계.

==================================================
6. Adapter Request Preview
==================================================
SendOrder 요청 형식을 메모리에서만 생성하는 미리보기.
파일과 상태를 변경하지 않는다.

==================================================
7. Execution Request
==================================================
실제 주문 요청 단위.
Order와 Kiwoom 주문 사이를 연결한다.

==================================================
8. Final Execution Guard
==================================================
ORDER_QUEUED 생성 직전 마지막 안전 검증.

==================================================
9. Fill
==================================================
실제 체결 결과.
Position 변경의 유일한 근거.

==================================================
10. Position
==================================================
실제 보유 상태.
Order가 아니라 Fill의 결과이다.

==================================================
11. 마감(Close)
==================================================
운영 종료 절차.

==================================================
12. 청산(Liquidation)
==================================================
Position을 0으로 만드는 거래 절차.

==================================================
13. Review Management
==================================================
자동 처리하면 안 되는 항목을 운영자가 확인하기 위한 관리 계층.

==================================================
14. Recovery
==================================================
재시작/긴급정지 해제 후 Runtime와 서버 상태를 검증하는 절차.

==================================================
15. Audit Log
==================================================
상태 전이와 주요 이벤트를 기록하는 감사 계층.
실행 판단은 하지 않는다.

==================================================
16. Runtime
==================================================
프로그램 실행 중 유지되는 상태 데이터(JSON/JSONL).

==================================================
17. Boundary
==================================================
프로젝트 내부와 Kiwoom OpenAPI 사이의 유일한 통신 계층.

==================================================
최종 원칙

Signal → Order → Execution → Fill → Position

각 용어는 하나의 의미만 가지며,
동일 용어를 다른 의미로 재정의하지 않는다.
