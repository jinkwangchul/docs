# MASTER_SPEC v1.1 대비 v1.2 변경점

## 목적

본 문서는 `MASTER_SPEC v1.1 Windows GUI Edition`과 `MASTER_SPEC v1.2 Structure Phase 2`의 차이를 정리한다.

v1.1은 원본 보존용 Legacy Reference이고, v1.2는 최신 구조개선 정책을 반영한 Current Master Spec이다.

---

# 1. 문서 지위 변경

## v1.1

- Windows GUI 기반 최초 확정 설계서.
- 기존 폴더 구조, 파일 구조, GUI 화면, 기본 자동매매 규칙 중심.

## v1.2

- 구조개선 2차 정책을 반영한 최신 기준 문서.
- 상태체계, 조기마감, 검토종목, 무결성 검사, 익일이월 정책을 재정립.

## 변경 의미

v1.1은 삭제하지 않고 보존한다.

앞으로 정책 판단과 코드 구조개선은 v1.2 기준으로 진행한다.

---

# 2. 상태체계 변경

## v1.1

- 기존 상태값과 GUI 표시가 혼재.
- 정지, 일시정지, 매도 홀딩, 상태 복구 등 여러 개념이 섞여 있음.

## v1.2

최종 상태를 6개로 정리.

- 감시/대기
- 매수/매도
- 감시/매도
- 조기마감
- 긴급정지
- 검토종목

## 폐기

- 정지
- 일시정지
- 전체대기
- 저강도 긴급정지
- 중강도 긴급정지
- 고강도 긴급정지

## 변경 의미

상태명이 운영자 기준으로 명확해졌고, 구버전 상태표시는 단계적으로 제거한다.

---

# 3. 긴급정지 정책 변경

## v1.1

- 긴급정지 버튼 중심.
- 전체 자동매매 정지 성격이 강함.

## v1.2

- 긴급정지를 단일 비상 상태로 정리.
- 다단계 긴급정지 폐기.
- 자동복귀 금지.
- 해제 시 무결성 검사 후 현재조건 재판정.

## 변경 의미

긴급정지는 단순 정지 버튼이 아니라 계좌 단위 위험을 차단하는 안전상태가 됨.

---

# 4. 검토종목 도입

## v1.1

- 문제 종목 격리 개념이 약함.
- 상태 불일치 발생 시 처리 기준이 충분히 분리되지 않음.

## v1.2

검토종목을 정식 상태로 도입.

검토종목은 자동매매 신뢰성이 훼손된 종목의 격리구역이다.

자동복귀 금지.

복귀는 수동 무결성 검사 후 현재조건 재판정으로만 가능.

## 변경 의미

A 종목 문제로 B 종목까지 멈추지 않게 하며, 문제 종목만 격리한다.

---

# 5. 검토위치 / 상세원인 분리

## v1.1

- 오류 사유나 로그 메시지 중심.

## v1.2

`진입사유` 대신 아래 두 값을 분리.

- 검토위치 = 문제 유형
- 상세원인 = 발생 원인

예:

```text
검토위치: 수량불일치
상세원인: HTS 수동매도
```

```text
검토위치: 주문불일치
상세원인: HTS 수동취소
```

## 변경 의미

운영자가 문제 위치와 원인을 빠르게 구분할 수 있다.

---

# 6. 감시/매도와 조기마감 분리

## v1.1

- 시간 종료, 정지, 매도전용 상태가 혼재할 수 있음.

## v1.2

감시/매도와 조기마감을 분리.

감시/매도:

- 일반 시간운영 종료 상태.
- 신규매수 금지.
- 루틴 매도정책 유지.

조기마감:

- 운영자가 명시적으로 실행한 예외적 정리 상태.
- 루틴 유지 + 시간조건 제거 + 즉시평가.

## 변경 의미

운영자는 일반 시간종료인지, 강제 조기정리인지 화면에서 바로 구분 가능하다.

---

# 7. 조기마감 정책 변경

## v1.1

- 장마감 또는 청산 중심 개념.
- 조기마감의 기본 동작이 명확히 분리되지 않음.

## v1.2

조기마감 기본값:

```text
루틴 유지
+ 시간조건 제거
+ 즉시평가
```

즉, 시장가 강제청산이 기본값이 아니다.

추가 옵션 후보:

- 현재가 청산
- 시장가 청산
- 지정가 청산
- 익절 N% 이상 청산
- 손절 N% 이하 청산
- 익일이월

## 변경 의미

조기마감은 루틴을 깨는 기능이 아니라 루틴을 가속하는 기능이다.

---

# 8. 익일이월 정책 변경

## v1.1

- 익일이월 후 재개 흐름이 명확하지 않음.

## v1.2

익일이월 발생 시 무조건 검토종목으로 이동.

```text
장마감 또는 조기마감
→ 익일이월
→ 검토종목
→ 수동 무결성 검사
→ 현재조건 재판정
```

자동복귀 금지.

## 변경 의미

익일이월 종목이 다음날 자동으로 정상 매매에 복귀하는 위험을 제거한다.

---

# 9. 무결성 검사 체계 변경

## v1.1

- 무결성검증 창 개념 존재.
- config/state/orders 중심 검증.

## v1.2

무결성 검사를 3종류로 재정의.

1. 자동 무결성 검사
2. 개별 무결성 검사
3. 전체 무결성 검사

공통 내부 단계:

```text
구조 무결성
→ 종목 무결성
→ 계좌 무결성
```

## 변경 의미

HTS/계좌 불일치뿐 아니라 파일/폴더 구조 변경, JSON 손상, 루틴 참조 누락까지 검사 범위에 포함한다.

---

# 10. 종목 등록 정책 변경

## v1.1

- 등록과 검증이 분리될 수 있음.

## v1.2

종목 등록 시 자동 무결성 검사를 내부 로직으로 수행.

검사:

- 보유수량 0
- 미체결 매수 0
- 미체결 매도 0
- 계좌조회 정상

종목등록창에는 별도 무결성 검사 버튼을 두지 않는다.

이상 발견 시 검토종목으로 이동 또는 검토종목 등록.

## 변경 의미

위험 종목이 정상 운영으로 들어오는 것을 등록 단계에서 차단한다.

---

# 11. 무결성 검사 버튼 위치 변경

## v1.1

- 무결성검증 창이 독립 기능으로 존재.

## v1.2

버튼 위치를 목적별로 분리.

- 자동검사: 종목 등록 / 프로그램 재시작 내부 자동 수행
- 개별검사: 검토종목 관리창
- 전체검사: 관제센터 도구 메뉴

## 변경 의미

사용자가 어떤 검사를 눌러야 하는지 헷갈리지 않도록 UI 흐름을 단순화한다.

---

# 12. 루틴과 메인엔진 책임 분리 강화

## v1.1

- 루틴 독립 운영 중심.
- 다중 루틴 가능성을 포함.

## v1.2

루틴은 신호 생성기.

메인엔진은 실행판정 및 주문집행 담당.

루틴은 주문을 직접 실행하지 않는다.

루틴은 시간판정, 긴급정지, 검토종목, 장마감 정책을 직접 처리하지 않는다.

## 변경 의미

루틴 로직과 안전 통제 로직을 분리하여 충돌 가능성을 줄인다.

---

# 13. 루틴 매도조건 확장

## v1.1

- MACD 매매 규칙 중심.

## v1.2

루틴은 아래와 같은 매매조건 조합을 허용한다.

예:

```text
매수 = MACD 조건
매도 = 매수가 대비 +N% 익절
매도 = 매수가 대비 -N% 손절
```

## 변경 의미

매수 신호와 매도 신호를 독립적으로 설계할 수 있다.

---

# 14. 파일 / 폴더 구조 방향 변경

## v1.1

- 루틴별 종목폴더 구조 중심.

## v1.2

종목데이터 중앙집중화 방향 채택.

목표:

```text
종목데이터/
└ 종목폴더/
   ├ state.json
   ├ orders.json
   ├ config.json
   └ stock_log.txt
```

루틴폴더는 루틴 설정과 신호 생성 자료만 보유.

## 변경 의미

state.json, orders.json 중복과 상태 충돌을 줄인다.

단, 실제 이관은 단계적으로 진행한다.

---

# 15. 프로그램 재시작 정책 변경

## v1.1

- 시스템 종료 후 재시작 시 자동 복구 가능성이 포함됨.

## v1.2

재시작 시 기존 state.json을 그대로 복구하지 않는다.

다시 확인:

- 현재시간
- 운영방식
- 보유수량
- 미체결 매수
- 미체결 매도
- 긴급정지 여부
- 이월 여부
- 파일/폴더 구조
- 루틴 참조

정상:

- 현재조건 재판정

이상:

- 검토종목 또는 긴급정지

## 변경 의미

재시작 후 잘못된 상태로 자동매매가 재개되는 위험을 줄인다.

---

# 16. UI 정책 변경

## v1.1

- Windows GUI 화면 구조 확정 중심.

## v1.2

운영자 관제 중심 UI 정책 추가.

상태 색상 후보:

- 감시/대기: 회색
- 매수/매도: 초록
- 감시/매도: 주황
- 조기마감: 보라
- 긴급정지: 빨강
- 검토종목: 노랑

클릭 정책:

- 수동 컬럼 좌클릭 → 수동운영 설정
- 시간 컬럼 좌클릭 → 시간운영 설정
- 상태 컬럼 우클릭 → 조기마감 / 긴급정지 / 무결성 검사 / 검토종목 이동

## 변경 의미

일상 설정과 예외 운영 명령을 분리한다.

---

# 17. 로그 정책 변경

## v1.1

- 변경사항과 오류 기록 중심.

## v1.2

판정 이유 기록을 강화.

검토종목 이동 시 필수 기록:

- 검토위치
- 상세원인
- 이전상태
- 변경상태
- 당시 보유수량
- 당시 미체결 매수/매도
- 관련 주문번호
- 관련 루틴명

## 변경 의미

나중에 왜 검토종목이 되었는지 추적 가능하다.

---

# 18. 코드 반영 방식 변경

## v1.1

- 설계 확정 후 구현 중심.

## v1.2

정책 확정과 코드 반영을 분리한다.

순서:

```text
정책 확정
→ MASTER_SPEC 반영
→ 상태코드 매핑
→ 소규모 코드 수정
→ 실행 검증
→ 다음 단계
```

## 변경 의미

무리한 일괄수정 대신 안정적인 점진 반영을 원칙으로 한다.

---

# 19. 결론

v1.2는 v1.1의 GUI 기반 자동매매 구조를 유지하면서, 실제 운영 중 발견된 위험 요소를 반영해 상태체계와 안전정책을 재정립한 문서이다.

가장 큰 변화는 아래 6개이다.

1. 상태체계 6개로 재정리.
2. 검토종목 정식 도입.
3. 조기마감과 감시/매도 분리.
4. 익일이월은 검토종목 이동으로 확정.
5. 무결성 검사를 자동/개별/전체 3종으로 확장.
6. 루틴은 신호만 만들고 메인엔진이 주문 실행을 최종 판단.
