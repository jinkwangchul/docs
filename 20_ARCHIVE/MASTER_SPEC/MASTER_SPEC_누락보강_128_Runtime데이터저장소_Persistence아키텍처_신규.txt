MASTER_SPEC 누락보강 128
주제 : Runtime 데이터 저장소 및 지속성(Persistence) 아키텍처 (신규)

※ 본 문서는 기존 01~127과 중복되지 않으며 Runtime 데이터의 저장,
복원 및 지속성(Persistence) 관리 체계를 정의한다.

1. 목적
프로젝트 실행 중 생성되는 모든 Runtime 데이터를 안정적으로 저장하고,
프로그램 재시작 및 장애 복구 시 동일한 상태를 재현할 수 있도록 한다.

2. Runtime 데이터 대상
- 종목 상태(State)
- PLAN 정보
- 주문 정보
- 체결 정보
- 예산 상태
- 운영 상태
- 검토관리 정보
- 임시 캐시

3. 저장 계층
① 메모리(Runtime)
② Runtime 파일
③ 로그 저장소
④ 백업 저장소

4. 저장 정책
- 이벤트 발생 시 즉시 저장
- 중요 상태 변경 시 강제 저장
- 주기적 자동 저장
- 종료 시 최종 저장

5. 복원 절차
① Runtime 데이터 로드
② 무결성 검사
③ 참조 관계 복원
④ 상태 재동기화
⑤ 운영 가능 여부 판정
⑥ 운영 재개

6. 데이터 무결성
- 파일 손상 검사
- JSON 구조 검증
- 참조 관계 확인
- 버전 호환성 확인
- 누락 데이터 검사

7. 백업 정책
- 자동 백업
- 수동 백업
- 세대별 백업 관리
- 백업 무결성 검증

8. 장애 대응
- 손상 Runtime 자동 격리
- 이전 백업 복원
- 복원 실패 시 검토관리 연계
- 복구 로그 생성

9. 향후 확장
- Snapshot 저장
- 증분(Incremental) 저장
- 데이터 압축
- 클라우드 동기화

10. 구현 원칙
- Runtime 데이터는 단일 저장 규격을 사용한다.
- 저장과 복원은 항상 동일한 절차를 따른다.
- Persistence 계층은 엔진 구현과 독립적으로 관리한다.

반영 원칙
본 문서는 Runtime 데이터 저장소 및 Persistence 아키텍처를 신규 정의한 설계 문서이다.
