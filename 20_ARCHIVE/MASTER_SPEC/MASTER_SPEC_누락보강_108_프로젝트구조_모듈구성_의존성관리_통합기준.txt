MASTER_SPEC 누락보강 108
주제 : 프로젝트 구조·폴더·모듈 구성 및 의존성 관리 통합 기준

출처 : 작업진행상황대화히스토리 3~8 비교 반영

목적
프로젝트의 디렉터리 구조, 모듈 구성, 의존성 관리 원칙을 통합하여
장기적인 유지보수성과 확장성을 확보한다.

1. 구조 원칙
- 기능별 모듈 분리
- UI, 엔진, 데이터, 운영 기능 분리
- 공통 기능은 공용 모듈로 관리
- 순환 참조를 지양한다.

2. 디렉터리 구성
- GUI
- Engine
- Routine
- Runtime
- Logs
- Stocks
- Config
- Test
- Docs

3. 모듈 의존성
Routine → PLAN → Execution → Management
상위 정책은 하위 실행을 직접 구현하지 않는다.

4. 공통 모듈
- 공통 유틸리티
- 공통 상태 관리
- 공통 로그
- 공통 JSON 처리
- 공통 UI Helper

5. 구현 원칙
- 모듈 간 역할을 중복하지 않는다.
- 내부 구현보다 공개 인터페이스를 사용한다.
- 변경 영향 범위를 최소화한다.

6. 확장 원칙
- 신규 루틴은 기존 구조를 재사용한다.
- 신규 기능은 공통 계층을 우선 검토한다.
- 폴더 구조는 기능 중심으로 유지한다.

7. 검증 항목
□ 순환참조 없음
□ 공통 모듈 재사용
□ 계층 의존성 유지
□ 구조 일관성
□ 유지보수성 확보

반영 원칙
본 문서는 기존 누락보강 171~180 수준의 프로젝트 구조·모듈 구성·의존성 관리 내용을
통합한 기준 문서이다.
