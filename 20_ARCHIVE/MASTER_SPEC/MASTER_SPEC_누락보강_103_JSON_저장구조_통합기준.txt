MASTER_SPEC 누락보강 103
주제 : JSON 및 저장 구조 통합 기준

출처 : 작업진행상황대화히스토리 3~8 비교 반영

목적
루틴 설정의 저장, 복원, 버전 관리 및 JSON 구조에 대한 공통 기준을 정의한다.

1. 저장 구조
- routine.json : 루틴 기본 정보
- rules.json : 전략/설정 정보
- version.txt : 버전 관리
- readme.md : 설명 문서
- samples : 예제 데이터

2. 저장 원칙
- UI 상태와 JSON 구조를 일치시킨다.
- 저장과 복원은 동일 규칙을 사용한다.
- 기본값과 사용자 설정을 명확히 구분한다.

3. JSON 설계 원칙
- 계층 구조를 유지한다.
- 의미 없는 중복 키를 만들지 않는다.
- 확장 가능한 구조를 우선한다.
- 하위 호환성을 고려한다.

4. 버전 관리
- 구조 변경 시 버전을 증가시킨다.
- 변경 이력을 기록한다.
- 이전 버전과의 호환 여부를 명시한다.

5. 저장/복원
① UI 입력
② JSON 생성
③ 파일 저장
④ 프로그램 재시작
⑤ JSON 읽기
⑥ UI 복원

6. 검증 항목
□ 저장 일치
□ 복원 일치
□ 기본값 일치
□ 버전 확인
□ 호환성 확인

7. 구현 원칙
- 저장 형식은 루틴 종류와 무관하게 공통 규칙을 따른다.
- JSON 키 변경 시 관련 문서와 구현을 동시에 갱신한다.
- 저장 구조보다 의미의 일관성을 우선한다.

반영 원칙
본 문서는 기존 누락보강 121~130 수준의 JSON·저장 구조 정책을 통합한 기준 문서이다.
