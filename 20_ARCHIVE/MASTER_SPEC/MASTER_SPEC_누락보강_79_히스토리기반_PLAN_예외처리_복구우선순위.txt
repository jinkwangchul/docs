MASTER_SPEC 누락보강 79
주제 : 히스토리 기반 PLAN 예외 처리 및 복구 우선순위

출처 : 작업진행상황대화히스토리_3~8 비교 반영

1. 목적
PLAN(BUY/SELL) 처리 중 예외 상황이 발생했을 때 일관된 복구 절차와
우선순위를 적용하기 위한 기준을 정의한다.

2. 기본 원칙
- 예외 발생 시 상태를 임의로 변경하지 않는다.
- 가능한 한 현재 PLAN을 보존하며 복구를 우선한다.
- 복구가 불가능한 경우에만 종료 또는 검토관리로 전환한다.

3. 예외 유형
- 주문 전송 실패
- 체결 정보 불일치
- 상태 저장 실패
- 통신 오류
- 내부 예외
- 프로그램 재시작

4. 처리 우선순위
① 현재 상태 보존
② 원인 기록
③ 복구 가능 여부 확인
④ 자동 복구 수행
⑤ 복구 실패 시 종료 정책 적용
⑥ 필요 시 검토관리 지정

5. 복구 원칙
- 복구 후 동일 PLAN을 계속 사용할 수 있으면 유지한다.
- 중복 PLAN 생성을 금지한다.
- 상태와 로그를 동기화한 후 처리 재개 여부를 판단한다.

6. 역할 분리
루틴
- 예외 정책 정의
- 종료 조건 정의

메인
- 상태 보존
- 복구 수행
- 로그 기록
- 검토관리 연계

7. 검증 항목
□ 상태 보존
□ 복구 성공
□ 로그 일치
□ 중복 PLAN 방지
□ 검토관리 연계
□ 재시작 복구

8. 반영 원칙
본 기준은 히스토리에서 확정된 PLAN 예외 처리 및 복구 철학을 기반으로 하며,
향후 모든 자동매매 루틴의 공통 예외 처리 기준으로 적용한다.
