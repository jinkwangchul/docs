MASTER_SPEC 누락보강 116
주제 : 루틴 패키지 배포·설치·업데이트 아키텍처 (신규)

※ 본 문서는 기존 01~115와 중복되지 않는 루틴 패키지의 배포 및 관리 구조를 신규 정의한다.

1. 목적
루틴을 프로그램 수정 없이 추가·업데이트·제거할 수 있는 표준 패키지 구조를 정의한다.

2. 목표
- 파일 배치만으로 루틴 자동 인식
- 설치 프로그램 불필요
- 기존 루틴과 독립 운영
- 버전 호환성 유지

3. 표준 패키지 구성
- routine.json
- rules.json
- version.txt
- readme.md
- samples/
- resources(선택)

4. 등록 절차
① 패키지 복사
② 무결성 검사
③ 메타데이터 확인
④ 버전 확인
⑤ 자동 등록
⑥ UI 반영

5. 업데이트 정책
- 동일 루틴 버전 비교
- 설정 호환성 확인
- 필요 시 마이그레이션
- 실패 시 이전 버전 복원

6. 제거 정책
- 운영 중 제거 금지
- PLAN 종료 후 제거
- 관련 설정 백업
- 등록 정보 정리

7. 호환성 정책
- 엔진 API 버전 확인
- 지원 버전 범위 명시
- 미지원 버전은 등록 차단
- 변경 이력 기록

8. 보안 및 검증
- 필수 파일 존재 확인
- JSON 구조 검증
- 중복 루틴 검사
- 손상 패키지 차단

9. 향후 확장
- 온라인 패키지 저장소
- 자동 업데이트
- 디지털 서명
- 개발자 패키지 배포

10. 구현 원칙
- 루틴은 플러그인처럼 독립 동작한다.
- 메인 프로그램은 패키지 규격만 의존한다.
- 배포 절차는 운영 환경과 개발 환경에서 동일해야 한다.

반영 원칙
본 문서는 루틴 패키지 배포·설치·업데이트 체계를 신규 정의한 설계 문서이다.
