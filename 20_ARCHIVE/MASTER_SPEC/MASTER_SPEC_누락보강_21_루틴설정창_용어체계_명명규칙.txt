MASTER_SPEC 누락보강 21
주제 : 루틴 설정창 용어 체계 및 명명 규칙

1. 목적
프로젝트 전반에서 동일한 개념은 항상 동일한 용어를 사용하여
UI, 문서, 엔진 간 혼선을 방지한다.

2. 기본 원칙
- 하나의 개념에는 하나의 공식 용어만 사용한다.
- 임시 설명용 표현은 MASTER_SPEC에 반영하지 않는다.
- UI와 문서의 명칭을 가능한 한 동일하게 유지한다.

3. 명명 규칙
- 실행 순서는 '수행 1~N' 형식 사용
- 정책은 '○○정책'
- 조건은 '○○조건'
- 설정은 '○○설정'

4. 금지 사항
- 동일 기능에 여러 이름 사용
- 설명용 별칭을 공식 명칭으로 승격
- 개발 편의상 축약어 사용

5. UI 표기 원칙
- 제목은 기능 중심
- 입력은 설정 중심
- 실행 결과는 상태 중심

6. 문서 반영 원칙
- 용어 변경 시 변경 이유 기록
- 기존 명칭과의 대응 관계 기록
- 영향 범위 함께 기록

7. 엔진 연계
- JSON 키와 UI 명칭은 필요 시 분리 가능
- 내부 변수명보다 사용자 용어를 우선 정의

8. 검증
- 동일 용어 중복 여부
- 폐기 용어 잔존 여부
- UI/문서 불일치 여부

9. 향후 관리
- 신규 용어 추가 시 본 규칙 검토
- 프로젝트 전체 용어 사전 유지

10. 결론
용어의 일관성은 구조 안정성의 일부이며,
모든 변경은 MASTER_SPEC 기준으로 관리한다.
