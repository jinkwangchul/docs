주제 : 히스토리 기반 NOT 연산 규칙 및 입력기 해석 기준

출처 : 작업진행상황대화히스토리_7 비교 반영

1. 목적
조건식 입력기에서 NOT 연산의 해석을 프로젝트 전체에서 동일하게 적용하기 위한 기준을 정의한다.

2. 기본 규칙
- A = 조건
- B = 조건
- C = 조건
- AND = 조건 연결
- OR = 조건 연결
- NOT = 뒤에 오는 조건을 제외

3. 해석 기준
예시:
A AND B NOT C

의미:
- A 조건 만족
- B 조건 만족
- C 조건은 제외

즉, NOT은 독립적인 논리 연산자가 아니라
바로 뒤 조건을 제외하는 의미로 해석한다.

4. 입력기 원칙
- 입력기와 내부 해석은 동일해야 한다.
- 사용자가 보는 조건식과 엔진 해석이 달라져서는 안 된다.
- 동일 규칙을 BUY/SELL 조건 모두에 적용한다.

5. 구현 원칙
- NOT 해석은 공통 파서에서 수행한다.
- 화면별 개별 해석을 금지한다.
- 테스트 케이스를 통해 동일 결과를 검증한다.

6. 검증 항목
□ A AND B NOT C
□ A OR B NOT C
□ 다중 조건 연결
□ 저장/복원 후 동일 해석
□ UI 표시와 엔진 해석 일치

7. 반영 원칙
본 규칙은 히스토리 검토 과정에서 확정된 입력기 해석 기준이며,
향후 조건식 파서와 UI의 공식 기준으로 사용한다.
