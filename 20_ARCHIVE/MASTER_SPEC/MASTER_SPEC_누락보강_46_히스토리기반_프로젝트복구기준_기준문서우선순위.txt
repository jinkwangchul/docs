MASTER_SPEC 누락보강 46
주제 : 히스토리 기반 프로젝트 복구 기준 및 기준 문서 우선순위

출처 : 프로젝트 복구 이력 및 작업 히스토리 비교 반영

1. 목적
프로젝트 복구 및 재개 시 어떤 자료를 기준으로 판단할 것인지
공식 우선순위를 정의한다.

2. 기준 문서 우선순위
① 현재 구현 코드
② MASTER_SPEC(확정본)
③ 작업 히스토리
④ 작업재개 요약서
⑤ 기타 메모

상위 자료와 충돌할 경우 하위 자료를 수정 대상으로 판단한다.

3. 복구 원칙
- 가장 최근 구현 상태를 먼저 확인한다.
- 코드와 문서가 다르면 원인을 분석한다.
- 문서가 오래된 경우 최신 구현에 맞게 갱신한다.
- 추정으로 복구하지 않는다.

4. 변경 검증 절차
① 현재 코드 확인
② 히스토리 확인
③ MASTER_SPEC 확인
④ 차이점 정리
⑤ 수정 여부 결정
⑥ 문서 갱신

5. 작업 재개 원칙
- 최신 정상 파일을 기준으로 시작한다.
- 중간 결과물이 아닌 확정본을 우선 사용한다.
- 폐기된 구조를 다시 적용하지 않는다.

6. 충돌 처리
- 코드와 문서가 다르면 이유를 기록한다.
- 히스토리와 문서가 다르면 실제 결정 과정을 확인한다.
- 사용자 최종 결정이 항상 우선한다.

7. 검증 항목
□ 최신 구현 확인
□ 문서 일치 여부
□ 정책 일치 여부
□ 복구 완료 확인
□ 재발 방지 기록

8. 결론
프로젝트 복구는 하나의 자료만으로 판단하지 않으며,
코드·MASTER_SPEC·히스토리를 함께 검증한 후 진행한다.
