MASTER_SPEC 누락보강 95
주제 : 히스토리 기반 PLAN 중심 자동매매 프레임워크 최종 아키텍처 보존 기준

출처 : 작업진행상황대화히스토리_3~8 비교 반영

1. 목적
프로젝트가 장기간 확장되더라도 PLAN 중심 아키텍처의 핵심 구조가 유지되도록
최종 보존 기준을 정의한다.

2. 핵심 보존 원칙
- PLAN 중심 구조를 유지한다.
- 전략과 실행 계층을 혼합하지 않는다.
- 공통 인터페이스를 우선한다.
- 공통 상태 머신을 유지한다.

3. 반드시 유지할 요소
- Routine Layer
- PLAN Layer
- Execution Layer
- Management Layer
- 이벤트 기반 상태 전이
- 공통 로그 및 복구 체계

4. 변경 가능 요소
- 루틴별 전략
- 필터
- 주문 정책
- UI 구성
- 운영 정책

5. 변경 절차
① 변경 필요성 검토
② 영향 범위 분석
③ 공통 구조 유지 여부 확인
④ 구현
⑤ 테스트
⑥ 문서 및 버전 갱신

6. 금지 사항
- PLAN 생명주기 임의 변경
- 공통 상태 정의 변경
- 계층 책임 혼합
- 로그·상태 불일치 허용
- 루틴별 독자 실행 구조 생성

7. 최종 검증
□ 공통 아키텍처 유지
□ 상태 머신 유지
□ 인터페이스 유지
□ 기존 루틴 호환
□ 문서 최신화
□ 운영 검증 완료

8. 반영 원칙
본 기준은 히스토리에서 확정된 PLAN 중심 자동매매 프레임워크의 최종 아키텍처 보존 기준이며,
향후 프로젝트의 구조 안정성과 장기 유지보수의 최상위 기준으로 적용한다.
