MASTER_SPEC 누락보강 90
주제 : 히스토리 기반 PLAN 중심 자동매매 프레임워크 최종 운영 검증 기준

출처 : 작업진행상황대화히스토리_3~8 비교 반영

1. 목적
PLAN 중심 자동매매 프레임워크가 실제 운영 환경에서도 설계 의도와 동일하게
동작하는지 확인하기 위한 최종 운영 검증 기준을 정의한다.

2. 운영 검증 원칙
- 기능 검증보다 전체 흐름 검증을 우선한다.
- 상태, 로그, 복구는 항상 동일한 결과를 유지해야 한다.
- 운영 중 예외도 정상 시나리오와 동일한 기준으로 검증한다.

3. 운영 시나리오
① 루틴 활성
② 신호 검출
③ PLAN 생성
④ 주문 실행
⑤ 체결 및 상태 전이
⑥ 완료·미완성·실패 판정
⑦ 종료 및 기록
⑧ 재시작 복구

4. 핵심 검증 항목
□ PLAN 생성 정상
□ 중복 PLAN 없음
□ 상태 머신 정상
□ 이벤트 기반 처리
□ 로그 일치
□ 복구 일치
□ 검토관리 연계 정상

5. 예외 검증
- 통신 오류
- 주문 실패
- 부분 체결
- CANCEL
- 프로그램 재시작
- 상태 복구

6. 최종 판정 기준
- 설계 철학과 구현이 일치한다.
- 운영 중 상태 불일치가 없다.
- 공통 인터페이스가 유지된다.
- 신규 루틴 추가 시 기존 구조가 유지된다.

7. 반영 원칙
본 기준은 히스토리에서 확정된 PLAN 중심 자동매매 프레임워크의 최종 운영 검증 기준이며,
향후 릴리스 전 최종 검증 문서로 적용한다.
