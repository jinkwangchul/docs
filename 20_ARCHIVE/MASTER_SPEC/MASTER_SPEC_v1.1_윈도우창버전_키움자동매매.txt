버튼, 목록, 입력창, 선택창, 확인창, 상태표시창

## [프로젝트 목표]

키움 OpenAPI를 이용한 Windows GUI 기반 자동매매 시스템 구축.

자동매매 루틴을 독립적으로 운영 가능하도록 설계한다.

동일 종목에 여러 자동매매 루틴을 동시 적용할 수 있어야 한다.

시스템 종료 후 재시작 시 자동 복구가 가능해야 한다.

모든 자동매매 루틴은 종목별 설정, 상태, 주문, 로그를 독립적으로 관리해야 한다.

사용자는 콘솔 명령어가 아니라 Windows 창에서 자동매매 상태를 확인하고 제어할 수 있어야 한다.

## [구현 UI 원칙]

1. 기본 UI는 Windows GUI 방식이다.

2. 콘솔 입력 방식은 개발자 디버그 용도로만 허용한다.

3. 일반 사용자는 버튼, 목록, 입력창, 확인창을 통해 기능을 실행한다.

4. 실계좌 실행, 종목 삭제, 초기화, 전체 자동매매 정지는 반드시 확인창을 표시한다.

5. 긴급 정지 버튼은 메인 윈도우에서 항상 접근 가능해야 한다.

6. 실행 중인 자동매매 종목은 표 형태로 표시한다.

7. 오류 발생 시 팝업 알림과 system_error.log 기록을 동시에 수행한다.

8. 자동매매 시작, 정지, 종목 삭제, 환경설정 변경은 PROJECT_CHANGELOG.txt 에 기록한다.

9. GUI는 내부 데이터 파일을 직접 수정하지 않고 관리자 기능 함수를 통해서만 수정한다.

10. GUI 표시값과 실제 파일 상태가 불일치할 경우 파일 상태를 기준으로 다시 로딩한다.

## [추천 GUI 프레임워크]

Python 기반 Windows 프로그램으로 구현한다.

추천 프레임워크 :

1순위 : PySide6

2순위 : PyQt5

3순위 : tkinter

추천 기준 :

PySide6는 현대적인 Windows GUI 구현에 적합하고 라이선스 측면에서도 비교적 안정적이다.

단, 키움 OpenAPI의 ActiveX 연동 제약이 있을 경우 PyQt5 사용을 허용한다.

최종 선택은 키움 OpenAPI 연동 테스트 결과에 따른다.

## [최상위 규칙]

1. 기초종목.txt 는 시스템의 마스터 데이터이다.

2. 자동매매 루틴은 기초종목.txt 를 직접 수정할 수 없다.

3. 종목 등록 및 삭제는 관리자 GUI 기능을 통해서만 가능하다.

4. 기존 함수 삭제 금지.

5. 기존 데이터 구조 변경 금지.

6. 기존 파일명 변경 금지.

7. 기존 폴더 구조 변경 금지.

8. 신규 기능은 추가 방식으로 구현한다.

9. 모든 변경사항은 PROJECT_CHANGELOG.txt 에 기록한다.

10. 로그 파일은 삭제하지 않는다.

11. 주문 상태는 반드시 orders.json 에 기록한다.

12. 자동매매 실행 상태는 반드시 state.json 에 기록한다.

13. 루틴별 예산 상태는 반드시 budget.json 에 기록한다.

14. 실계좌 자동매매는 기본 비활성화한다.

15. 실계좌 자동매매 실행은 사용자 수동 승인 후에만 허용한다.

16. GUI에서 표시되는 모든 상태는 파일 및 키움 계좌 조회 결과를 기준으로 갱신한다.

17. GUI 버튼 클릭으로 실행되는 모든 기능은 로그를 남긴다.

### 3. 검색식등록 창

기능 :

키움 HTS에 사용자가 미리 생성한 "자동매매" 검색식을 호출한다.

화면 구성 :

1. 검색식 이름 표시
2. 검색식 불러오기 버튼
3. 검색 결과 표
4. 등록 실행 버튼
5. 닫기 버튼

검색 결과 표 표시 항목 :

1. 선택 여부
2. 종목코드
3. 종목명
4. 현재 등록 여부
5. 오류 여부

규칙 :

1. 기본 검색식 이름은 "자동매매"이다.

2. 이미 기초종목.txt 에 등록된 종목은 중복 등록하지 않는다.

3. 중복 종목은 표에서 중복으로 표시한다.

4. 등록 완료 종목 수를 팝업으로 표시한다.

## [자동매매 루틴 규칙]

자동매매 루틴 폴더는 "_" 로 시작한다.

예)

_MACD매매루틴

_RSI매매루틴

_이격도매매루틴

프로그램 시작 시 자동 탐색한다.

GUI 출력 시 "_" 는 제거한다.

루틴 폴더명은 실제 루틴 식별값으로 사용한다.

단, 기초종목.txt 에 기록되는 루틴명은 사용자 표시용 명칭을 사용한다.

예)

폴더명 : _MACD매매루틴

표시명 : MACD매매루틴

기초종목.txt 기록명 : MACD

## [기초종목.txt]

역할 :

전체 종목 관리용 마스터 데이터

형식 :

종목코드,종목명,등록루틴1,등록루틴2,...

예)

005930,삼성전자,MACD

000660,SK하이닉스,MACD,RSI

930000,가상종목,MACD,이격도

규칙 :

1. 동일 종목코드 중복 등록 금지.

2. 동일 종목명 중복 등록 금지.

3. 동일 종목의 다중 루틴 등록 허용.

4. 동일 종목의 동일 루틴 중복 등록 금지.

5. 자동매매 루틴은 기초종목.txt 를 직접 수정할 수 없다.

6. 기초종목.txt 수정은 관리자 GUI 기능을 통해서만 가능하다.

7. 기초종목.txt 는 루틴 등록 현황의 기준 데이터이다.

8. 루틴 폴더와 기초종목.txt 의 정보가 충돌할 경우 기초종목.txt 를 우선 기준으로 삼는다.

_루틴명/종목코드_종목명/

_MACD매매루틴/005930_삼성전자/

state.json

orders.json

logs/

규칙 :

2. 실행 상태와 복구 상태는 state.json 에 저장한다.

3. 주문 상태는 orders.json 에 저장한다.

4. 로그는 logs 폴더에 일별로 저장한다.

5. 설정, 상태, 주문, 로그를 하나의 파일에 혼합 저장하지 않는다.

## [config.json 검증 규칙]

1. buy_amount 는 0보다 커야 한다.

2. buy_qty 는 0 이상이어야 한다.

3. trade_amount_type 이 AMOUNT 이면 buy_amount 를 사용한다.

4. trade_amount_type 이 QTY 이면 buy_qty 를 사용한다.

5. max_buy_count 는 1 이상이어야 한다.

6. buy_signal_bar 는 1 이상이어야 한다.

7. sell_signal_bar 는 1 이상이어야 한다.

8. daily_loss_limit 은 0 이하 값이어야 한다.

9. start_time 은 end_buy_time 보다 빨라야 한다.

10. timeframe 은 허용값만 사용할 수 있다.

11. budget_limit 은 0보다 커야 한다.

12. buy_amount_mode 가 CUSTOM 이면 buy_amount_custom_steps 는 비어 있으면 안 된다.

13. profit_hold_enabled 가 true 이면 profit_hold_percent 는 0 이상이어야 한다.

14. resell_condition 이 AVG_PRICE_PROFIT 이면 resell_profit_percent 는 0보다 커야 한다.

15. 검증 실패 시 해당 종목의 자동매매는 시작하지 않는다.

16. 검증 실패 내역은 GUI 팝업으로 표시하고 system_error.log 에 기록한다.

## [orders.json]

역할 :

종목별, 루틴별 주문 상태 저장

기본 구조 :

{
  "orders": []
}

주문 항목 구조 :

{
  "order_id": "20260531-005930-MACD-BUY-001",
  "kiwoom_order_no": "",
  "routine": "MACD",
  "code": "005930",
  "name": "삼성전자",
  "side": "BUY",
  "order_qty": 10,
  "filled_qty": 0,
  "unfilled_qty": 10,
  "order_price": 75000,
  "filled_price": 0,
  "status": "ORDER_REQUESTED",
  "created_at": "2026-05-31 09:15:10",
  "updated_at": "2026-05-31 09:15:10"
}

side 허용값 :

BUY

SELL

status 허용값 :

READY

ORDER_REQUESTED

ORDER_ACCEPTED

PARTIAL_FILLED

FILLED

CANCEL_REQUESTED

CANCELLED

REJECTED

FAILED

규칙 :

1. 주문 요청 전 orders.json 에 주문 예정 정보를 기록한다.

2. 주문 요청 후 status 를 ORDER_REQUESTED 로 변경한다.

3. 키움 주문 접수 확인 시 ORDER_ACCEPTED 로 변경한다.

4. 일부 체결 시 PARTIAL_FILLED 로 변경한다.

5. 전량 체결 시 FILLED 로 변경한다.

6. 부분체결 후 미체결 수량 취소 요청 시 CANCEL_REQUESTED 로 변경한다.

7. 취소 완료 시 CANCELLED 로 변경한다.

8. 주문 거부 시 REJECTED 로 변경한다.

9. API 오류 또는 알 수 없는 실패 발생 시 FAILED 로 변경한다.

10. 모든 주문 상태 변경은 logs 에도 기록한다.

11. 주문 상태는 GUI 주문상태 보기 창에 표시한다.

## [budget.json]

역할 :

루틴 단위 예산 관리

위치 :

_루틴명/budget.json

기본 구조 :

{
  "routine": "MACD",
  "total_budget": 1000000,
  "used_budget": 0,
  "available_budget": 1000000,
  "reserved_order_budget": 0,
  "daily_realized_pnl": 0,
  "daily_loss_limit_percent": -3,
  "updated_at": "2026-05-31 09:00:00"

규칙 :

1. 예산은 루틴 단위로 관리한다.

2. 동일 루틴에 등록된 종목 전체가 해당 루틴 예산을 공유한다.

3. 주문 요청 중인 금액은 reserved_order_budget 으로 임시 차감한다.

4. 체결 완료 시 reserved_order_budget 에서 used_budget 으로 반영한다.

5. 주문 취소 또는 거부 시 reserved_order_budget 을 복원한다.

6. 예산 부족 시 신규 매수를 거부한다.

7. 예산 부족 메시지를 GUI 팝업으로 출력한다.

8. 예산 부족 내역은 로그에 기록한다.

9. 루틴별 예산은 메인 윈도우 루틴 목록에 표시한다.

## [검색식 등록 정책]

1. 키움 HTS에 사용자가 미리 생성한 "자동매매" 검색식을 호출한다.

2. 검색식 결과 종목을 기초종목.txt 에 등록한다.

3. 이미 등록된 종목은 중복 등록하지 않는다.

4. 종목코드와 종목명이 유효하지 않은 경우 등록하지 않는다.

5. 등록 완료 종목 수를 GUI 팝업으로 출력한다.

6. 중복 제외 종목 수를 GUI 팝업으로 출력한다.

7. 오류 종목 수를 GUI 팝업으로 출력한다.

8. 등록 결과는 PROJECT_CHANGELOG.txt 에 기록한다.

---

## [수동등록 정책]

1. 사용자는 종목코드와 종목명을 GUI 입력창에 직접 입력할 수 있다.

2. 입력 형식은 종목코드, 종목명이다.

3. 여러 종목은 등록 예정 목록에 추가 후 일괄 등록할 수 있다.

4. 동일 종목코드가 기초종목.txt 에 이미 존재하면 등록하지 않는다.

5. 동일 종목명이 기초종목.txt 에 이미 존재하면 등록하지 않는다.

6. 중복 항목은 "중복항목입니다" 팝업을 표시한다.

7. 등록 결과는 PROJECT_CHANGELOG.txt 에 기록한다.

---

## [매매루틴 지정 정책]

1. 기초종목.txt 에 등록된 종목만 매매루틴에 지정할 수 있다.

2. 동일 종목은 여러 매매루틴에 등록할 수 있다.

3. 동일 종목이 동일 매매루틴에 중복 등록되는 것은 금지한다.

4. 매매루틴 지정 시 기초종목.txt 의 해당 종목 행에 루틴명을 추가한다.

5. 동시에 해당 루틴 폴더 아래에 종목별 폴더를 생성한다.

6. 종목별 폴더명은 종목코드_종목명 형식으로 한다.

7. 이미 등록된 루틴은 GUI에서 체크된 상태로 표시한다.

8. 종목별 폴더 생성 시 config.json, state.json, orders.json, logs 폴더를 함께 생성한다.

9. 루틴 지정 결과는 PROJECT_CHANGELOG.txt 에 기록한다.

## [무결성 검증 정책]

1. 기초종목.txt 의 종목코드와 종목명을 키움 API 기준 실제 종목 정보와 비교한다.

2. 루틴 폴더 내 종목 폴더와 기초종목.txt 의 루틴 등록 정보를 비교한다.

3. 불일치 항목을 즉시 삭제하지 않는다.

4. 먼저 불일치 목록을 GUI 표로 출력한다.

5. invalid_items.log 에 기록한다.

6. 사용자 확인 후 삭제 또는 격리한다.

7. 삭제 또는 격리 결과를 PROJECT_CHANGELOG.txt 에 기록한다.

검증 대상 :

1. 기초종목.txt 중복 종목

2. 기초종목.txt 종목코드 오류

3. 기초종목.txt 종목명 오류

4. 루틴 폴더에는 있으나 기초종목.txt 에 없는 종목

5. 기초종목.txt 에는 있으나 루틴 폴더에 없는 종목

6. 종목 폴더명 형식 오류

7. 필수 파일 누락

필수 파일 :

config.json

state.json

orders.json

logs

## [중복 주문 방지 정책]

1. 동일 종목, 동일 루틴, 동일 봉에서는 매수 주문을 1회만 허용한다.

2. 동일 종목, 동일 루틴, 동일 봉에서는 매도 주문을 1회만 허용한다.

3. 주문 요청 후 체결, 취소, 거부, 실패 중 하나가 확정되기 전까지 추가 주문을 금지한다.

4. pending_order 가 true 인 경우 신규 주문을 발생시키지 않는다.

5. 마지막 신호 발생 봉 시간은 state.json 의 last_signal_candle_time 에 기록한다.

6. 마지막 주문 발생 봉 시간은 state.json 의 last_order_candle_time 에 기록한다.

7. 중복 주문 차단 내역은 로그에 기록한다.

8. 중복 주문 차단이 반복 발생하면 GUI 상태에 경고 표시한다.

## [추가매수 제한 정책]

2. 현재가가 직전 매수가보다 높으면 추가매수하지 않는다.

3. 기본값은 추가매수 금지이다.

4. config.json 의 allow_higher_rebuy 값이 true 인 경우에만 예외적으로 허용한다.

5. allow_higher_rebuy 기본값은 false 이다.

## [매매 세트 상태 정책]

상태값 :

WAIT_BUY

BUY_ACTIVE

WAIT_SELL

SELL_DONE

흐름 :

WAIT_BUY → BUY_ACTIVE → WAIT_SELL → SELL_DONE → WAIT_BUY

규칙 :

1. 보유수량이 없는 상태에서는 매도신호를 무시한다.

2. 매도 완료 후 다음 매수신호가 나오기 전까지 매도신호를 무시한다.

3. 매수 발생 시 새로운 매매 세트를 시작한다.

4. 매도 발생 시 현재 매매 세트를 종료한다.

5. 현재 매매 세트 번호는 state.json 의 current_set_no 에 기록한다.

6. 매도신호 무시 상태는 state.json 의 ignore_sell_until_next_buy 에 기록한다.

7. 매매 세트 상태는 자동매매설정 창에 표시한다.

## [매수 회차]

최대 매수 회차는 사용자 설정값 max_buy_count 를 사용한다.

예)

1회

3회

5회

10회

설정 가능.

매수 회차 증가 방식은 buy_amount_mode 를 따른다.

ADD :

기준 금액 또는 수량에 지정값을 더한다.

MULTIPLY :

기준 금액 또는 수량에 지정 배수를 곱한다.

FIBONACCI :

피보나치 수열 기준으로 증가한다.

CUSTOM :

buy_amount_custom_steps 에 입력된 사용자 지정값을 사용한다.

CUSTOM 규칙 :

1. 입력값은 증가 연산자와 숫자 목록으로 구성한다.

2. 예: +1,2,5,8,9

3. 설정된 증가값 개수가 max_buy_count 보다 적으면 마지막 값을 반복 적용한다.

4. 설정된 증가값 개수가 max_buy_count 보다 많으면 max_buy_count 까지만 적용한다.

규칙 :

2. 매수 평단에서 거래세 및 매도 비용을 제외하고 profit_hold_percent 이하이면 매도하지 않는다.

3. 매도하지 않은 경우 HOLD 상태로 기록한다.

4. 이후 재매도 조건은 resell_condition 을 따른다.

resell_condition :

NEXT_SELL_SIGNAL :

AVG_PRICE_PROFIT :

평단 대비 resell_profit_percent 이상 상승 시 매도한다.

8. 루틴 폴더 내 종목 폴더 삭제 또는 격리

9. PROJECT_CHANGELOG.txt 기록

주의 :

로그 파일은 원칙적으로 삭제하지 않는다.

삭제 대상 종목 폴더는 즉시 삭제보다 격리를 우선한다.

ADD

FIX

DOC

## [화면번호 정책]

화면번호는 4자리 문자열로 관리한다.

범위 :

1000 ~ 1999 : 로그인 / 계좌 / 예수금

2000 ~ 2999 : 조건검색

3000 ~ 3999 : 일봉 / 분봉 조회

4000 ~ 4999 : 실시간 시세

5000 ~ 5999 : 주문 / 체결

9000 ~ 9999 : 관리자 GUI 기능

규칙 :

1. 동일 화면번호 중복 사용 금지.

2. 화면번호 사용 이력은 screen_registry.json 에 기록한다.

3. 화면번호 충돌 발생 시 신규 요청을 거부한다.

## [실계좌 전환 안전장치]

실계좌 모드는 기본 비활성화한다.

실계좌 전환 조건 :

1. 모의투자 계좌에서 최소 20거래일 이상 테스트

2. 로그인 검증 완료

3. 실시간 수신 검증 완료

4. 매수 검증 완료

5. 매도 검증 완료

6. 부분체결 검증 완료

7. 상태복구 검증 완료

8. 일 손실 제한 검증 완료

9. 주문 중복 방지 검증 완료

10. 사용자 수동 승인

실계좌 실행 승인 문구 :

실계좌 자동매매 시작 승인

규칙 :

1. 실계좌 승인 창에서 사용자가 위 문구를 정확히 입력해야 한다.

2. 문구가 일치하지 않으면 실계좌 자동매매를 시작하지 않는다.

3. 실계좌 승인 실패는 system_error.log 에 기록한다.

4. 실계좌 시작 내역은 PROJECT_CHANGELOG.txt 에 기록한다.

5. 실계좌 모드에서는 메인 윈도우 상단에 경고 문구를 항상 표시한다.
