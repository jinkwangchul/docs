MASTER_SPEC 누락보강 28
주제 : 완료정책 및 후속 정책 설계 원칙

1. 목적
완료정책은 주문 종료 여부만 판단하는 기능이 아니라, 매수·매도 계획 종료 이후의 처리 흐름을 정의한다.

2. 기본 철학
- 완료와 종료는 동일한 의미가 아니다.
- 완료 이후에도 후속 정책이 존재할 수 있다.
- 후속 정책은 루틴이 결정하고 메인은 수행한다.

3. 완료 판단
- 목표 조건 충족
- 반복 종료 조건 충족
- 미체결 정책 종료
- 루틴 종료 조건 충족

4. 후속 정책
① 다음 신호 대기
② 보유잔량 시장가 처리
③ 검토관리 전환
④ 루틴 종료
⑤ 후속 루틴 연계(향후)

5. 연계 규칙
- 반복이탈조건 미사용 → 다음신호로 이월
- 반복이탈조건 사용 → 보유잔량시장가매도
- 완료정책은 반복이탈조건 결과를 따른다.

6. 책임 분리
UI : 정책 입력
루틴 : 완료 판단
메인 : 주문 및 상태 반영

7. 구현 원칙
- 완료정책은 독립 정책으로 유지
- 미체결정책과 역할을 혼합하지 않는다.
- 공통 상태제어와 저장 구조를 사용한다.

8. 검증 항목
□ 완료 조건
□ 후속 정책 선택
□ 상태 변경
□ UI 표시
□ JSON 저장
□ 엔진 연계

9. 향후 보강
- 완료 상태전이도
- 후속 정책 우선순위
- 정책 충돌 처리
- 엔진 매핑

10. 결론
완료정책은 실행 종료가 아니라 다음 단계로 연결하기 위한 정책이며,
프로젝트 전체의 후속 흐름을 일관되게 관리하는 기준이 된다.
