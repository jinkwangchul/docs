MASTER_SPEC 누락보강 71
주제 : 히스토리 기반 BUY PLAN 상태 표시 및 운영 상태 관리 기준

출처 : 작업진행상황대화히스토리_3~8 비교 반영

1. 목적
BUY PLAN의 내부 진행 상태와 운영자가 확인하는 상태를 명확히 구분하기 위한
공통 기준을 정의한다.

2. 기본 원칙
- 내부 처리 상태와 화면 표시 상태를 혼용하지 않는다.
- 상태는 BUY PLAN 생명주기를 그대로 반영한다.

3. 내부 상태
- BUY PLAN 생성
- 주문 진행
- 부분 체결
- 매수 미완성
- 완료
- 실패
- 종료

4. 운영 표시
운영 화면은 내부 상태를 그대로 노출하는 것이 아니라
운영상 필요한 의미로 표시한다.

5. 상태 변경 기준
- 체결 발생 시 즉시 갱신
- 재매수 수행 시 진행 상태 유지
- 목표 달성 시 완료
- 유효조건 종료 후 정책 완료 시 종료

6. 구현 원칙
- 상태 변경은 단일 관리 지점에서 수행한다.
- 동일 이벤트로 복수 상태를 동시에 생성하지 않는다.
- 상태 변경 이력을 기록한다.

7. 검증 항목
□ 생성
□ 진행
□ 부분 체결
□ 미완성
□ 완료
□ 종료
□ 상태 기록 일치

8. 반영 원칙
본 기준은 히스토리에서 확정된 BUY PLAN 상태 관리 원칙이며,
향후 모든 루틴의 상태 관리 표준으로 적용한다.
