MASTER_SPEC 누락보강 77
주제 : 히스토리 기반 PLAN 공통 상태 머신(State Machine) 설계 원칙

출처 : 작업진행상황대화히스토리_3~8 비교 반영

1. 목적
모든 PLAN(BUY/SELL)이 동일한 상태 전이 규칙을 따르도록 공통 상태 머신 설계 원칙을 정의한다.

2. 기본 철학
- PLAN은 상태 머신으로 관리한다.
- 모든 상태 전이는 명확한 이벤트를 통해서만 발생한다.
- 임의 상태 변경을 허용하지 않는다.

3. 공통 상태
- CREATED
- IN_PROGRESS
- PARTIAL_FILLED
- COMPLETED
- INCOMPLETE
- FAILED
- CANCELED
- CLOSED

4. 상태 전이 원칙
- 생성 → 진행
- 진행 → 부분체결
- 진행/부분체결 → 완료
- 진행/부분체결 → 미완성
- 미완성 → 완료 또는 실패 또는 취소
- 완료/실패/취소 → 종료

5. 이벤트 기준
- 신호 발생
- 주문 접수
- 체결
- 부분 체결
- 재시도
- CANCEL
- 유효조건 종료
- 운영 종료

6. 구현 원칙
- 하나의 이벤트는 하나의 상태 전이만 수행한다.
- 종료 상태에서는 추가 전이를 허용하지 않는다.
- 상태 전이는 로그와 함께 기록한다.

7. 검증 항목
□ 상태 전이 순서
□ 중복 전이 방지
□ 종료 상태 고정
□ 이벤트-상태 일치
□ 로그 일치

8. 반영 원칙
본 기준은 히스토리에서 확정된 PLAN 기반 상태 머신 설계 철학이며,
향후 모든 자동매매 루틴의 공통 상태 관리 기준으로 적용한다.
