MASTER_SPEC_추가갱신_프로젝트_구성요소의존성맵_Component_Dependency_Map_2026-07-03

목적
- 프로젝트의 주요 구성요소 간 의존 관계를 정의하고 허용되는 호출 방향을 명확히 한다.

==================================================
1. 최상위 계층
==================================================
GUI
↓
Controller
↓
Engine / Policy
↓
Runtime
↓
Boundary
↓
Kiwoom OpenAPI

==================================================
2. 허용되는 의존 방향
==================================================
GUI → Controller
Controller → Engine
Controller → Runtime
Controller → Boundary
Engine → Runtime(Read)
Boundary → OpenAPI

==================================================
3. 금지되는 의존 방향
==================================================
Engine → GUI
Engine → Boundary
Runtime → Controller
Runtime → GUI
Boundary → Engine 정책 판단
GUI → OpenAPI 직접 호출

==================================================
4. Runtime 의존
==================================================
routine_signals
↓
order_queue
↓
real_trade_guard
↓
order_execution(예정)
↓
fills(예정)
↓
positions(예정)
↓
review(예정)
↓
audit(예정)

==================================================
5. 변경 영향
==================================================
Controller 변경
→ Engine
→ Runtime
→ 테스트

Runtime 변경
→ Controller
→ Recovery
→ Audit

Boundary 변경
→ Execution
→ OpenAPI 연동
→ 운영 검증

==================================================
최종 원칙
의존성은 항상 상위에서 하위로만 흐르며,
역방향 의존이나 순환 의존은 허용하지 않는다.
