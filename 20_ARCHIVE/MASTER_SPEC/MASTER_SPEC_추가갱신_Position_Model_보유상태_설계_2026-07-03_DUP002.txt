MASTER_SPEC_추가갱신_Position_Model_보유상태_설계_2026-07-03

목적
- 본 문서는 체결(Fill) 결과를 기반으로 내부 Position(보유상태)을 관리하기 위한 기준을 정의한다.
- Position은 주문(Order)이 아니라 체결(Fill)의 결과이며, Recovery·검토관리·청산의 기준 데이터이다.

1. 기본 원칙
- Position은 Fill 결과로만 생성·변경된다.
- SendOrder 성공만으로 Position을 변경하지 않는다.
- 부분체결은 누적 반영한다.
- Kiwoom 잔고와 내부 Position은 주기적으로 비교한다.

2. 생성 흐름
Signal
→ Order
→ Execution
→ Kiwoom Order
→ Fill
→ Position

3. Position 핵심 필드
- position_id
- code
- name
- holding_qty
- available_qty
- avg_price
- total_buy_amount
- realized_pnl
- unrealized_pnl
- source_order_ids
- source_fill_ids
- updated_at
- verified_by_kiwoom

4. 변경 규칙
매수 Fill:
- holding_qty 증가
- avg_price 재계산
- total_buy_amount 갱신

매도 Fill:
- holding_qty 감소
- realized_pnl 갱신
- holding_qty가 0이면 Position 종료 후보

5. Position과 Kiwoom 잔고
정기 비교 항목
- 보유수량
- 가용수량
- 평균단가
- 종목코드

불일치 시 자동 수정하지 않고 검토관리 후보로 분류한다.

6. 청산 연계
청산은 Position 기준으로 수행한다.
Position이 없으면 청산 대상이 아니다.
청산 완료는 Fill 기준으로 확정한다.

7. Recovery
재시작 시 확인 순서
- Position
- Fill
- Kiwoom 잔고
- Order
- Review Management

8. Audit Log
기록 대상
- Position 생성
- Position 변경
- Position 종료
- 서버 검증 결과

9. 금지
- Order만으로 Position 생성
- SendOrder 성공만으로 Position 변경
- 서버 확인 없는 자동 복원
- Position 직접 수정으로 체결 이력 대체

10. 최종 원칙
Position은 실제 보유 사실을 표현하는 엔티티이며,
항상 Fill과 Kiwoom 잔고를 기준으로 관리한다.
