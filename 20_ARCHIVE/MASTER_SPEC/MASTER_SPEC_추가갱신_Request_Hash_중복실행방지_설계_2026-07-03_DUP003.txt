MASTER_SPEC_추가갱신_Request_Hash_중복실행방지_설계_2026-07-03

목적
- 실주문 직전 동일 주문이 반복 실행되는 것을 방지하기 위한 Request Hash 정책을 정의한다.
- 본 문서는 설계 기준이며 구현 문서가 아니다.

1. Request Hash의 역할
- 동일 주문의 중복 SendOrder 방지
- 재시작 후 중복 실행 판별
- Lock과 함께 최종 실행 안전장치 제공

2. 생성 시점
ExecutionController가 Final Execution Guard를 모두 통과한 뒤,
ORDER_QUEUED 생성 직전에 생성한다.

3. 입력 후보
- order_id
- source_signal_id
- code
- side
- quantity
- price
- account_no
- order_type
- hoga

주의:
시간(created_at)은 Hash 구성요소에 포함하지 않는다.
동일 주문은 동일 Hash가 생성되어야 한다.

4. 사용 원칙
- active Request Hash가 존재하면 동일 주문 실행 금지
- Hash 충돌 시 SendOrder 호출 금지
- Lock과 Hash를 함께 확인

5. Runtime 관계
향후 저장 위치 후보
- order_executions.json
- audit_log.jsonl

관계
request_hash
  ↔ execution_id
  ↔ order_id
  ↔ lock_id

6. 재시작 정책
프로그램 재시작 시
- active execution
- active lock
- request_hash
를 함께 확인한다.

불명확하면 자동 재실행하지 않고 검토관리 대상으로 보낸다.

7. 금지
- Candidate 단계 생성
- Approval 단계 생성
- Policy 단계 생성
- Preflight 단계 생성
- Adapter Preview 단계 생성
- GUI 직접 생성
- Timer 직접 생성

8. 향후 구현 순서
1) Request Hash 규격 확정
2) Execution Request 연동
3) Lock 연동
4) Audit Log 기록
5) SendOrder 직전 중복 검사

최종 원칙
Request Hash는 Lock과 함께 실주문 직전의 마지막 중복 실행 방지 기준으로 사용한다.
