MASTER_SPEC_추가갱신_Kiwoom_Boundary_API_경계설계_2026-07-03

목적
- 프로젝트 내부 도메인과 Kiwoom OpenAPI 사이의 경계를 명확히 정의한다.
- 모든 실주문과 서버 통신은 단일 Boundary를 통해서만 수행하는 것을 원칙으로 한다.

1. 기본 원칙
- Domain Engine은 Kiwoom API를 직접 호출하지 않는다.
- GUI는 Kiwoom API를 직접 호출하지 않는다.
- Timer는 Kiwoom API를 직접 호출하지 않는다.
- SendOrder는 KiwoomOrderExecutor만 호출할 수 있다.

2. 계층 구조
GUI / Timer
    ↓
Controller Layer
    ↓
Domain Engine
    ↓
Execution Controller
    ↓
Kiwoom Boundary
    ↓
Kiwoom OpenAPI

3. Boundary 책임
- SendOrder 요청 전달
- TR 요청 전달
- 실시간 등록/해제
- Chejan 이벤트 수신
- API 오류 코드 전달
- 내부 객체 ↔ API 파라미터 변환

4. Domain이 넘기는 정보
- execution_id
- order_id
- source_signal_id
- account_no
- code
- side
- quantity
- price
- order_type
- hoga

5. Boundary가 반환하는 정보
- success/fail
- api_result_code
- api_message
- kiwoom_order_no
- requested_at

6. 금지
- Boundary 내부에서 주문 판단
- 전략 판단
- Approval 수행
- Policy 수행
- Preflight 수행
- Runtime 상태 직접 변경

7. 오류 처리
- API 오류는 그대로 상위에 전달한다.
- Boundary가 자동 재주문하지 않는다.
- 자동 재시도 정책은 Controller에서 결정한다.

8. Recovery 연계
- Recovery는 Boundary를 통해 현재 서버 상태를 조회한다.
- Boundary는 조회 결과만 제공한다.

9. Audit Log
- SendOrder 호출
- TR 요청
- Chejan 수신
- API 오류
를 Audit Log 기록 대상으로 사용한다.

최종 원칙
Kiwoom Boundary는 '외부 시스템과의 통신 계층'이며,
비즈니스 판단은 절대 포함하지 않는다.
