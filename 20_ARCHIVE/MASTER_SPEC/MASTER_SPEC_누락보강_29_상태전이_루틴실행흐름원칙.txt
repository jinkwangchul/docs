MASTER_SPEC 누락보강 29
주제 : 상태전이 및 루틴 실행 흐름 원칙

1. 목적
루틴의 각 상태가 어떤 순서로 전이되는지 정의하여 UI, 저장구조,
루틴 엔진, 메인 엔진이 동일한 흐름을 따르도록 한다.

2. 기본 원칙
- 상태는 항상 순차적으로 전이한다.
- 이전 상태를 건너뛰는 직접 전이는 예외 상황에서만 허용한다.
- 상태 전이는 데이터 기반으로 관리한다.

3. 기본 실행 흐름
대기
→ 신호검출
→ 조건평가
→ BUY/SELL/CANCEL 결정
→ 주문요청
→ 체결대기
→ 후속정책
→ 완료
→ 대기

4. 주문 상태
- 주문대기
- 주문접수
- 부분체결
- 전체체결
- 미체결
- 주문취소
- 종료

5. 루틴 상태
- 비활성
- 대기
- 실행중
- 후속정책 수행
- 완료
- 종료

6. 상태전이 원칙
- 상태 변경은 하나의 공통 관리 계층에서 수행한다.
- UI는 상태를 표시만 한다.
- 루틴은 상태 변경을 요청한다.
- 메인은 실제 상태를 확정한다.

7. 예외 처리
- 데이터 불일치
- 주문 실패
- API 오류
- 재시작
- 긴급정지

예외 발생 시 정상 흐름보다 복구 절차를 우선한다.

8. 검증 항목
□ 상태 누락 여부
□ 중복 전이 여부
□ 무한 반복 여부
□ UI 표시 일치
□ 저장 상태 일치
□ 엔진 상태 일치

9. 향후 보강
- 상태전이 다이어그램
- 예외 전이도
- 복구 시나리오
- 테스트 케이스

10. 결론
상태전이는 프로젝트 전체에서 하나의 공통 규칙으로 관리하며,
모든 루틴은 동일한 상태 흐름을 기반으로 동작한다.
