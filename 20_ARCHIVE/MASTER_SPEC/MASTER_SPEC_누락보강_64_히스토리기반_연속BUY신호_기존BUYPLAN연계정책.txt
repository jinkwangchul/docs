MASTER_SPEC 누락보강 64
주제 : 히스토리 기반 연속 BUY 신호 처리 및 기존 BUY PLAN 연계 정책

출처 : 작업진행상황대화히스토리_3~8 비교 반영

1. 목적
BUY PLAN이 진행 중인 상태에서 새로운 BUY 신호가 발생하는 경우의
처리 원칙을 표준화한다.

2. 기본 원칙
- 연속 BUY 신호가 발생하더라도 즉시 새로운 BUY PLAN을 생성하지 않는다.
- 기존 BUY PLAN의 상태를 먼저 확인한다.

3. 처리 절차
① 기존 BUY PLAN 존재 여부 확인
② 완료 여부 확인
③ 미완성 여부 확인
④ 루틴 정책에 따른 처리 결정

4. 미완성 상태 처리
기존 BUY PLAN이 미완성 상태인 경우에는
루틴에서 정의한 정책에 따라 기존 계획을 연장하거나 갱신한다.

5. 완료 상태 처리
기존 BUY PLAN이 완료된 경우에는
새로운 BUY 신호에 대해 새로운 BUY PLAN을 생성할 수 있다.

6. 역할 분리
루틴
- 연속 BUY 허용 정책
- 기존 계획 연계 기준
- 새 계획 생성 조건

메인
- BUY PLAN 상태 관리
- 주문 실행
- 체결 결과 반영

7. 구현 원칙
- 동일 종목에 중복 BUY PLAN을 무분별하게 생성하지 않는다.
- 기존 계획과의 관계를 우선 판단한다.
- 루틴 정책과 메인 실행 책임을 분리한다.

8. 반영 원칙
본 정책은 히스토리에서 확정된 연속 BUY 처리 철학이며,
향후 모든 루틴의 공통 BUY PLAN 운영 기준으로 적용한다.
