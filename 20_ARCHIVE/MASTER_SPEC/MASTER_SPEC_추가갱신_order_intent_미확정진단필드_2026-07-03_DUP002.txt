MASTER_SPEC_추가갱신_order_intent_미확정진단필드_2026-07-03

작성 목적
- 본 문서는 주문 후보 생성 단계에서 추가된 order_intent 필드의 의미, 현재 범위, 금지사항, 향후 확장 방향을 MASTER_SPEC에 반영하기 위한 추가 갱신자료이다.
- order_intent는 현재 주문방식 확정값이 아니라, 주문방식이 아직 확정되지 않았음을 명시하는 진단 필드이다.
- hoga/order_type 확정, UI state 매핑, Adapter/Executor/SendOrder 연결은 아직 수행하지 않는다.

==================================================
1. 배경
==================================================

현재 주문 파이프라인은 Adapter Request Preview까지 안전하게 구성되었으나, 실제 키움 주문 요청으로 넘어가기 전 핵심 미완성 항목이 남아 있다.

미완성 항목:
- hoga 확정
- order_type 확정
- UI 주문방식과 order_queue 후보 연결
- BUY/SELL별 주문방식 출처 추적
- sell setting_a/b/c 출처 식별
- 실제 SendOrder 입력값 매핑

기존 구조에서는 order_queue 후보가 side, quantity, price 등 기본 정보는 가지고 있었지만,
주문방식이 왜 확정되지 않았는지 설명하는 필드가 없었다.

따라서 order_intent를 추가하여 주문 후보가 자기 자신의 주문방식 미확정 상태를 명시하도록 한다.

==================================================
2. 현재 구현 범위
==================================================

변경 파일:
- order_candidate_engine.py
- tests/test_order_queue_approval_scenarios.py

추가 helper:
- build_order_intent_for_candidate(side, candidate)

적용 대상:
- build_buy_candidate()
- build_sell_candidate()

추가 필드:
- order_intent

현재 order_intent는 BUY/SELL 후보 생성 결과에 포함된다.
직접 build_buy_candidate() / build_sell_candidate() 호출 결과에도 order_intent와 execution_enabled=False가 붙도록 보강되었다.

==================================================
3. order_intent의 현재 의미
==================================================

order_intent는 현재 “확정 주문 지시”가 아니다.

현재 의미:
- 이 주문 후보의 주문방식 출처가 아직 확정되지 않았음을 표시한다.
- UI state/rules.json을 아직 읽지 않았음을 표시한다.
- hoga/order_type이 아직 실주문용으로 확정되지 않았음을 표시한다.
- 향후 UI state 매핑을 붙일 때 확장할 위치를 확보한다.

즉 order_intent는 현재 진단 메타데이터이다.

==================================================
4. BUY order_intent 구조
==================================================

BUY 예시:

{
  "side": "BUY",
  "source": "order_candidate_engine",
  "budget_source": "entry_amount",
  "price_basis": "latest_price",
  "source_ui_path": null,
  "unresolved": true
}

필드 의미:
- side: BUY
- source: order_candidate_engine에서 생성됨
- budget_source: 수량/금액 산출 근거
- price_basis: 가격 기준 근거
- source_ui_path: 현재는 알 수 없으므로 null
- unresolved: UI 주문방식이 아직 확정되지 않았으므로 true

현재 BUY는 config/state/latest_price 기반 후보 산출만 수행한다.
indicator_follow_ui_state.buy_ui.base는 아직 읽지 않는다.

==================================================
5. SELL order_intent 구조
==================================================

SELL 예시:

{
  "side": "SELL",
  "source": "order_candidate_engine",
  "holding_source": "REAL_OR_STATE_HOLDING",
  "price_basis": "latest_price",
  "source_ui_path": null,
  "unresolved": true
}

필드 의미:
- side: SELL
- source: order_candidate_engine에서 생성됨
- holding_source: 매도 가능 수량 산출 근거
- price_basis: 가격 기준 근거
- source_ui_path: 현재는 알 수 없으므로 null
- unresolved: sell setting_a/b/c 출처가 아직 신호 payload에 없으므로 true

현재 SELL은 보유수량/가용수량 기준 후보 산출만 수행한다.
sell_ui.setting_a/b/c 중 어느 주문방식에서 온 신호인지는 아직 알 수 없다.

==================================================
6. source_ui_path 정책
==================================================

source_ui_path는 정확히 알 수 있을 때만 채운다.

현재 정책:
- 정확하지 않으면 null.
- 추정으로 buy_ui.base를 넣지 않는다.
- 추정으로 sell_ui.setting_a/b/c를 넣지 않는다.
- sell signal payload에 setting_a/b/c 출처가 없으면 null 유지.
- “아는 척” 경로를 넣는 행위 금지.

향후 source_ui_path 후보:
- indicator_follow_ui_state.state.buy_ui.base
- indicator_follow_ui_state.state.sell_ui.setting_a
- indicator_follow_ui_state.state.sell_ui.setting_b
- indicator_follow_ui_state.state.sell_ui.setting_c

단, 향후에도 실제 신호 payload 또는 명확한 매핑 근거가 있어야 한다.

==================================================
7. unresolved 정책
==================================================

현재 기본값:
- unresolved=true

의미:
- 주문방식 확정 불가
- UI state 미연결
- hoga/order_type 미확정
- source_ui_path 미확정

향후 unresolved=false가 되려면 아래 조건이 필요하다.

- UI state 또는 rules 기반 주문방식 출처 확인
- source_ui_path 확정
- method_type 확정
- price_mode 확정
- hoga_mode 확정
- order_type/hoga 매핑 가능
- sell의 경우 setting_a/b/c 출처 확인

현재 단계에서는 unresolved=false를 만들지 않는다.

==================================================
8. order_type / hoga 정책
==================================================

현재 order_type:
- 기존 값 유지
- 대부분 UNDECIDED 또는 기존 후보 정책 유지

현재 hoga:
- 확정하지 않음

금지:

- 한글 combo text를 바로 키움 hoga code로 매핑 금지
- SendOrder 입력값으로 사용 금지

11. 기존 파이프라인과의 관계
==================================================

order_intent는 기존 상태 전이에 영향을 주지 않는다.

영향 없음:
- PENDING -> APPROVED/BLOCKED
- APPROVED -> EXECUTABLE/BLOCKED_POLICY
- EXECUTABLE -> REAL_READY/BLOCKED_REAL
- REAL_READY -> Adapter Request Preview
- execution_enabled
- real_trade_guard
- SendOrder
- Adapter/Executor 연결

order_intent는 현재 진단 메타데이터이므로 approval/preflight/adapter가 무시해도 된다.

14. 최종 결론
==================================================

order_intent는 현재 주문방식 확정값이 아니다.

order_intent는 주문 후보가 아직 hoga/order_type/UI 출처를 확정하지 못했다는 사실을 명시하는 진단 필드이다.

이 필드는 향후 UI state 기반 주문방식 매핑을 안전하게 연결하기 위한 준비 단계이다.

현재 단계에서 가장 중요한 원칙은 다음과 같다.

정확히 알면 나중에 확정한다.
정확히 모르면 unresolved=true로 남긴다.
추정값을 실주문 입력으로 사용하지 않는다.
