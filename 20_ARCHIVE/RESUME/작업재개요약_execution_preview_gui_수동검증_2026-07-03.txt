2. 이번 단계 추가/확인 파일
==================================================

1) order_hoga_mapper.py
- map_order_hoga_preview(order)
- order_intent의 호가 의도를 내부 표준값으로 preview 변환
- 시장가 -> MARKET
- 지정가/현재가 -> LIMIT
- 미확정/빈값/알 수 없는 값 -> unresolved=True
- Kiwoom OpenAPI 코드값 직접 매핑 없음

2) order_type_mapper.py
- map_order_type_preview(order)
- order_intent의 매수/매도 의도를 내부 표준값으로 preview 변환
- BUY/매수 -> BUY
- SELL/매도 -> SELL
- 빈값/미확정/알 수 없는 값/숫자 코드값 -> unresolved=True
- Kiwoom 주문유형 코드 매핑 없음

3) execution_controller.py
- build_execution_preview(order, guard=None)
- REAL_READY 상태 확인
- Hoga Mapper 호출
- OrderType Mapper 호출
- guard가 dict이면 adapter request preview builder 사용 가능 여부 확인
- ok=True는 실제 주문 가능이 아니라 preview 입력 해소 의미

4) final_execution_guard.py
- evaluate_final_execution_guard(order, guard, execution_preview)
- 최종 실행 직전 조건을 순수 판정
- 검사 조건:
  - order.status == REAL_READY
  - order.execution_enabled == true
  - guard.operator_confirmed == true
  - guard.real_trade_enabled == true
  - hoga_preview.unresolved == false
  - order_type_preview.unresolved == false
  - execution_preview.unresolved == false

5) order_lock_manager.py
- build_order_lock_preview(order, execution_preview)
- lock_key, lock_id 후보만 메모리 dict로 생성
- runtime/order_locks.json 생성 또는 저장 없음

6) order_request_hash.py

- canonical JSON 기반 SHA-256 stable hash 후보 생성
- 필수 후보 필드:
  - order_id
  - source_signal_id
  - code
  - side/order_type
  - quantity
  - price
  - hoga
  - lock_id

7) order_execution_request.py
- build_execution_request_preview(...)

- runtime/order_executions.json 생성 없음

8) execution_pipeline_controller.py
- run_execution_preview_pipeline(order, guard)
- 호출 순서:
  1. build_execution_preview
  2. evaluate_final_execution_guard
  3. build_order_lock_preview
  4. build_order_request_hash_preview
  5. build_execution_request_preview
- 첫 차단 지점을 blocked_stage로 반환
- 모든 단계 결과를 pipeline dict에 포함

9) execution_pipeline_summary.py

5. 현재 구조적 의미
==================================================

현재 프로젝트는 REAL_READY order 1건에 대해 SendOrder 직전까지의 실행 준비 상태를 단일 service 호출로 검증할 수 있다.

실제 가능한 흐름:

order_id 입력
  -> order_queue.json에서 REAL_READY order 읽기
  -> real_trade_guard.json 읽기 전용 로드
  -> Execution Preview Pipeline 실행
  -> Summary 생성
  -> Reporter text 생성
  -> GUI 다이얼로그 표시

이 흐름은 실제 주문을 하지 않으며, 운영자가 SendOrder 전 상태를 눈으로 검증하기 위한 Preview 전용 흐름이다.
