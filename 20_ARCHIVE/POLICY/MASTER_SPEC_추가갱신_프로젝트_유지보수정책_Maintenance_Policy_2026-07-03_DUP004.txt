MASTER_SPEC_추가갱신_프로젝트_유지보수정책_Maintenance_Policy_2026-07-03

목적
- 프로젝트가 장기간 개발·운영되는 동안 일관된 유지보수 기준을 정의한다.

1. 유지보수 범위
- 버그 수정
- 성능 개선
- 구조 개선
- 기능 확장
- 문서 갱신

2. 유지보수 원칙
- 기존 아키텍처를 우선 존중한다.
- 구조 변경보다 원인 분석을 먼저 수행한다.
- 임시 코드 대신 구조적 해결을 우선한다.

3. 변경 절차
① 문제 재현
② 원인 분석
③ 영향 범위 확인
④ 수정
⑤ 단위 테스트
⑥ 회귀 테스트
⑦ 문서 갱신

4. 호환성
- Runtime 포맷 변경은 최소화한다.
- 상태값 변경은 State Machine 검토 후 적용한다.
- ID 체계는 유지한다.

5. 기술 부채 관리
- 임시 구현은 추적 가능해야 한다.
- TODO는 담당 이유와 제거 조건을 남긴다.
- 장기 미해결 항목은 별도 관리한다.

6. 유지보수 금지
- 원인 분석 없는 수정
- 테스트 없는 수정
- 문서 없는 구조 변경
- Runtime 직접 편집으로 문제 해결

7. 유지보수 완료 기준
□ 문제 재현 완료
□ 원인 확인
□ 수정 완료
□ 테스트 통과
□ 회귀 이상 없음
□ 문서 갱신 완료

최종 원칙
유지보수는 기존 기능을 유지하면서 안정성을 높이는 과정이며,
단기 편의보다 장기 일관성을 우선한다.
