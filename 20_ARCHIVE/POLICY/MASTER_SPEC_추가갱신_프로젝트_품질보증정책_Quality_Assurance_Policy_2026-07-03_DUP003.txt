MASTER_SPEC_추가갱신_프로젝트_품질보증정책_Quality_Assurance_Policy_2026-07-03

목적
- 프로젝트의 품질을 일관된 기준으로 유지하기 위한 품질보증(QA) 정책을 정의한다.

1. 품질 목표
- 기능 정확성
- 상태 일관성
- Runtime 무결성
- 실주문 안전성
- 복구 가능성
- 추적 가능성

2. 품질 검증 대상
□ State Machine
□ Runtime 파일
□ Controller 호출 순서
□ Engine 판단 결과
□ Guard 정책
□ Review 정책
□ Recovery 정책

3. 구현 완료 전 확인
- 단위 테스트 통과
- 회귀 테스트 통과
- Preview 검증 완료
- Runtime 부작용 없음
- 문서 갱신 완료

4. Runtime 품질
- JSON 구조 유지
- ID 참조 무결성 유지
- 손상 데이터 자동 정상화 금지

5. 운영 품질
- 실주문은 단일 진입점 유지
- 검토관리 우회 금지
- Recovery 검증 생략 금지

6. 품질 지표
- 테스트 성공 여부
- 회귀 실패 여부
- Runtime 오류 여부
- 상태 전이 오류 여부
- 검토관리 발생 건수

7. 품질 저하로 판단하는 사례
- 테스트 없이 병합
- Runtime 직접 수정
- Preview에서 상태 변경
- Controller 우회
- 책임 혼합

최종 원칙
품질은 구현 완료 후 확인하는 절차가 아니라,
설계·구현·테스트 전 과정에서 지속적으로 유지되어야 한다.
