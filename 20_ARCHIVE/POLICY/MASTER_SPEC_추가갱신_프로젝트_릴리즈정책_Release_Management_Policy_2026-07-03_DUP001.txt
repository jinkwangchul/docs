MASTER_SPEC_추가갱신_프로젝트_릴리즈정책_Release_Management_Policy_2026-07-03

목적
- 기능 개발부터 배포(릴리즈)까지의 절차와 승인 기준을 정의한다.

1. 릴리즈 단계
1) 개발 완료
2) 단위 테스트
3) 회귀 테스트
4) Preview 검증
5) 문서 갱신
6) 릴리즈 후보(RC)
7) 최종 승인
8) 운영 반영

2. 릴리즈 조건
□ 구현 완료
□ Definition of Done 충족
□ 테스트 전략 충족
□ Runtime 영향 확인
□ 변경관리 절차 완료
□ 위험관리 검토 완료
□ 품질보증 기준 충족

3. 릴리즈 제외 대상
- 미완성 기능
- 임시 코드
- 디버그 코드
- 실험 기능
- 테스트 전용 기능

4. 긴급 수정
- 원인 기록
- 최소 범위 수정
- 회귀 테스트 수행
- 문서 갱신

5. 버전 관리
- 기능 단위로 버전 증가
- Runtime 구조 변경은 별도 기록
- 구조 변경은 ADR 및 MASTER_SPEC와 함께 관리

6. 금지
- 테스트 없는 릴리즈
- 문서 없는 구조 변경 배포
- Preview 검증 없는 실주문 관련 배포

최종 원칙
릴리즈는 개발 완료가 아니라,
검증·문서화·승인이 완료된 상태를 의미한다.
