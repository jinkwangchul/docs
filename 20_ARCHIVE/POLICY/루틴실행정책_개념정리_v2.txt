# 루틴 실행정책 개념정리 v2

작성 목적:
- MACD 오실레이터 루틴을 시작점으로 하되, 볼린저밴드/엔벨로프/RSI 등 다른 루틴에서도 재사용 가능한 실행정책 구조를 정의한다.
- 메인파트는 고정 실행 행동을 담당하고, 루틴은 기법별 신호와 실행정책을 담당한다.
- v2에서는 execution_policy.json을 추가하여 BUY/SELL/CANCEL 신호가 실제 주문 행동으로 변환되는 공통 실행 계층을 분리한다.

1. 기본 역할 분리

메인파트:
- BUY 수신 시 매수 주문 실행
- SELL 수신 시 매도 주문 실행
- CANCEL 수신 시 주문취소 실행
- 체결/미체결 추적
- 잔고/평단/현재가/호가 조회
- 검토관리, 조기마감, 자동마감, 청산, 긴급정지 등 시스템 운영정책 처리

루틴파트:
- BUY / SELL / CANCEL 신호 판단
- 단일가격, 다중호가, 단일지점, 다중지점 조합 결정
- 미체결 대응 조건 판단
- 루틴별 실행정책 커스터마이징

2. BUY / SELL / CANCEL 정체성

BUY:
- 포지션 구축 또는 확대 신호

SELL:
- 포지션 축소 또는 청산 신호

CANCEL:
- 루틴 입장에서는 신호
- 메인 입장에서는 주문취소 행동
- 미체결 주문을 정리하고 재 BUY 또는 재 SELL로 이어가기 위한 실행정책 신호

3. 매수/매도 실행축

가격축:
- 단일가격
- 다중호가

시간축:
- 단일지점
- 다중지점

가능 조합:
- 단일가격 + 단일지점
- 단일가격 + 다중지점
- 다중호가 + 단일지점
- 다중호가 + 다중지점

4. 다중호가 개념

다중호가는 가격의 종축 개념이다.
BUY 또는 SELL 신호 시 여러 호가에 주문을 배치하여 순간 파동 속에서 체결 효율을 높이는 기법이다.

5. 다중지점 개념

다중지점은 시간의 횡축 개념이다.
다음 BUY/SELL 신호를 기다리는 것이 아니라, 최초 메인 신호 발생 이후 특정 시간 또는 봉 안에서 해당 신호 가격에 최대한 근접하거나 더 유리한 가격에 체결되도록 실행 효율을 높이는 기법이다.

다중지점은 평단관리 그 자체가 아니라, 메인 검출신호에 따른 매수/매도 행위의 오차를 줄이는 실행 고도화 기술이다.

6. 평단 기준

평단은 키움 서버의 전체 보유 평단을 우선 사용한다.
프로그램 내부 평단은 보조 검증용으로 사용한다.
평단과 현재가의 비교가 원인 조건이며, 손익률은 그 결과 표시값이다.

7. 미체결 대응

미체결은 즉시 실패가 아니다.
미체결 발생 시 시간 제한, 봉 제한 등을 우선 확인한다.
가격 상승 이탈만으로 즉시 CANCEL 처리하는 것은 기본값으로 사용하지 않는다.
주가는 파동이 있으므로 일정 시간 기다리는 방식이 기본 방향이다.

8. 매수 미체결 대응

BUY 주문 후 부분체결 또는 미체결 발생:
- 미체결 잔량만 CANCEL
- 잔여 예산 기준 재 BUY 가능
- 부분체결은 인정
- 목표는 해당 BUY 신호의 실행 효율 제고

9. 매도 미체결 대응

SELL 주문 후 부분체결 또는 미체결 발생:
- 미체결 잔량만 CANCEL
- 잔여 수량 기준 재 SELL 가능
- 전량매도는 주문 의도이며, 실제 체결은 부분체결될 수 있음
- 최종 목표는 보유수량 0 또는 루틴이 정한 잔여수량

10. execution_policy.json 역할

execution_policy.json은 루틴별 신호와 메인 주문행동 사이의 공통 실행 규칙이다.

포함 내용:
- 주문 기준: 금액, 수량, 보유수량
- 주문 가격 방식: 시장가, 현재가, 지정가, 호가 기준
- 호가 정보 사용 여부
- 체결/부분체결/미체결 추적
- 재시도 횟수와 재시도 대상
- 평단 데이터 기준
- 검토관리 이동 조건
- 로그 및 상태 기록 항목

11. 안전 우선순위

시스템 정책은 루틴 정책보다 우선한다.

예:
- 검토관리 상태에서는 신규 주문 금지
- 조기마감/자동마감/청산 상태에서는 신규 BUY 금지
- 시스템 CANCEL은 루틴 CANCEL보다 우선
- 서버 평단과 내부 평단 불일치 시 검토관리 우선

12. 구현 방향

현재 단계에서는 프로젝트 본 코드에 바로 반영하지 않는다.
먼저 루틴 패키지 내부 정책 파일 구조로 확정한다.

권장 파일:
- buy_policy.json
- sell_policy.json
- cancel_policy.json
- execution_policy.json

위 파일들은 설계 확정 후 routines/MACD매매루틴/ 내부에 둘 수 있으며, 다른 루틴에서도 같은 형식을 재사용할 수 있게 한다.
