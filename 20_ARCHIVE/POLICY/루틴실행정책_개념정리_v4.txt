# 루틴 실행정책 개념정리 v4

핵심 수정:
- 루틴 권한 과대 해석을 제거한다.
- 종목이 구심점이며, 기본 정책과 동작은 메인파트의 지배를 받는다.
- 루틴은 메인의 활동에 근거를 제공하는 책사 역할이다.
- 루틴 신호는 주문이 아니라 제안이다.
- 메인이 모든 최종 결정권과 실행권을 가진다.
- 조기/자동마감은 즉시 BUY 금지가 아니라 마지막 SELL 신호를 기다리는 상태다.

1. 최상위 원칙

종목 중심 구조:
- 종목이 운영의 중심이다.
- 메인파트가 종목 운영상태, 시간정책, 자금정책, 마감정책, 청산정책, 검토관리 정책을 지배한다.
- 루틴은 메인파트가 서버에서 가져온 현재가, 호가, 봉데이터, 평단, 보유수량 등을 참고해 BUY/SELL/CANCEL 신호를 제안한다.
- 메인은 루틴 신호를 참고하되, 정책상 불허되면 무시한다.

2. 메인과 루틴의 관계

메인:
- 군주/집행권자
- 서버 데이터 수집
- 시간/자금/보유/미수/미도/검토관리 판정
- 조기마감/자동마감/청산/긴급정지 수행
- BUY/SELL/CANCEL 실행 승인 또는 거부
- 실제 주문/취소/체결 추적

루틴:
- 책사
- 지표 기반 BUY/SELL/CANCEL 신호 제안
- 단일가격/다중호가/단일지점/다중지점 실행 방식 제안
- 미체결 대응 방식 제안
- 메인 정책을 이길 수 없음

3. BUY PLAN 용어 정정

BUY PLAN이라는 표현은 루틴 권한이 과도해 보일 수 있으므로 주의한다.
메인 승인 전에는 PLAN이 아니라 Signal Suggestion 또는 Signal Execution Context다.

정확한 계층:
StockContext
  └ MainPolicyContext
      └ RoutineContext
          └ SignalExecutionContext
              └ MainApprovedOrder

4. 마감정책 정정

마감정책은 즉시 BUY 금지가 아니다.

조기/자동마감 진입:
- 상태 = 마지막 SELL 대기
- BUY 신호 허용
- SELL 신호 허용
- 첫 SELL 주문 접수 시 그날 마지막 루틴 매매로 간주
- 마지막 SELL 주문 접수 후 BUY/SELL 차단
- 이후 남은 보유/미체결은 청산 또는 검토관리 정책으로 처리

5. 다중지점 기준가격

다중지점의 기준가격은 최초 메인신호 발생 시 현재가다.
BUY 다중지점은 최초 BUY 신호 현재가 기준.
SELL 다중지점은 최초 SELL 신호 현재가 기준.

6. 다중지점 3개 모드

A. fixed_time_split
- 정해진 시간 안에 정해진 횟수로 분할 실행

B. interval_compare
- 최초 실행 이후 일정 시간/봉마다 기준가 대비 현재가를 비교 후 실행

C. time_window_price_condition
- 정해진 시간 안에서 기준가 대비 특정 가격조건을 만족하면 실행

7. CANCEL

루틴 CANCEL:
- 신호/제안

메인 CANCEL:
- 실제 주문취소 행동

미체결은 즉시 실패가 아니다.
기본은 시간/봉 제한을 우선한다.
가격 이탈만으로 즉시 취소하는 것은 기본값으로 사용하지 않는다.

8. 백테스트 전 구현 방향

백테스트 전에는 다음을 모두 표현 가능하게 해야 한다.
- 단일가격 + 단일지점
- 단일가격 + 다중지점
- 다중호가 + 단일지점
- 다중호가 + 다중지점
- BUY/SELL 양방향 다중지점
- BUY/SELL 양방향 다중호가
- BUY/SELL 양방향 CANCEL 후 재시도

단, 모든 실행은 메인 게이트 승인 후에만 주문으로 이어진다.
