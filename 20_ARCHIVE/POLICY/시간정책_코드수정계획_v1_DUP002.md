## 1. 현재 코드 판정

현재 파일은 최근 실패한 QTimer/자동전환 패치가 들어가기 전 상태에 가깝다.

따라서 복구 기준으로 사용할 수 있다.

문제는 다음이다.

```text
상태 표시명
상태 저장값
시간판정
감시시작 버튼 판정
감시종료 버튼 판정
```

이 서로 완전히 분리되어 있지 않다.

---

## 2. 바로 코드 수정하면 안 되는 항목

아래는 당분간 금지한다.

```text
QTimer 자동갱신
전체 state.json 강제 순회
refresh_all 반복 호출
화면 표시 직전 강제 시간보정
```

이유:
- 창 깜빡임 발생
- 상태 저장값이 꼬임
- 감시시작/감시종료 판정이 충돌함

## 5. 상태 반환 기준

### 수동운영

```text
정규장 안 → RUNNING
추가시장 사용 + 추가시장 안 → RUNNING
그 외 → MONITORING
```

### 시간운영

```text
매수시작~매수종료 → RUNNING
매수종료~정규장 실시간 종료 → SELL_ONLY
정규장 실시간 종료 이후 → MONITORING
```

추가시장 시간운영은 별도 정책 확정 전까지 보류.

## 6. gui_windows.py 연결 지점

### 1차 연결 대상

```text
감시시작 함수 1곳
감시종료 함수 1곳
```

### 감시시작

기존:

```text
상태를 직접 MONITORING/RUNNING 등으로 저장
```

변경:

```text
time_policy.decide_status_on_start(config)
결과만 state.json에 저장
```

### 감시종료

변경:

```text
무조건 STOPPED 저장
화면은 감시/대기로 표시
```

## 7. state_policy.py 역할 정리

`state_policy.py`는 아래만 담당한다.

```text
내부상태 → 화면표시명
화면표시명 → 색상
운영방식 표시명
시간 문자열 정규화 유틸
```

시간판정 핵심은 `time_policy.py`로 분리한다.

## 8. 검증 순서

### 1차

```text
수동 종목 감시시작
→ 정규장 안이면 매수/매도
→ 정규장 밖이면 감시/대기
```

### 2차

```text
시간운영 종목 감시시작
→ 매수시간 안이면 매수/매도
→ 매수종료 이후면 감시/매도
→ 정규장 종료 이후면 감시/대기
```

### 3차

```text
감시종료
→ 감시/대기 표시
→ 다시 감시시작 시 시간정책 재판정
```

### 4차

```text
루틴지정/루틴해제/등록해제 기존 기능 유지 확인
```
