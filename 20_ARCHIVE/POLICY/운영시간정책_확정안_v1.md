# 운영시간정책 확정안 v1

작성일: 2026-06-05
목적: 시간정책 패치 실패를 중단하고, 환경설정/종목설정/상태판정 기준을 먼저 고정한다.

---

## 1. 핵심 결론

시간정책은 `gui_windows.py` 안에서 직접 처리하지 않는다.

구조는 아래처럼 분리한다.

```text
환경설정 = 시간표 관리
종목설정 = 해당 시간표를 사용할지 결정
상태정책 = 현재 상태명을 표시명으로 변환
시간판정엔진 = 현재시간 + 종목설정으로 다음 상태 산출
```

---

## 2. 환경설정 역할

환경설정은 시간표만 관리한다.

### 2-1. 정규장 시간표

```text
정규장 시작: 09:00
정규장 실시간 종료: 15:20
동시호가 참고 구간: 15:20~15:30
```

주의:
- 15:20~15:30은 실시간 자동매매 가능 시간으로 보지 않는다.
- 장마감 청산 기준시간은 `정규장 실시간 종료`를 따른다.

### 2-2. 시간운영 전역시간

```text
기본 매수 시작
기본 매수 종료
```

시간운영 종목이 개별시간을 쓰지 않을 때 적용한다.

### 2-3. 추가시장 시간표

추가시장은 정규장 시간이 아니다.

대표 목적:
- 넥스트장
- 향후 추가 거래시장

환경설정은 아래 시간표만 가진다.

```text
추가시장1 시작/종료
추가시장2 시작/종료
추가시장3 시작/종료
```

주의:
- 추가시장 사용 여부는 환경설정에서 결정하지 않는다.
- 종목마다 넥스트장 가능 여부가 다르므로 종목설정에서 결정한다.

---

## 3. 종목설정 역할

종목설정은 해당 종목이 어떤 시간표를 사용할지 결정한다.

### 3-1. 수동운영

기본 정책:

```text
정규장 안 → 매수/매도
정규장 밖 → 감시/대기
```

옵션:

```text
추가시장 사용 여부
```

추가시장 사용 시:

```text
정규장 또는 선택된 추가시장 안 → 매수/매도
그 외 → 감시/대기
```

### 3-2. 시간운영

기본 정책:

```text
매수시작 ~ 매수종료 → 매수/매도
매수종료 ~ 정규장 실시간 종료 → 감시/매도
정규장 실시간 종료 이후 → 감시/대기
```

시간 기준:
- 개별시간이 있으면 개별시간 우선
- 개별시간이 없으면 전역시간 사용

추가시장 사용 여부는 종목별 옵션으로 둔다.
단, 추가시장 시간운영 정책은 별도 확정 전까지 실제 주문과 연결하지 않는다.

### 3-3. 조기마감

조기마감은 종목별 옵션이다.

이유:

```text
A 종목은 조기마감
B 종목은 정상운영
```

이 가능해야 한다.

---

## 4. 감시/매도 정책

감시/매도는 시간운영에서 매수 종료 이후 정규장 실시간 종료 전까지의 상태다.

선택 옵션:

```text
1. 루틴 매도신호에 따른 매도
2. 익절
3. 손절
4. 즉시매도
```

즉시매도 방식:

```text
현재가
시장가
```

---

## 5. 장마감 청산정책

환경설정에는 전역 기준을 둔다.

```text
사용 여부
정규장 실시간 종료 N분 전
청산방식: 현재가 / 시장가
```

종목별로 사용할지 여부는 종목설정에서 결정한다.

---

## 6. 상태명 기준

화면 표시 상태는 아래 6개로 유지한다.

```text
감시/대기
매수/매도
감시/매도
조기마감
긴급정지
검토종목
```

단, 내부 상태와 화면 표시를 혼동하지 않는다.

권장 내부 상태:

```text
STOPPED       = 감시종료/미가동
MONITORING    = 감시/대기
RUNNING       = 매수/매도
SELL_ONLY     = 감시/매도
EARLY_CLOSE   = 조기마감
EMERGENCY_STOPPED = 긴급정지
REVIEW_REQUIRED   = 검토종목
```

---

## 7. 감시시작/감시종료 정책

### 감시시작

감시시작은 현재 시간과 종목 운영방식에 따라 상태를 산출한다.

```text
수동운영 → 수동운영 시간판정
시간운영 → 시간운영 시간판정
```

### 감시종료

감시종료는 시간과 무관하게 우선 적용한다.

```text
감시종료 → STOPPED 저장
화면 표시 → 감시/대기
```

주의:
- 감시종료 후 자동 시간정책이 임의로 다시 RUNNING으로 바꾸면 안 된다.
- 자동 시간갱신은 추후 별도 설계 후 적용한다.

---

## 8. 구현 우선순위

1. 이 문서를 기준으로 `time_policy.py` 신규 작성
2. `state_policy.py`는 상태 표시/색상만 담당
3. `gui_windows.py`는 감시시작/감시종료 버튼에서 `time_policy.py`를 호출만 함
4. 자동갱신 QTimer는 당분간 금지
5. 수동 테스트 통과 후 자동갱신 재검토

---

## 9. 현재 코드 수정 가능 여부

가능하다.

단, 기존처럼 `gui_windows.py`에 시간정책을 직접 덧붙이면 다시 꼬일 가능성이 높다.

수정 방식은 아래가 안전하다.

```text
1단계: time_policy.py 신규 파일 생성
2단계: 단위 테스트용 함수만 검증
3단계: 감시시작 함수 1곳 연결
4단계: 감시종료 함수 1곳 정리
5단계: 화면 표시명 정리
6단계: 자동갱신은 마지막에 검토
```
