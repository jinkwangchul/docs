제3부 종목관리 정책

본 문서는 종목관리 정책을 정의한다.

종목관리는 프로젝트의 기본 운영 단위이다.

--------------------------------------------------

1. 기본 원칙

모든 종목은 독립적으로 관리한다.

한 종목의 문제는 다른 종목에 영향을 주지 않아야 한다.

--------------------------------------------------

2. 종목 등록

종목 등록은 종목관리의 시작 단계이다.

등록 전 기본 검증을 수행한다.

--------------------------------------------------

3. 중복 등록

동일 종목 중복 등록 금지.

이미 등록된 종목은 재등록 불가.

--------------------------------------------------

4. 오류 종목

오류 종목은 등록 불가.

종목 정보 검증 실패 시 등록 거부.

--------------------------------------------------

5. 종목 폴더 정책

중앙 종목폴더 단일 원본 정책 적용.

모든 종목 데이터는 stocks 폴더 기준으로 관리.

--------------------------------------------------

6. 종목 데이터

종목별 데이터는 독립 관리.

종목 삭제 시 해당 데이터 처리 정책 적용.

--------------------------------------------------

7. 루틴 지정

종목은 루틴과 연결 가능.

하나의 종목은 지정된 루틴 정책을 따른다.

--------------------------------------------------

8. 루틴 해제

루틴 연결 제거 가능.

해제 후 미지정 상태로 전환 가능.

--------------------------------------------------

9. 루틴 변경

기존 루틴 해제 후 신규 루틴 지정 가능.

--------------------------------------------------

10. 루틴 패키지 구조

루틴은 패키지 단위로 관리.

예시

routine.json

rules.json

readme.md

version.txt

--------------------------------------------------

11. 루틴 자동 인식

루틴 파일 배치 시 자동 인식 가능.

별도 설치 절차를 요구하지 않는다.

--------------------------------------------------

12. 루틴 복원

루틴 패키지 복원 시 자동 등록 가능.

--------------------------------------------------

13. 루틴 삭제

루틴 삭제 시 연결 종목 보호 정책 적용.

문제 발생 시 검토관리 연계 가능.

--------------------------------------------------

14. 종목 위치

종목은 다음 위치 중 하나에 존재한다.

운영중

감시/대기

검토관리

미지정

--------------------------------------------------

15. 검토관리 이동

정책에 따라 자동 또는 수동 이동 가능.

--------------------------------------------------

16. 복귀

검토관리에서 원래 위치 복귀 가능.

--------------------------------------------------

17. 미지정

루틴 연결 없이 종목 보관 가능.

--------------------------------------------------

18. 삭제

종목 제거 가능.

삭제 정책은 검토관리 삭제와 구분한다.

--------------------------------------------------

19. 안정성검사

정식 명칭

안정성검사

사용.

무결성검사 명칭 사용 금지.

--------------------------------------------------

20. 안정성검사 목적

종목 상태 점검.

파일 상태 점검.

루틴 연결 상태 점검.

운영 가능 여부 점검.

--------------------------------------------------

21. 안정성검사 결과

정상

문제 발견

검토 필요

상태 반환 가능.

--------------------------------------------------

22. 재시작 연계

프로그램 재시작 후 종목 재검사 수행.

문제 종목은 검토관리 이동 가능.

--------------------------------------------------

23. 긴급정지 연계

긴급정지 해제 후 안정성검사 수행.

문제 종목은 검토관리 이동 가능.

--------------------------------------------------

--------------------------------------------------

25. 최종 원칙

종목은 프로젝트의 기본 관리 단위이다.

종목 정보의 독립성 및 안정성을 최우선으로 한다.
