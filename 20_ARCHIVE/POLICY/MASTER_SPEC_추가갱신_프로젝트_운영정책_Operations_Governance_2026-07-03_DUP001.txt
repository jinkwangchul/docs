MASTER_SPEC_추가갱신_프로젝트_운영정책_Operations_Governance_2026-07-03

목적
- 프로젝트를 실제 운영할 때 준수해야 하는 운영 원칙과 의사결정 기준을 정의한다.
- 구현 정책과 운영 정책을 구분하여 장기 유지보수 기준으로 사용한다.

==================================================
1. 운영 기본 원칙
==================================================
- 안정성을 수익보다 우선한다.
- 자동 처리보다 검증 가능한 처리를 우선한다.
- 불확실한 상태는 검토관리로 이관한다.
- 모든 운영 변경은 추적 가능해야 한다.

==================================================
2. 운영 시작 조건
==================================================
□ Runtime 무결성 확인
□ Guard 상태 확인
□ 계좌 선택 확인
□ 로그인 확인
□ Review 미처리 항목 확인
□ Recovery 완료 확인

==================================================
3. 운영 중 원칙
==================================================
- Preview 결과와 실제 실행 결과를 구분한다.
- Runtime 이상 징후는 즉시 기록한다.
- 허용되지 않은 상태 전이는 운영 중단 대상이다.
- Controller를 우회한 수동 조작을 금지한다.

==================================================
4. 운영 종료 조건
==================================================
□ 진행 중 검증 완료
□ 미처리 오류 확인
□ Audit 기록 확인
□ Runtime 저장 완료

==================================================
5. 장애 대응
==================================================
- Runtime 손상 → Recovery 절차
- 상태 불일치 → Review Management
- 계좌/로그인 이상 → 실주문 차단
- 원인 불명 → 운영 중단 후 분석

==================================================
6. 운영 기록
==================================================
기록 대상
- 운영 시작
- 운영 종료
- 주요 상태 전이
- Review 발생
- Recovery 수행
- 장애 발생

==================================================
7. 운영 금지
==================================================
- Recovery 없이 운영 재개
- Review 우회
- Runtime 직접 수정
- 실주문 강제 실행
- 검증 없는 정책 변경

==================================================
최종 원칙

운영 정책은 시스템을 '동작'시키기 위한 기준이 아니라,
안전하고 일관되게 '운영'하기 위한 기준이다.
