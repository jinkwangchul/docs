Startup Recovery / Session Resume is complete.

What operators can now do:
- Restart the application without losing prior runtime evidence to a forced
  startup reset.
- See whether the previous session is ready, needs review, is blocked, or has
  invalid runtime evidence.
- Review unfinished orders, Fill/Position gaps, Broker Holdings mismatches,
  active locks, uncertain sends, and reconciliation items.
- Use the existing reconciliation workflow for unresolved evidence.
- Explicitly approve the session before automatic trading resumes.

How resume remains safe:
- Approval is tied to the exact runtime evidence snapshot.
- A later file change revokes approval.
- Automatic trading and all order progression remain blocked before approval.
- Startup Recovery does not resend orders, call SendOrder, repair Position,
  initialize runtime files, or erase evidence.
- Existing Source of Truth and Writer ownership remain unchanged.
