0. 절대 작업 원칙
================================================================================

1) 압축파일 생성 금지
- 사용자는 압축파일을 다루기 번거로워한다.
- 결과물은 가급적 개별 파일로 제공한다.
- 새창 재개용 문서도 txt 개별 파일로 제공한다.
- ZIP 생성은 사용자가 명시적으로 요구하지 않는 한 금지한다.

2) 임의 삭제/임의 수정 금지
- 사용자가 요청한 항목 외에는 건드리지 않는다.
- 특히 UI 공통폼은 한 줄 수정이 전체 BUY/SELL 여러 위치에 퍼질 수 있으므로 반드시 영향범위를 확인한다.
- “QLabel('에') → QLabel('대비')” 같은 전체 치환은 요청 범위와 영향 범위를 먼저 정확히 파악해야 한다.
- 기존에 정상 동작하던 BUY 완료정책, 매수방식, 매도방식, 신호검출조건을 의도 없이 깨면 안 된다.

3) 결과물 생성 전 구현 방향 확인
- 사용자는 구현 방향 확인을 중요하게 본다.
- 단, 지금처럼 사용자가 “작성해라”, “파일 줘”, “수정파일 줘”라고 직접 지시한 경우에는 바로 파일 생성한다.
- 불필요한 질문, 중복 대화, 긴 설명은 피한다.

4) 설명 최소화
- 사용자는 긴 설명을 싫어한다.
- 수정파일 제공 시에는 “수정본” + 다운로드 링크만 간단히 주는 방식이 적합하다.
- 단, 새창 재개 문서와 마스터스펙 갱신 문서는 상세해야 한다.

5) 테스트 필수
- 파일 생성 후 최소한 py_compile로 문법 검증해야 한다.
- 가능하면 변경 위치를 텍스트 검색으로 확인한다.
- 런타임 오류 가능성이 있는 속성 삭제는 절대 주의한다.
- UI 행을 삭제할 때는 해당 체크박스를 참조하는 sync 함수와 signal connect도 같이 점검해야 한다.

1. 현재까지의 최신 정상 기준 파일
================================================================================

가장 최근 사용자가 “이거 가지고 수정해서 파일줘”라고 올린 기준 파일:
- gui_macd_routine_settings_dialog(111).py

이 파일은 사용자가 복원한 정상 계열의 파일이다.
이전 assistant가 생성한 일부 파일은 UI가 깨졌거나, 완료정책 관련 속성 삭제로 런타임 오류가 발생했으므로 그대로 신뢰하면 안 된다.

문제 있었던 파일/상태:
- gui_macd_routine_settings_dialog(110).py: 직전 assistant가 잘못 만든 버전으로 사용자가 “쓰레기”라고 판정.
- gui_macd_routine_settings_dialog(111).py: 사용자가 다시 업로드한 수정 기준 파일.
- gui_macd_routine_settings_dialog(112_from111).py: 마지막으로 생성했으나 사용자가 최종 확인하지 않았고, 이 창에서 신뢰가 깨졌으므로 다음 창에서는 사용자가 직접 올리는 최신 파일을 기준으로 재검토하는 것이 안전하다.

다음 창에서 가장 먼저 해야 할 일:
1) 사용자가 올려주는 최신 gui_macd_routine_settings_dialog.py 파일을 기준으로 삼는다.
2) 이전 assistant가 생성한 112_from111.py를 무조건 최신으로 간주하지 않는다.
3) 현재 UI 스크린샷과 파일 내용을 같이 비교한다.
4) “미체결정책” 공통 함수만 수정하려면 해당 함수 전체 범위를 정확히 추출해서 수정한다.
5) 단순 문자열 전체 치환은 위험하므로 최소 범위만 수정한다.

2. 오늘 작업한 UI 위치와 핵심 맥락
================================================================================

작업 위치:
- MACD매매루틴 설정창
- 구성 탭
- 매도설정 영역
- 하단 3분할 영역:
  1) 매도방식
  2) 미체결정책
  3) 완료정책

현재 UI 철학:
- 메인 SELL 신호는 최초 매도 트리거다.
- 매도방식은 메인 SELL 신호 발생 시 최초 1회 매도계획을 만든다.
- 미체결정책은 최초 매도와 재매도 주문 모두에 공통 적용되는 주문취소 기준이다.
- 완료정책은 최초 매도 이후 잔량이 남았을 때 사용하는 재매도/잔량매도 전략이다.
- 완료정책은 매도방식과 유사한 폼을 가질 수 있으나, 설정값은 분리되어야 한다.
- 즉 구현은 재사용 가능하지만 설정 인스턴스는 분리해야 한다.

실행 개념:
SELL 신호 발생
→ 매도방식 1회 수행
→ 미체결정책 적용
→ 잔량 없으면 완료
→ 잔량 있으면 완료정책/재매도정책 수행
→ 다시 미체결정책 적용
→ 잔량 있으면 반복
→ 종료조건 또는 마지막회 조건 도달 시 완료/검토관리

3. 매도방식 관련 확정/보류 내용
================================================================================

3.1 매도방식 역할
- 메인 SELL 신호를 트리거로 최초 1회 동작한다.
- 최초 매도계획 생성용이다.
- 재매도/잔량매도와 같은 반복 수행은 완료정책이 담당한다.

3.2 매도방식 마지막회 설정
사용자가 요청한 변경:
- 기존:
  □ 마지막회 시장가 매도
- 변경:
  □ 마지막회 [시장가/현재가]

의미:
- 마지막회 체크박스는 다중지점 하위 설정이다.
- 다중지점의 시간 또는 평단 조건이 켜져야 활성화된다.
- 마지막회 주문 타입을 시장가 또는 현재가로 선택할 수 있어야 한다.
- 콤보박스 기본값은 시장가로 두는 흐름이었다.
- 단, UI 문구는 최종적으로 사용자가 다시 볼 수 있으므로 다음 창에서 재확인 필요.

주의:
- “마지막회 시장가 매도”를 단순 QLabel 하나로 두면 유연성이 떨어진다.
- 사용자는 최초 매도에서는 시장가를 쓰고 싶지 않지만, 재매도 또는 완료정책에서는 시장가를 쓰고 싶을 수 있다고 했다.
- 따라서 최초 매도방식과 완료정책의 마지막회 시장가/현재가 선택은 독립 설정이어야 한다.

4. 미체결정책 관련 확정/변경 흐름
================================================================================

4.1 기존 미체결정책 문제
이전에 있던 가격 비교 3줄:
- 주문가에 현재가 상하 0.25% 이내 일괄 주문취소
- 현재가에 평단가 상하 0.25% 이내 일괄 주문취소
- 평단가에 주문가 상하 0.25% 이내 일괄 주문취소

사용자는 며칠 고민 후 효용성이 없다고 판단했고, 한때 모두 삭제하기로 했다.
그러나 이후 새로 구상한 형태로 가격조건 1줄을 다시 추가하려고 했다.

4.2 미체결정책 시간 기준 문구 확정 흐름
초기 형태:
- 매도지점 [매회] [20][초] 이후 주문취소

변경 논의:
- “매도주문 후 미체결 수량 발생 시 [20][분/초/봉]마다 [순차/일괄] 주문 취소”
- 순차가 어색하다고 판단.
- 매회/일괄로 복귀.
- 일괄은 각 주문마다 시간이 아니라 “메인 신호에 따른 방식 1세트가 끝나고 30초 이후 취소” 개념이라고 정리.
- 따라서 “기준”이라는 단어가 필요하다고 판단.

최종 문구:
- 매도 미체결 발생 시 [매회/일괄] 기준 [20][분/초/봉] 후 주문취소

BUY 공통일 경우:
- 매수 미체결 발생 시 [매회/일괄] 기준 [20][분/초/봉] 후 주문취소

콤보 순서:
- 분/초/봉이 프로젝트 전체 원칙.
- 다만 기본 선택값은 현재 UI 맥락상 “초”로 쓰는 경우가 많았다.
- 사용자는 순서 일관성을 중요하게 지적했다.
- 콤보 아이템 순서는 반드시 ["분", "초", "봉"].
- 기본값은 기존 화면과 맞춰 "초"일 수 있으나, 새로 만들 때 임의 변경 금지.

4.3 매회/일괄 의미
매회:
- 각 주문별 미체결 발생 기준.
- 해당 주문이 미체결 상태로 지정 시간 경과 시 개별 취소.

일괄:
- 메인 신호에 따른 매도방식 1세트가 끝난 시점 기준.
- 세트 종료 후 지정 시간 경과 시 남아있는 미체결 주문을 한번에 취소.
- “지정시간마다”가 아니라 “세트 종료 후 N초/분/봉 후 일괄 취소”에 가깝다.
- 그래서 UI 문구에 “기준”을 넣었다.

4.4 미체결정책에 새로 추가하려는 가격 조건 1줄
사용자 요청:
- 미체결 정책에 다음 한 줄 추가:
  [주문가/현재가/평단가] 대비 [주문가/현재가/평단가] [상향/하향/상하][0.15]%[이상/이하/이내/이탈] 매수주문취소

SELL 영역에서는 마지막 문구가 자연스럽게:
- 매도주문취소

BUY 영역에서는:
- 매수주문취소

중요:
- 사용자는 “주문가 설정은 현재 창내 공통폼을 쓰고 있는건 알지?”라고 했다.
- 즉 기존에 여러 곳에서 사용하는 가격 비교 공통폼 형태가 있다.
- 새 줄도 기존 공통폼과 같은 동작/숨김 규칙을 따라야 한다.

4.5 방향에 따른 비교 콤보 숨김 규칙
반드시 적용:
- 방향이 상향 또는 하향이면 비교 콤보에는 이상/이하만 표시
- 방향이 상하이면 비교 콤보에는 이내/이탈만 표시
- 단순히 ["이상","이하","이내","이탈"] 전체가 항상 보이는 콤보가 아니다.
- 기존 sync_direction_compare_combo 또는 sync_gap_compare_combo 형태의 숨김 로직을 반드시 연결해야 한다.

4.6 “에” → “대비” 변경
사용자 요청:
- “여기서 주문가 '에' 를 대비로 모두 바꿔줘”

해석 주의:
- 창 내 가격 비교 공통폼에서 “A 에 B” 형태는 “A 대비 B”로 바꾼다.
- 예:
  주문가 에 현재가 → 주문가 대비 현재가
  현재가 에 평단가 → 현재가 대비 평단가
  주문가 에 평단가 → 주문가 대비 평단가
- 단, 전역 문자열 치환은 매우 위험하다.
- “QLabel('에')”가 가격 비교 용도로만 쓰이는지 확인하고 수정해야 한다.
- 만약 다른 자연어 문장 안의 “에”가 QLabel로 존재한다면 의도치 않게 바뀔 수 있다.
- 다음 창에서는 함수 단위로 범위를 좁혀 수정하는 것이 좋다.

5. 완료정책 관련 확정 내용
================================================================================

5.1 완료정책 역할
- 완료정책은 최초 매도 이후 잔량 재매도 전용 전략으로 본다.
- 이름은 아직 “완료정책”으로 유지 중이나, 의미상 “잔량매도정책” 또는 “재매도정책”에 가깝다.
- 추후 명칭 변경 가능.

5.2 완료정책 상단 첫 줄 삭제
사용자 요청:
- 완료정책 상단의 “마지막 주문 취소 이후 [3][분] 동안 수행” 행 삭제

주의:
- 이 행을 단순 삭제하면 내부 sync 함수에서 self.complete_after_cancel_check 또는 self.sell_complete_after_cancel_check를 참조해 AttributeError가 발생했다.
- 실제 발생한 오류:
  AttributeError: 'MacdRoutineSettingsDialog' object has no attribute 'complete_after_cancel_check'
- 원인:
  UI 생성 행은 삭제했지만, 그 체크박스를 참조하는 sync_fill_ratio_enabled, sync_detail_row_enabled, sync_complete_mode 등의 로직이 남아 있었다.
- 따라서 행 삭제 시 반드시 다음을 같이 점검해야 한다.
  1) 체크박스 생성 코드
  2) 해당 체크박스 setEnabled 호출
  3) toggled.connect 호출
  4) isChecked 참조
  5) 해당 체크박스를 조건으로 쓰던 하위 row 활성/비활성 로직

5.3 완료정책 첫 줄 삭제의 현재 상태
- 사용자 스크린샷 기준으로 어느 순간 완료정책 첫 줄은 삭제된 상태까지 도달했다.
- 그러나 이후 미체결정책 수정 과정에서 파일 버전이 오염되었으므로 다음 창에서 다시 확인 필요.
- 최종 기준 파일을 받으면 “마지막 주문 취소 이후” 문자열 검색부터 해야 한다.
- 남아 있으면 UI 행과 참조 로직을 함께 제거하거나 hidden compatibility checkbox를 두는 방식을 신중히 선택해야 한다.

6. 신호검출조건 관련 현재 반영 내용
================================================================================

6.1 매도 신호검출조건 B
사용자 요청으로 조건 B 두 번째 줄에 볼린저밴드 설정을 넣었다.
형태:
- 가격박스 하향 0.1% 이상
- 볼린저밴드 하향 0.1% 이상
- 주문가/현재가/평단가 대비 조건

조건 B에서 볼린저밴드는 가격박스와 유사한 형태로 추가된 상태다.
다음 창에서 조건 B UI가 유지되는지 확인해야 한다.

6.2 매도 신호검출조건 C
사용자 요청으로 조건 C 상단에 주문가 등 가격 필터를 넣었다.
형태:
- 주문가 대비 현재가 상하 0.25% 이내
- MACD선 - 1.0 이하
- 배열 5 > 20 > 60

주의:
- “에”를 “대비”로 바꾸는 작업은 조건 A/B/C의 가격비교 라벨에도 적용되어야 한다.
- 하지만 전역 치환으로 다른 부분이 깨질 수 있으므로 주의.

6.3 조건식 연산자
- AND/OR/NOT 사용.
- 사용자는 NOT을 AND NOT, OR NOT처럼 붙여 쓰는 것을 강하게 금지했다.
- NOT은 동일 레벨의 조건 제외 연산자로 본다.
- 예: A AND B NOT C는 A이고 B이고 C가 아닌 것.
- AND NOT, OR NOT 같은 표현은 프로젝트에서 금지.

7. 이전 assistant 오류/금지 행동 기록
================================================================================

이번 창에서 assistant가 반복적으로 잘못한 부분:

1) 최신 파일 인식 실패
- assistant가 본인이 생성한 sandbox 파일을 못 본다고 잘못 주장했다.
- 실제로는 /mnt/data 내 생성 파일을 계속 사용할 수 있었다.
- 사용자가 “네가 준 파일을 네가 못봐?”라고 지적했다.

2) 이미지 생성 오작동
- 사용자가 문구 수정 파일을 요청했는데 image_gen 호출이 발생했다.
- 사용자는 즉시 “이미지 금지”라고 지적했다.
- 이후 이미지 생성 절대 금지.
- 이 프로젝트 작업은 코드/문서 파일 생성 중심이다.

3) 완료정책 행 삭제 후 참조 로직 미제거
- “마지막 주문 취소 이후” 행을 삭제하면서 complete_after_cancel_check 참조를 남겨 런타임 오류를 발생시켰다.
- py_compile은 통과했지만 런타임에서 UI 생성 중 AttributeError 발생.
- 교훈: PyQt UI에서는 py_compile만으로 안전성 보장 불가. 삭제한 위젯 참조를 문자열 검색해야 한다.

4) 미체결정책 공통함수 수정 실패
- 기존 함수 끝에 add_cancel_gap_row 호출만 넣는 방식으로 수정했으나 실제 UI가 깨졌다.
- 기존 함수 내부 정의/호출 위치를 제대로 파악하지 못했다.
- 잘못된 파일에서 작업하거나, 이미 오염된 파일을 기준으로 다시 수정해서 문제가 반복되었다.

5) 과도한 설명
- 사용자는 불필요한 설명, 질문, 중복대화를 싫어한다.
- 파일 요청 시에는 수정파일만 제공해야 한다.
