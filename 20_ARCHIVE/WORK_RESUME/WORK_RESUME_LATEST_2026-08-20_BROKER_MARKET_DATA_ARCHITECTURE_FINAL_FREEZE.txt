4. Current Broker And Market-data State
==================================================

- BrokerSession uses connection_epoch and login_session_id provenance.
- Pending TR and Governor dispatch revalidate the current broker session.
- Stale TR/realtime events fail closed.
- Market data modes are TR_PRIMARY_SHADOWING, REALTIME_ELIGIBLE,
  REALTIME_PRIMARY, and TR_RECONCILING.
- New processes and new broker sessions never restore old realtime-primary
  authority.
- Canonical one-minute SoT remains stocks/<stock>/candles.json.
- Only changed, read-back-verified atomic commits emit BAR_COMMITTED.
- Operation-owned TR and verified realtime-primary events enter the per-stock
  normalized MarketDataHost -> OperationHost fast path.
- Missing/incomplete realtime minutes use governed opt10080 reconciliation and
  return to TR_PRIMARY_SHADOWING after verified repair.

5. Registration And Roster State
==================================================

- operation_policy.json stock_registration.default_location accepts WAITING or
  EXCLUDED and defaults to WAITING when missing/malformed.
- The default applies once to a true-new central stock and is not retroactive.
- Registration, assignment changes, exclusion release, Recovery completion,
  and persisted RUNNING do not create participants.
- Current-session participants are created only from successful explicit
  operation starts.
- Process restart does not restore the participant set.
