MASTER_SPEC_추가갱신_구현단계별_완료기준_Definition_of_Done_2026-07-03

목적
- 각 구현 단계가 '완료'되었다고 판단할 수 있는 객관적인 기준(Definition of Done)을 정의한다.
- 구현 완료와 설계 완료를 구분하고, 테스트·검증 기준을 통일한다.

==================================================
1. 공통 완료 기준
==================================================

각 구현 단계는 아래 조건을 모두 만족해야 완료로 인정한다.

□ 코드 구현 완료
□ 단위 테스트 작성
□ 회귀 테스트 통과
□ Runtime 부작용 확인
□ 실주문 미연결 확인
□ Audit 대상 확인
□ 문서 갱신 완료

==================================================
2. Candidate 단계
==================================================

완료 조건
□ Order Candidate 생성
□ order_intent 생성
□ order_provenance 생성
□ execution_enabled=false 유지
□ 기존 Approval 테스트 통과

==================================================
3. Approval 단계
==================================================

완료 조건
□ APPROVED/BLOCKED 정상 전이
□ 상태 외 부작용 없음
□ Runtime 저장 검증
□ 회귀 테스트 통과

==================================================
4. Policy 단계
==================================================

완료 조건
□ EXECUTABLE/BLOCKED_POLICY 전이
□ execution_enabled 변경 없음
□ 단건 처리 검증

==================================================
5. Preflight 단계
==================================================

완료 조건
□ REAL_READY/BLOCKED_REAL 전이
□ Guard 검증
□ 자동 Guard 생성 없음
□ SendOrder 미연결

==================================================
6. Adapter Preview
==================================================

완료 조건
□ Preview 생성
□ Queue 변경 없음
□ SendOrder/Stub 미호출

==================================================
7. Execution 단계(향후)
==================================================

완료 조건
□ Final Guard 통과
□ Lock 확인
□ Request Hash 생성
□ ORDER_QUEUED 생성
□ SendOrder는 별도 검증

==================================================
8. 체결 단계(향후)
==================================================

완료 조건
□ Fill 생성
□ Position 갱신
□ Audit Log 기록
□ Recovery 영향 검증

==================================================
9. 운영 단계(향후)
==================================================

완료 조건
□ Review 연계
□ Recovery 검증
□ Runtime 일관성 확인

==================================================
10. 완료 판정 원칙
==================================================

다음 중 하나라도 미완료면 해당 단계는 완료로 인정하지 않는다.

- 테스트 없음
- 회귀 검증 없음
- 문서 미갱신
- Runtime 영향 미확인
- 책임 범위 초과 구현

최종 원칙

'구현 완료'는 코드 작성이 아니라,
구현 + 검증 + 문서화 + 안전성 확인까지 끝난 상태를 의미한다.
