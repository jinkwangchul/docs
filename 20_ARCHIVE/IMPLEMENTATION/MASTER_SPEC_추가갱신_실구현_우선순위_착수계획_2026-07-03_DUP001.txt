MASTER_SPEC_추가갱신_실구현_우선순위_착수계획_2026-07-03

목적
- 아키텍처 설계 이후 실제 구현에 착수할 때 적용할 구현 우선순위를 확정한다.
- 설계와 구현을 혼동하지 않도록 각 단계의 목표를 명확히 구분한다.

==================================================
1. 현재 구현 완료
==================================================

완료
- Signal → Order Candidate
- Approval
- Operation Policy
- Real Preflight
- Adapter Request Preview
- order_intent
- order_provenance

미구현
- ExecutionController
- Order Lock
- Request Hash
- ORDER_QUEUED
- SendOrder
- Fill
- Position Runtime
- Recovery Runtime

==================================================
2. 구현 우선순위
==================================================

Priority 1
- hoga / order_type 매핑 규칙 확정
- order_intent resolved 조건 확정

Priority 2
- ExecutionController 인터페이스
- Final Execution Guard 구현

Priority 3
- Order Lock Manager
- Request Hash 생성

Priority 4
- Execution Request 생성
- ORDER_QUEUED 생성

Priority 5
- Kiwoom Boundary 연결
- KiwoomOrderExecutor

Priority 6
- Chejan / Fill
- Position Runtime

Priority 7
- Recovery Runtime
- Review Runtime
- Audit Runtime

==================================================
3. 구현 원칙
==================================================

- 한 번에 하나의 책임만 구현한다.
- Controller는 호출만 담당한다.
- Engine은 판단만 담당한다.
- Boundary는 API 통신만 담당한다.
- Runtime은 데이터 저장만 담당한다.

==================================================
4. 각 단계 완료 조건
==================================================

ExecutionController
- SendOrder 없음
- 상태 전이 없음
- 인터페이스만 검증

Final Guard
- 모든 차단 조건 검증
- ORDER_QUEUED 생성 없음

Lock
- 중복 검증
- Runtime 저장 없음

Execution Request
- 데이터 생성
- SendOrder 없음

Boundary
- Preview와 실제 요청 일치 검증
- SendOrder는 별도 단계

==================================================
5. 절대 금지
==================================================

- 여러 단계 동시 구현
- 선행조건 없이 다음 단계 구현
- 테스트 없이 Runtime 변경
- SendOrder 조기 연결
- 상태 전이 우회

==================================================
최종 원칙

앞으로의 구현은 작은 단위로 완료·검증한 뒤 다음 단계로 진행한다.
