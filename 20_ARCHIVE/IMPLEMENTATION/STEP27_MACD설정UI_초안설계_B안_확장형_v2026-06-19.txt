STEP27_MACD설정UI_초안설계_B안_확장형_v2026-06-19

작성 목적:
본 문서는 STEP26 MACD 설정 UI 항목목록화 이후,
MACD매매루틴 설정 UI의 초안 구조를 B안(확장형) 기준으로 설계한 문서이다.

본 문서는 UI 구현 파일이 아니다.
본 문서는 코드 패치가 아니다.
본 문서는 실제 GUI 변경 전 사용자 검토용 설계 초안이다.

------------------------------------------------------------
1. 설계 기준
------------------------------------------------------------

선택 방향:
- B안 확장형 UI

선택 이유:
- SELL 계층은 STEP23으로 일부 구현 완료되었다.
- BUY 계층은 아직 확정 전이나 향후 평단 중심, 지속매수, 다중매수와 연결될 가능성이 높다.
- CANCEL은 메인 주문취소와 다른 루틴 신호/제안 개념으로 재정리 필요성이 있다.
- 지금부터 UI 영역을 좁게 만들면 이후 확장 시 화면을 다시 뜯어야 할 가능성이 크다.
- 단, 미확정 항목은 편집 불가/잠금/설명 전용으로 둔다.

핵심 원칙:
- 확정된 항목만 편집 가능
- 미확정 항목은 보이더라도 잠금
- HOLD 항목은 UI에 절대 넣지 않음
- 실주문 실행 항목은 잠금 또는 숨김
- rules.json 저장 기능은 처음부터 바로 넣지 않음

3. 상단 요약 영역
------------------------------------------------------------

표시 항목:
- 루틴명: MACD매매루틴
- rules.json 경로
- rules 버전
- 신호 전용 모드 여부
- 실행 허용 여부
- 마지막 로드 상태
- 경고 문구

권장 경고 문구:
- "현재 단계에서는 실주문 실행이 비활성화되어 있습니다."
- "루틴은 BUY/SELL 신호를 생성하고, 실제 주문 실행은 메인 계층에서 담당합니다."
- "조건 미충족은 HOLD가 아니라 signal=None입니다."

편집 여부:
- 루틴명: 읽기 전용
- rules 경로: 읽기 전용
- 신호 전용 모드: 읽기 전용 또는 잠금
- 실행 허용 여부: 잠금

4. 기본설정 탭
------------------------------------------------------------

편집 가능 후보:
1. 루틴 사용 여부
- rules.enabled
- 체크박스

읽기/잠금 권장:
2. signal_only
- 현재 true 유지
- 체크박스 표시 가능하나 잠금 권장

3. execution_enabled
- 현재 false 유지
- 실주문 전까지 잠금 또는 숨김
- 표시 시 반드시 경고 문구 포함

4. allowed_order_signals
- BUY / SELL 표시
- 편집 금지

5. non_signal
- signal=None 설명 표시
- 편집 금지

금지:
- HOLD 추가 선택지
- WAIT/SKIP/NO_SIGNAL을 공식 신호 선택지로 제공

5. BUY 탭
------------------------------------------------------------

현재 방향:
- BUY 탭은 존재시키되 최소 표시/잠금 중심으로 구성한다.
- BUY는 향후 평단 중심, 지속매수, 다중매수와 연결되므로 지금 편집 확장 금지.

표시 항목:
1. BUY 사용 여부
- 현재 구조가 있으면 표시
- 편집 여부는 잠금 권장

2. BUY delay_bar
- 현재 값 표시
- 편집 보류 권장

3. BUY 조건그룹 요약
- groups 존재 시 목록 표시
- 상세 편집은 보류

4. BUY 설명
- "BUY는 포지션 구축 또는 확대 신호입니다."
- "향후 평단 중심/지속매수/다중매수 구조와 함께 확정 예정입니다."

잠금/보류 항목:
- buy.signal_logic
- buy.signals
- 지속매수
- 평단 기반 매수강도
- 다중매수
- 능동매수
- 매수 실패/미완성 판정
- 회차별 예산 배분

UI 처리:
- 별도 섹션으로 표시 가능하나 회색 잠금
- "추후 확정" 라벨 표시

------------------------------------------------------------
6. SELL 탭
------------------------------------------------------------

SELL 탭은 STEP23 구현 완료 범위를 중심으로 구성한다.

6.1 SELL 공통

편집 가능 후보:
1. SELL 사용 여부
- sell.enabled
- 체크박스

2. SELL 결합 방식
- sell.signal_logic
- OR / AND
- 콤보박스 또는 라디오버튼
- STEP23 검증 완료

권장 UI:
- OR / AND 라디오버튼
- 설명 문구:
  OR = 활성화된 SELL 조건 중 하나라도 충족하면 SELL
  AND = 활성화된 SELL 조건이 모두 충족되어야 SELL

6.2 MACD SELL 영역

편집 가능 후보:
1. MACD SELL 사용 여부
- sell.signals.macd_sell.enabled

2. delay_bar
- sell.signals.macd_sell.delay_bar
- 숫자 입력 또는 콤보

읽기/보류:
3. 조건그룹
- groups 표시
- 상세 편집은 이번 단계 보류 권장

6.3 수익률 SELL 영역

편집 가능 후보:
1. 수익률 SELL 사용 여부
- sell.signals.profit_rate_sell.enabled

2. 목표 수익률
- target_profit_rate 또는 profit_rate_percent
- 단위: %
- 기준: 평단 대비 현재가 수익률

설명 문구:
- "현재가가 보유 평단 대비 목표 수익률 이상이면 SELL 후보가 됩니다."
- "보유 수량이 없거나 평단 정보가 없으면 평가하지 않습니다."
- "평단/현재가/보유수량은 설정값이 아니라 메인 context에서 제공됩니다."

주의:
- 평단 입력칸을 만들지 않는다.
- 현재가 입력칸을 만들지 않는다.
- 보유수량 입력칸을 만들지 않는다.

------------------------------------------------------------
7. 확장예정 탭
------------------------------------------------------------

목적:
- 향후 기능 위치를 미리 확보
- 사용자가 앞으로 들어올 항목을 인지
- 단, 편집/저장/동작 금지

표시 항목:
1. 다중매수
- 상태: 미확정/잠금
- 설명: BUY 신호 이후 여러 회차 또는 여러 조건으로 포지션을 구축하는 영역

2. 다중호가
- 상태: 미확정/잠금
- 설명: 하나의 신호에서 여러 호가에 주문을 배치하는 가격축 구조

3. 다중지점
- 상태: 미확정/잠금
- 설명: 하나의 신호 이후 시간/봉/조건에 따라 여러 지점에서 실행하는 시간축 구조

4. 지속매수
- 상태: 미확정/잠금
- 설명: 보유 중 BUY 신호 발생 시 포지션을 계속 확장할지 판단하는 영역

5. 평단 중심 매수강도
- 상태: 미확정/잠금
- 설명: 현재가와 평단의 괴리를 기준으로 매수 강도를 조정하는 영역

6. 능동매수
- 상태: 미확정/잠금
- 설명: 기본 매수계획 실패 또는 포지션 보정 필요 시 현재 상태 기준으로 매수량을 재산정하는 영역

7. 루틴 CANCEL
- 상태: 미확정/잠금
- 설명: 직접 주문취소가 아니라 BUY/SELL 사이클 내부에서 실행방식 다양성을 부여할 수 있는 신호/제안 영역

금지:
- 확장예정 탭에서 실제 설정값 저장 금지
- CANCEL 실행 버튼 금지
- HOLD 표시 금지

8. 하단 버튼 영역
------------------------------------------------------------

초기 UI 권장 버튼:

1. 다시 불러오기
- rules.json 재로드
- 읽기 동작

2. 미리보기
- 현재 UI 값이 rules 구조로 어떻게 보일지 표시
- 실제 저장 안 함

3. 저장
- 초기 단계에서는 비활성 권장
- 저장 기능은 별도 승인 후 추가

4. 닫기
- 창 닫기

5. 검증
- 향후 rules.json 구조검증 버튼 가능
- 현재 단계에서는 읽기 검증까지만

버튼 정책:
- 첫 구현은 읽기/미리보기 중심
- 저장은 나중에
- 실주문 관련 버튼 없음

------------------------------------------------------------
9. 저장 정책
------------------------------------------------------------

초기 구현에서는 저장 기능을 넣지 않는 것이 안전하다.

1단계:
- rules.json 읽기
- 화면 표시
- 값 변경 UI 일부 허용
- 미리보기만 제공
- 저장 비활성

2단계:
- 사용자 확인 후 저장 기능 추가
- 저장 전 백업
- 알 수 없는 키 보존
- 변경 전/후 비교 표시

3단계:
- 구조검증 통과 시 저장
- 실패 시 저장 차단

이유:
- rules.json은 실제 루틴 설정 파일이다.
- UI 저장 오류가 루틴 동작을 망칠 수 있다.
- BUY/CANCEL 미확정 영역이 있으므로 저장 범위를 제한해야 한다.

10. 데이터 매핑 원칙
------------------------------------------------------------

- enabled
- signal_only

- 주문번호
- 원주문번호
- 체결수량
- 서버잔고
- context runtime 값
