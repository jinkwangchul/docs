============================================================
2. 현재 주요 파일 구조
============================================================

주요 파일과 역할:

- gui_main.py
  프로그램 실행 진입점. MainWindow 실행.

- gui_windows.py
  메인창 중심. 과거 대형 기능 대부분 분리됨.

- gui_main_table_loader.py
  메인창 루틴표/실행종목표 로딩 및 정렬 담당.

- gui_auto_trade_setting_window.py
  자동매매설정창 본체. 현재는 UI 연결 및 통합 제어 허브 역할. 약 2000줄 수준으로 감소.

- gui_auto_trade_table_loader.py
  자동매매설정창 하단 종목표 로딩/표시 담당.

- gui_auto_trade_status_ops.py
  자동매매 상태 변경/운영방식 재판정.

- gui_auto_trade_close.py
  조기마감/개별청산/마감 관련 UI 및 저장 흐름.

- gui_auto_trade_policy.py
  조기마감/자동마감/청산/현황/시간정책 관련 정책 함수.

- gui_auto_trade_timer.py
  시간정책 및 runtime 파일 변경 감시 타이머.

- gui_auto_trade_run_control.py
  매매시작/정지 실행 제어.

- gui_auto_trade_review_ops.py
  자동매매설정창에서 검토관리/안정성검사 호출.

- gui_auto_trade_context_menu.py
  자동매매설정창 우클릭 메뉴.

- gui_auto_trade_selection.py
  자동매매설정창 종목 선택 관련 함수.

- gui_auto_trade_runtime.py
  now_text, stock dir 파싱, state 저장 등 공통 runtime 유틸.

- gui_base_stock_service.py
  기초종목/라이브러리/종목코드 검증/루틴 연결 기초 함수.

- gui_auto_trade_ats_ops.py
  ATS 설정 저장/열기/즉시매도 placeholder 등.

- gui_auto_trade_situation.py
  현황 표시등 create_auto_trade_situation_item 단일 기준.

- gui_review_required_window.py
  검토관리창 기준 파일.

- gui_routine_assign_window.py
  매매루틴지정/해제 창.

- gui_centered_checkbox_delegate.py
  공용 체크박스 델리게이트.

============================================================
5. 남은 위험구간
============================================================

구조보다 정책이 위험한 단계이다.

위험구간:
1. 프로그램 재시작 시 보유/미수/미도/이월 판정.
2. 긴급정지 해제 시 재시작과 동일한 판정 적용 여부.
3. 검토관리 복귀 시 현재 조건 재판정 여부.
4. 조기마감 + 이월 + 청산시간대 겹침.
5. 자동마감 + 이월 + 청산시간대 겹침.
6. 마감 진행 중 미수 발견 시 검토관리 이동.
7. 미도 존재 시 처리 대상 판정.
8. 빨강 데이터 불일치 발생 시 자동분류 금지 유지.
9. ATS 장후 시간과 청산/마감 정책 충돌.

============================================================
6. 추가 구조개선 후보
============================================================

추가 후보는 있으나 당장 우선순위는 낮다.

후보:
- append_changelog / append_stock_log 공용화.
- default_operation_policy / read_operation_policy 중복 정리.
- reset_runtime_statuses_for_program_start 독립 모듈화.
- 검토관리 복귀 판정 공통화.
- 재시작/긴급정지/검토관리 복귀 판정 엔진 단일화.

마지막 항목은 구조개선이라기보다 운영정책 안정화에 가깝다.
