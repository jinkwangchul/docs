MASTER_SPEC_추가갱신_프로젝트_인터페이스카탈로그_Interface_Catalog_2026-07-03

목적
- 프로젝트 내부 계층 간 인터페이스와 입·출력 계약(Contract)을 표준화한다.

==================================================
1. 인터페이스 원칙
==================================================
- 계층 간 통신은 공개 인터페이스를 통해 수행한다.
- 내부 구현은 외부에 노출하지 않는다.
- 인터페이스 변경은 하위 호환성을 우선 고려한다.

==================================================
2. GUI ↔ Controller
==================================================
입력
- 사용자 이벤트
출력
- 처리 결과
- 화면 갱신 요청

==================================================
3. Controller ↔ Engine
==================================================
입력
- Runtime(Read)
- Config
- Event
출력
- 계산 결과
- Signal
- Policy 결과

==================================================
4. Controller ↔ Runtime
==================================================
입력
- 상태 변경 요청
출력
- 저장 결과
- 조회 결과

==================================================
5. Controller ↔ Boundary
==================================================
입력
- 주문 요청
- 조회 요청
출력
- OpenAPI 응답
- 오류 정보

==================================================
6. 인터페이스 계약
==================================================
□ 입력 검증
□ 반환값 명확화
□ 예외 처리 규칙
□ 상태 변경 주체 명확화

==================================================
7. 변경 원칙
==================================================
- 인터페이스 변경 시 관련 테스트 갱신
- Runtime 계약 변경 시 Runtime Specification 갱신
- 공개 인터페이스는 문서와 함께 관리

==================================================
최종 원칙
인터페이스는 계층 간 계약이며,
구현보다 계약의 안정성을 우선한다.
