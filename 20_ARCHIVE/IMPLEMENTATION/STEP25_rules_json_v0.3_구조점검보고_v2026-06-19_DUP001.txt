2. v0.3으로 반영 가능한 확정 항목
------------------------------------------------------------

rules.json v0.3에서 반영 가능한 항목:

1. sell.signal_logic
- 값: OR 또는 AND
- 의미:
  OR = 활성화된 SELL 신호 후보 중 하나라도 통과하면 SELL
  AND = 활성화된 SELL 신호 후보가 모두 통과해야 SELL

2. sell.signals.macd_sell
- 기존 STEP22 구조 유지
- groups 기반 조건 평가 유지
- 기존 sell.groups 호환 유지 대상

3. sell.signals.profit_rate_sell
- STEP23에서 실제 평가 완료
- enabled=false 기본값 유지 가능
- 기준: 평단 대비 현재가 수익률
- 상태값은 context에서 읽는다
- 보유 없음, 평단 없음/0 이하, 현재가 없음/0 이하는 평가 제외

4. context 분리 원칙
- config/rules.json: 전략 설정값
- context: 현재 종목 상태값
- 평단/현재가/보유수량을 rules.json에 저장하지 않는다

4. v0.3 SELL 권장 구조
------------------------------------------------------------

권장 구조:

sell:
  enabled: true
  signal_logic: "OR"
  signals:
    macd_sell:
      enabled: true
      delay_bar: 1
      groups_logic: "OR"
      groups: [...]
    profit_rate_sell:
      enabled: false
      target_profit_rate: 3.0
      profit_rate_percent: 3.0
      basis: "average_price"
      context_fields:
        avg_price: ["avg_price", "average_price", "평단"]
        current_price: ["current_price", "price", "현재가"]
        holding_qty: ["holding_qty", "qty", "보유수량"]

주의:
- target_profit_rate와 profit_rate_percent는 호환 목적상 둘 다 허용 가능
- 실제 엔진이 둘 중 어떤 키를 우선하는지는 STEP23 코드 기준을 따른다
- 기본값은 enabled=false가 안전
- basis는 average_price로 고정하는 것이 현재 확정 기준과 맞다

------------------------------------------------------------
5. BUY 영역 점검
------------------------------------------------------------

BUY는 v0.3에서 무리하게 SELL과 대칭 구조로 확정하지 않는다.

이유:
- BUY는 단순 진입이 아니라 평단 중심, 포지션 구축, 지속매수, 다중매수, 능동매수, CANCEL 개념과 연결된다.
- 사용자 발언 기준으로 UI 들어가면서 B안을 진행하기로 했다.
- 따라서 BUY 확장은 UI/B안에서 별도 확정 후 rules.json v0.4 또는 그 이후에서 반영하는 것이 안전하다.

v0.3에서 BUY는 기존 구조 유지 권장:
buy:
  enabled: true
  delay_bar: 1
  groups: [...]

임의 추가 금지:
- buy.signal_logic
- buy.signals.macd_buy
- buy.signals.active_buy
- buy.signals.average_price_buy
- buy.signals.cancel
- buy.position_policy
- buy.multi_buy
- buy.rebuy
- buy.failure_policy

위 항목은 사용자와 개념 확정 전까지 예약 문서에도 과도하게 넣지 않는 것이 안전하다.

------------------------------------------------------------
6. CANCEL 영역 점검
------------------------------------------------------------

CANCEL은 v0.3에서 구현하지 않는다.

현재 정리:
- 메인 CANCEL = 실제 주문취소 행동
- 루틴 CANCEL = 신호/제안으로 재정립 가능성이 있으나, 아직 이번 v0.3 반영 대상 아님

주의:
- 기존 MASTER_SPEC 갱신반영문에는 CANCEL이 루틴 공식 신호가 아니라고 정리된 부분이 있다.
- 이후 대화에서 루틴 CANCEL은 직접 행동이 아니라 BUY/SELL 사이클 내부의 신호라는 방향이 다시 확인되었다.
- 따라서 CANCEL은 추후 별도 개념정리와 마스터스펙 재반영이 필요하다.
- v0.3에서 CANCEL을 넣으면 혼선 재발 위험이 크다.

8. rules.json v0.3 초안 적용 여부
------------------------------------------------------------

현재 판단:
- 실제 rules.json 교체는 하지 않는다.
- v0.3 초안은 참고용/검토용으로만 작성한다.
- 사용자가 승인하면 별도 적용본 rules.json 파일을 생성한다.

이유:
- rules.json은 실제 루틴 실행 설정 파일이다.
- 현재 단계에서 잘못 교체하면 기존 검증 상태가 흔들릴 수 있다.
- BUY/CANCEL/UI가 아직 정식 반영 전이다.
