MASTER_SPEC_추가갱신_프로젝트_상태전이카탈로그_State_Transition_Catalog_2026-07-03

목적
- 프로젝트 전반에서 사용되는 상태(State)와 허용되는 상태 전이 규칙을 표준화한다.

==================================================
1. 기본 원칙
==================================================
- 모든 상태 전이는 State Machine을 따른다.
- 상태는 Controller만 변경한다.
- 허용되지 않은 전이는 BLOCKED 처리한다.

==================================================
2. Signal 상태
==================================================
PENDING
→ APPROVED
→ BLOCKED

==================================================
3. Order 상태
==================================================
CANDIDATE
→ APPROVED
→ EXECUTABLE
→ REAL_READY
→ ORDER_QUEUED(예정)
→ ORDER_SENT(예정)
→ FILLED(예정)
→ CLOSED(예정)

실패 경로
→ BLOCKED
→ BLOCKED_POLICY
→ BLOCKED_REAL
→ CANCELLED(예정)

==================================================
4. Review 상태
==================================================
OPEN
→ IN_PROGRESS
→ RESOLVED
→ CLOSED

==================================================
5. Recovery 상태
==================================================
DETECTED
→ ANALYZING
→ RECOVERING
→ VERIFIED
→ COMPLETED

==================================================
6. 상태 전이 검증
==================================================
□ 허용된 전이인가
□ Controller를 통한 변경인가
□ Runtime 기록이 남는가
□ Audit 추적 가능한가

==================================================
7. 금지 사항
==================================================
- 상태 건너뛰기
- Runtime 직접 상태 수정
- Controller 우회
- 완료 상태에서 임의 재개

==================================================
최종 원칙
상태는 프로젝트의 운영 흐름을 표현하는 기준이며,
모든 상태 변경은 검증 가능하고 추적 가능해야 한다.
