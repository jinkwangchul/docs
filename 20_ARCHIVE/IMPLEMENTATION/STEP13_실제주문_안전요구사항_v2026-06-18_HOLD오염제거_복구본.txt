# STEP13_실제주문_안전요구사항_v2026-06-18_HOLD오염제거_복구본

작성 목적:
본 문서는 삭제된 STEP13_실제주문_안전요구사항 문서 중 HOLD 오염 구절을 제거하고,
실제 주문 실행 전 반드시 유지해야 할 안전 요구사항만 선별 복구한 기준 문서이다.

복구 기준:
- 루틴에는 HOLD 개념이 없다.
- 루틴의 공식 주문 의사 신호는 BUY / SELL 중심으로 제한한다.
- 조건 미충족, 데이터 부족, 신호 없음은 HOLD 신호가 아니라 "주문신호 없음"으로 처리한다.
- 실제 주문 실행은 루틴이 아니라 메인 주문관리 계층에서 수행한다.
- 지금 단계에서 Kiwoom SendOrder 직접 연결은 금지한다.
- execution_enabled 기본값은 False이다.

------------------------------------------------------------
1. 삭제된 기존 문서의 오염 판정
------------------------------------------------------------

기존 STEP13 문서에는 다음 문장이 포함되어 있었다.

- BUY 신호 생성 가능
- SELL 신호 생성 가능
- HOLD 유지 가능

이 중 "HOLD 유지 가능"은 오염 구절이다.

판정:
- HOLD는 루틴 신호가 아니다.
- HOLD는 사용자 확정 개념이 아니다.
- HOLD는 MASTER_SPEC 기준 공식 상태/신호가 아니다.
- HOLD를 정상 검증 항목으로 둔 테스트 또는 문서는 오염 의심 대상으로 분류한다.

따라서 기존 문서 전체를 무조건 폐기하는 것이 아니라,
HOLD 관련 구절은 폐기하고 실제 주문 안전 요구사항은 선별 복구한다.

2. 현재까지 검증된 주문 파이프라인
------------------------------------------------------------

현재까지 검증된 흐름은 다음과 같다.

루틴 신호
→ routine_signals.json
→ order_queue.json
→ 주문후보 생성
→ 승인/차단
→ 운영정책 게이트
→ 실주문 사전검사
→ Adapter
→ Mock SendOrder
→ Mock Fill
→ Mock Position
→ SELL
→ 포지션 종료

검증 완료로 볼 수 있는 항목:

- BUY 신호 기반 주문후보 생성
- SELL 신호 기반 주문후보 생성
- entry_amount / price 기반 quantity 산정
- 승인단계 APPROVED / BLOCKED 분리
- 운영정책 BLOCKED_POLICY / EXECUTABLE 분리
- Mock 주문 실행
- Mock 체결 반영
- Mock Position 기반 보유 생성
- SELL 후보 생성 시 mock_position.mock_holding_qty 참조
- 전량매도 및 포지션 종료 흐름

검증 제외 또는 재검증 필요 항목:

- HOLD 유지 가능 관련 테스트
- BUY / SELL 외 루틴 신호 저장
- 조건 미충족 시 신호큐 저장 여부
- 루틴 신호 없음 처리
- 루틴 신호부 전체 오염 여부

------------------------------------------------------------
3. 루틴 신호 원칙
------------------------------------------------------------

루틴은 실제 주문 실행기가 아니다.

루틴의 역할:
- BUY 판단
- SELL 판단
- 주문 방식/미체결 처리/재시도 조건 등 주문정책 제안 가능

루틴의 역할이 아닌 것:
- HOLD 신호 생성
- 실제 주문 실행
- Kiwoom SendOrder 호출
- 주문번호 관리
- 미체결 수량 직접 추적
- 주문 취소 직접 실행
- 주문 정정 직접 실행
- 체결통보 직접 처리
- 실계좌 잔고 동기화

중요 원칙:

루틴 = 신호 + 정책
메인 주문관리 = 실행 + 체결/미체결/취소/정정/재주문 관리

루틴이 주문번호, 원주문번호, 체결수량, 미체결수량까지 직접 관리하기 시작하면
루틴은 전략엔진이 아니라 주문엔진이 되어 구조가 무너진다.

------------------------------------------------------------
4. "신호 없음" 처리 규칙
------------------------------------------------------------

HOLD라는 신호는 사용하지 않는다.

다음 상황은 모두 HOLD가 아니라 "주문신호 없음"으로 처리한다.

- MACD 매수 조건 미충족
- MACD 매도 조건 미충족
- 데이터 부족
- 루틴 비활성
- 종목 비활성
- 기준봉 부족
- 보유 없음 상태에서 SELL 조건만 발생
- 보유 있음 상태에서 BUY 조건이 정책상 무효
- 기타 BUY / SELL로 확정되지 않은 판단

처리 원칙:

- 주문신호 없음은 routine_signals.json에 주문신호로 저장하지 않는다.
- 주문신호 없음은 order_queue.json 주문후보로 변환하지 않는다.
- 주문신호 없음은 상태값으로 승격하지 않는다.
- 필요 시 로그에는 "NO_SIGNAL" 또는 "신호 없음" 수준의 설명 문구로만 남긴다.
- 단, "NO_SIGNAL"을 공식 루틴 신호로 정의하지 않는다.

------------------------------------------------------------
5. 실제 주문 실행기 도입 전 핵심 원칙
------------------------------------------------------------

실제 주문 실행기는 절대 루틴 안에 넣지 않는다.

실제 주문 실행기는 메인 프로그램의 주문관리 계층에 위치해야 한다.

권장 파일 위치:

kiwoom_auto/
- real_order_executor.py
- kiwoom_order_adapter.py
- order_execution_log_reader.py

역할 분리:

1) real_order_executor.py
- EXECUTABLE 주문을 읽는다.
- 실제 주문 요청 가능 여부를 최종 확인한다.
- 아직 직접 Kiwoom API를 알 필요는 없다.
- Kiwoom Adapter에 넘기기 전 마지막 사전검사 계층이다.

2) kiwoom_order_adapter.py
- Kiwoom OpenAPI 주문 함수와 직접 연결되는 어댑터다.
- SendOrder 호출은 이 파일로 격리한다.
- 루틴 또는 주문후보 생성기가 SendOrder를 직접 호출하면 안 된다.

3) order_execution_log_reader.py
- 실제 주문 요청 기록을 읽기 전용으로 확인한다.
- 주문 실행 결과를 운영자가 검토할 수 있도록 한다.

------------------------------------------------------------
6. 실제 주문 실행 전 필수 차단 조건
------------------------------------------------------------

아래 조건 중 하나라도 해당하면 실제 주문은 금지한다.

6.1 전역 차단

- 긴급정지 활성
- 키움 로그인 안 됨
- 계좌 미선택
- 실거래 허용 플래그 꺼짐
- 장 상태 불명
- 서버/프로그램 상태 불일치
- 안정성검사 미통과
- 운영정책 게이트 미통과
- 실계좌/Mock 데이터 혼재 의심
- 복구 기준본 불명확
- 사용자 승인 없음

6.2 종목 차단

- 검토관리 종목
- 조기마감 중 BUY
- 자동마감 중 BUY
- 청산중
- 미수 존재
- 미도 존재
- 보유/주문/체결 정보 불일치
- 종목 state 신뢰 불가
- 종목 파일 손상
- 루틴 연결 정보 불일치
- 종목 예산/주수 설정 미확정

6.3 주문 차단

- status가 EXECUTABLE이 아님
- execution_enabled가 True가 아님
- quantity가 None 또는 0 이하
- side가 BUY/SELL이 아님
- 중복 주문 가능성이 있음
- source_signal_id가 없음
- order_id가 없음
- 가격 미확정
- 주문유형 미확정
- 금액/수량 정책 미확정
- 계좌번호 미확정
- 화면번호 미확정
- 테스트/Mock 주문 데이터와 실주문 데이터가 분리되지 않음

------------------------------------------------------------
7. execution_enabled 정책
------------------------------------------------------------

기본값:

execution_enabled=False

실제 주문 허용 조건:

아래 조건을 모두 만족해야만 True로 전환 가능하다.

- 사용자가 명시적으로 실주문 모드를 켰다.
- 계좌가 선택되어 있다.
- Kiwoom 로그인 상태가 확인됐다.
- 운영정책 게이트를 통과했다.
- 주문수량이 확정됐다.
- 주문유형이 확정됐다.
- 중복주문 방지키가 생성됐다.
- 테스트/Mock 데이터가 남아 있지 않다.
- 실주문 모드 플래그가 True이다.
- operator_confirmed가 True이다.
- 안정성검사가 통과됐다.
- 주문 대상 종목이 검토관리 상태가 아니다.

중요:

EXECUTABLE이라고 해서 바로 주문하면 안 된다.

정상 순서:

EXECUTABLE
→ 실주문 허용 검사
→ execution_enabled=True
→ REAL_READY
→ Adapter 호출
→ 주문요청

------------------------------------------------------------
8. 실제 주문 실행 상태값
------------------------------------------------------------

order_queue.json의 status는 주문관리 계층 내부 상태로 관리한다.

기본 흐름:

- PENDING
- APPROVED
- BLOCKED
- BLOCKED_POLICY
- EXECUTABLE
- MOCK_SENT
- REAL_READY
- REAL_SENT
- REAL_FAILED
- REAL_CONFIRMED
- REAL_CANCELLED

주의:

이 상태값은 주문관리 내부 상태이다.
루틴 공식 신호가 아니다.
사용자 화면 공식 종목 상태와도 구분해야 한다.

의미:

REAL_READY
- 실제 주문 실행 직전 상태
- 아직 SendOrder 호출 전

REAL_SENT
- SendOrder 호출 완료
- 체결 여부는 아직 모름

REAL_FAILED
- SendOrder 호출 실패 또는 사전검사 실패

REAL_CONFIRMED
- 주문 접수/체결 이벤트로 확인된 상태

REAL_CANCELLED
- 주문 취소 처리된 상태

BLOCKED_REAL
- 실주문 사전검사에서 차단된 상태
- 구현 시 별도 사용 가능하나, 사용자 승인 후 확정한다.

------------------------------------------------------------

실제 SendOrder를 호출하려면 최소한 아래 값들이 확정되어야 한다.

  - 신규매도
  - 매수취소
  - 매도취소
- 종목코드
- 수량
- 가격
- 주문유형
  - 시장가
  - 지정가
  - 현재가 기반 지정가
- 원주문번호
  - 취소/정정 시 필요
- 화면번호
- 중복주문 방지키
- source_signal_id
- order_id
- 주문 로그 경로
- 실주문 허용 플래그

현재 단계에서는 이 값들이 완전히 확정되지 않았으므로 SendOrder 직접 연결은 아직 이르다.

12. 현재 결론
------------------------------------------------------------

삭제된 STEP13 문서는 완전 무가치 문서가 아니었다.

다만 HOLD 오염 구절이 포함되어 있었으므로 원본 그대로는 기준 문서로 사용하면 안 된다.

본 복구본은 다음 원칙으로 사용한다.

1. HOLD 관련 내용은 폐기한다.
2. 루틴 신호는 BUY / SELL 중심으로 제한한다.
3. 신호 없음은 주문신호가 아니며 큐에 저장하지 않는다.
4. 실제 주문 실행은 루틴이 아니라 메인 주문관리 계층에서 수행한다.
5. SendOrder 직접 연결은 아직 금지한다.
6. 실주문 전 real_order_preflight 단계가 필요하다.
7. execution_enabled는 기본 False를 유지한다.
8. 코드 작성 전에는 반드시 마스터스펙, 대화히스토리, 기존 코드, 사용자 승인 절차를 거친다.

이 문서는 실주문 구현을 시작하라는 문서가 아니다.
이 문서는 실주문 구현 전 안전경계와 오염 제거 기준을 복구한 문서이다.
