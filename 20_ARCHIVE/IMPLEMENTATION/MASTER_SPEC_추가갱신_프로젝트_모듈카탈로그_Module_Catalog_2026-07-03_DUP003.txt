MASTER_SPEC_추가갱신_프로젝트_모듈카탈로그_Module_Catalog_2026-07-03

목적
- 프로젝트를 구성하는 주요 모듈의 책임과 입·출력을 한 곳에서 조회할 수 있는 기준 문서이다.

==================================================
1. GUI 계층
==================================================
역할
- 사용자 입력
- 화면 표시
- Controller 호출

입력
- 사용자 이벤트

출력
- Controller 요청

==================================================
2. Controller 계층
==================================================
역할
- 전체 흐름 제어
- 상태 전이
- Runtime 갱신
- Boundary 호출

입력
- GUI
- Timer
- Event

출력
- Engine
- Runtime
- Boundary

==================================================
3. Engine 계층
==================================================
역할
- 계산
- 신호 판단
- 정책 평가

입력
- Runtime(Read)
- Config

출력
- 계산 결과

==================================================
4. Runtime 계층
==================================================
역할
- JSON 데이터 저장
- 상태 유지

입력
- Controller

출력
- Controller
- Engine(Read)

==================================================
5. Boundary 계층
==================================================
역할
- OpenAPI 통신
- 외부 시스템 연결

입력
- Controller

출력
- OpenAPI 응답

==================================================
6. Runtime 카탈로그
==================================================
- routine_signals
- order_queue
- real_trade_guard
- order_locks(예정)
- order_executions(예정)
- fills(예정)
- positions(예정)
- review_items(예정)
- audit_log(예정)

==================================================
7. 모듈 변경 원칙
==================================================
- 책임 변경 시 MASTER_SPEC 갱신
- 입출력 변경 시 Runtime 규격 검토
- 의존성 변경 시 Component Dependency Map 검토

==================================================
최종 원칙
각 모듈은 하나의 핵심 책임을 가지며,
입력·출력·의존성은 명확하게 문서화되어야 한다.
