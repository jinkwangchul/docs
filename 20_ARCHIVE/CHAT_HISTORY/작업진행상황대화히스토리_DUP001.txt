MASTER_SPEC는 삭제 대상이 아니다.

현재 우리가 진행한 구조개선 흐름을 보면:

MASTER_SPEC
      ↓
실제 구현
      ↓
구조개선
      ↓
검증
관계다.

즉 MASTER_SPEC는

설계 기준서
이고,

현재 만든 문서들은

작업 이력서
완료 판정서
재개 문서
이다.

역할이 다르다.

내 추천은 다음.

1. 원본 보존
MASTER_SPEC_v1.1_윈도우창버전_키움자동매매.txt
절대 수정하지 말고 보관.

폴더:

docs/spec_archive/
2. 현재 상태 반영본 작성
새 파일 생성.

예:

MASTER_SPEC_v1.2_structure_phase1.md
내용:

v1.1 기준 설계
+
구조개선 1차 결과 반영
+
실제 구현 상태 반영
3. 현재 상태 표시
맨 위에:

MASTER_SPEC v1.1

MASTER_SPEC v1.2
상태 : Current

docs/

1. gui_main_window.py

3. gui_auto_trade_window.py
   AutoTradeSettingWindow

4. gui_stock_register_window.py

1순위 AutoTradeSettingWindow
2순위 RoutineAssignWindow
3순위 StockRegisterWindow

AutoTradeSettingWindow

RoutineAssignWindow

= 종목등록 핵심창

MainWindow
= 비교적 단순하니 마지막
현재 결론:

구조개선 1차 = 완료
구조개선 2차 = 창 클래스 분리

WATCH_SELL → 감시/매도

문제 1.

load_selected_routine_stocks()에는 스크롤 보존 시작부가 들어가 있다.

selected_stock_paths, stock_scroll_value = self.capture_stock_table_view_state()
하지만 이 함수 끝에서 복원하는 부분이 실제로 들어갔는지 확인 결과가 부족하다. 검색 결과상 복원 함수는 refresh_all() 쪽에는 보이지만, 종목 설정 변경 후 호출 경로가 load_selected_routine_stocks()만 직접 타면 다시 튈 수 있다.

더 큰 문제.

즉 자동매매설정 창 시작 시 초기화가 아니라, 매매루틴지정 창 쪽에 잘못 들어갔다.
